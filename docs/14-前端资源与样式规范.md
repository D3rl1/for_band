# 14 · 前端资源与样式规范

## 14.1 这个板块解决什么

管两件事：**第三方前端资源怎么放、怎么引**（这一节现在就能执行），
以及**界面视觉长什么样**（§14.6，待定稿）。

写这份的起因：2026-09-22 发现仓库里**并存两份 Bootstrap、版本还不一样**，页面引的是
没记录来源的那份；同时每个页面首屏会闪一下无样式白板。两个问题都源于"没有一份写下来的规矩"。

## 14.2 第三方前端资源：只有一个目录，一个库只存一份

**唯一目录**：`src/main/resources/static/vendor/<库名>/`

| 库 | 版本 | 文件 | 大小 | SHA256 |
|---|---|---|---|---|
| Bootstrap | **5.3.8** | `bootstrap/bootstrap.min.css` | 232,111 B | `d85327d99c7a3ee1f9b5d0500d1370acea3ad2db39c163c2f51f232baedbdede` |
| Bootstrap | **5.3.8** | `bootstrap/bootstrap.bundle.min.js` | 80,496 B | `e4fd49181388c48ec5040bd3fe66f57c29c8e67fcd8502b3354b96ec7ab47cc7` |

来源与升级步骤记在同目录的 `bootstrap/SOURCE.md`。

### 硬规矩

1. **一个库只存一份。** 仓库里出现第二份 = 将来必然有人改错那一份（本次踩的就是这个）。
2. **新增或升级任何第三方前端文件，必须**：三源下载 → **SHA256 一致才入库** →
   把版本号 / 来源 URL / SHA256 / 日期写进该目录的 `SOURCE.md`。
   **单一来源不许入库**——只从一个站下载等于无条件相信那一个站，文件被动过手脚是看不出来的。
3. **页面统一从本目录引入**，路径形如 `/vendor/bootstrap/…`。
4. **不许引外链（CDN）**。理由见 `DECISIONS.md` D7：校园网在未登录认证前会拦掉所有对外请求，
   样式取不到就是白板；且第三方 CDN 有投毒前科（BootCDN 2023-06 起，且专挑移动端下发）。

### 标准引入方式（每个页面 `<head>` 里照抄）

```html
<link rel="stylesheet" href="/vendor/bootstrap/bootstrap.min.css">
<script src="/vendor/bootstrap/bootstrap.bundle.min.js"></script>
```

`bundle` 版自带 Popper，弹窗 / 下拉都要它。

## 14.3 为什么 CSS 必须写在 `<head>` 里，不能用 JS 动态注入

浏览器拿到 HTML 后是**边解析边决定去下载什么**的。CSS 写在 `<head>` 里，浏览器一开始解析就知道
要去取样式，和 HTML 几乎同时到手，用户看到的就是完整页面。

**用 JS 在 `DOMContentLoaded` 里再 `document.createElement('link')` 挂样式，会出两个问题**：

1. **FOUC**（Flash of Unstyled Content，无样式内容闪烁）：页面已经渲染出来了、样式还没到，
   用户先看到一排没边框没颜色的黑字，然后"啪"地跳成正常样子。手机上网慢时更明显。
2. **同一份 JS 被加载两遍**：如果页面 `<head>` 里已经引了 `bootstrap.bundle.min.js`，
   脚本再动态插一个 `<script>`，就是加载并执行两次。Bootstrap 的 JS 负责往页面上挂下拉菜单、
   弹窗这些行为，挂两遍可能重复绑定（点一下菜单开两次）。

> **反例（已修）**：`static/app.js` 末尾曾在 `DOMContentLoaded` 里同时注入 `<link>` 和一个新的
> `<script>`，而各页面 `<head>` 又已经引了同一份 JS —— 于是每个页面首屏都闪，且 JS 跑两遍。

## 14.4 静态资源的两条规矩

**其一：静态资源不存在必须回 404，不许冒成 500。**

浏览器**每次打开页面都会自动请求 `/favicon.ico`**；它若不存在又走了统一兜底，就变成
"**每次页面加载往日志里写一条 ERROR + 完整堆栈**"——真正的错误被这堆噪音淹掉，
浏览器控制台也每次报红。「资源不存在」是客户端问题，不是服务端异常：
`GlobalExceptionHandler` 里有专门映射（`NoResourceFoundException` → `10002` / 404，代码注释引本节）。
**同类还有 405 / 415**——它们该回什么码尚未定死，见 `docs/10` §10.5 与 `交接单.md` `#6`。

> 本条是 2026-09-22 实测 `/favicon.ico` 返回 500 后定的（完整排查见 `work_log.md`）。

**其二：第三方库要能独立验证"没被换过"——从三个来源各下一份比 SHA256。**

`sha256sum bootstrap.min.css`（Windows：`certutil -hashfile bootstrap.min.css SHA256`）。
三份应当**互相一致、且与 §14.2 表里记的值一致**；不一致就先停下查明原因，别继续。
`.js` 同法换 `/js/` 路径。三个来源的地址在 §14.2 的表格里。

> 这是 §14.2 那条硬规矩「**同一个库不许存两份**」的**验证手段**：
> 只靠"目录里看一眼"看不出两个文件是不是同一个版本，比哈希才看得出。

## 14.6 视觉规范（**已定稿**）

### 14.6.1 怎么用（实现者先读这段）

样式**只有一个入口**：

```html
<link rel="stylesheet" href="/vendor/bootstrap/bootstrap.min.css">
<link rel="stylesheet" href="/band.css">        <!-- 本规范的全部实现 -->
<script src="/band-nav.js"></script>            <!-- 侧栏展开/收起（悬停驱动 + 键盘兜底 + 矮屏滚动 + 点菜单项后保持展开） -->
```

- **不要**在页面里写样式，**不要**用内联 `style=` 定颜色——一旦散开就改不动了。
- **改风格只改 `band.css` 的 §1「设计令牌」那一段**（全是 CSS 变量），别的地方都不用动。
- 页面骨架见 §14.6.4；一个完整的定稿样例在仓库根目录的 `design-samples/final-pc.html`
  （⚠️ **该目录不在 git 里**——它只留在这台机器上，**克隆仓库后没有**。
  真正的参照物是**已上线的页面**：拷 `static/events.html` 的 `<head>` 与骨架）。

> ⚠️ **自定义类名必须避开 Bootstrap 的保留类名。** 本项目已经栽过**四次**：
> `.row`（带 `flex-wrap` 的网格）、`.nav`、`.mark`（会给元素加黄色高亮背景）、`.btn`。
> 新增类名前，先去 `bootstrap.min.css` 里搜一下有没有同名。

### 14.6.2 色板：木与丝

取自**民乐器本体的材料色**——木（阮、琵琶、古筝、扬琴）与丝（弦）。

| 变量 | 值 | 用途 |
|---|---|---|
| `--silk` | `#F7F3EC` | 页面底（蚕丝米白） |
| `--cell` | `#F1EBE0` | 卡片 / 次级底 |
| `--pale` | `#D2C3AE` | 细线（**装饰性**，可以很淡） |
| `--edge` | `#9C856B` | 组件边界：输入框 / chip / 分页（要看得见，≥3:1） |
| `--wood` | `#7A5136` | **主色**：主按钮、选中、重点 |
| `--deep` | `#33241A` | 正文与标题 |
| `--mid` | `#6F5F51` | 次级文字 |
| `--shell` | `#2A1D14` | 深木：侧栏 / 主角格 |
| `--shellmid` | `#B3A392` | 深色底上的次级字 |
| `--shellhi` | `#C08A5E` | 深色底上的亮木（选中条等） |
| `--cinna` | `#B23A2E` | **朱砂**：只给异常状态与印章 |
| `--onwood` | `#FBF8F2` | 木色底上的字 |

**三条铁律：**

1. **不碰蓝系。** 学校**管乐团**系统的主色是靛蓝，两个团的系统要能一眼分开。
2. **朱砂只给"异常"和"印章"。** 休团 / 退团 / 毕业 / 警示 —— **常态（在团）不强调**，
   强调常态等于没有重点。印是朱砂的，因为**印本来就该是朱砂**。
   > **~~例外：欢迎行里的姓名也用朱砂~~（2026-09-23 拍板 → 2026-09-24 撤销）**
   > **原委（留痕，不抹）**：2026-09-23 用户拍板，理由"印章上刻的本来就是名字"；
   > 当时已写明代价——姓名属"常态"，用朱砂会稀释"朱砂=异常"的重点，并限死"只此一处、不许扩散"。
   > **撤销（2026-09-24，用户提出）**：理由是**民俗上的忌讳**——**红笔写活人的名字**
   > （判官勾名那种），用户原话"红色确实太不吉利了"。
   > ⚠️ 这与"稀释重点"是两码事：**不是调低红度，而是整条撤掉**（用朱砂系里"好看一点的红"同样犯忌）。
   > **撤销后姓名怎么强调**：改走**字体**——欢迎行的姓名字面换成一门**楷体子集字体**，
   > 颜色回到墨色系。规格见 §14.6.5「姓名字体」与 §14.6.4「页面头部的欢迎行」。
   > **结论**：**铁律 2 恢复成没有例外** —— 朱砂只给异常与印章。
3. **底色是暖中性白，不是宣纸黄。** （实测 `rgb(247,243,236)`，R−B 只有 +11；
   宣纸黄会在 +50 上下——一旦偏黄就滑向"古风文旅海报"。）
4. **"挖出来的凹槽"不算画框线。** 侧栏当前项那块浅色（含右缘两个"肩"）用的是**页面底色 `--silk`**，
   视觉上是"把侧栏挖掉一块、露出下面的页面"——这是**减法**，不是给元素加边框或阴影，
   所以不违反 §14.6.3 的"少画框线"。（复选标记的细环用 `--wood`，**不用朱砂**：朱砂只给异常。）

### 14.6.3 版式

- **少画框线，靠留白与字重分层。**
  一句话原则：**"如果你需要一条边框，你其实需要的是更多间距。"**
  → 侧栏没有底色边框、表格没有竖线网格、状态标记不带框。
  > **例外一**：侧栏当前项的"凹槽 + 肩"——它是**减法**（用页面底色挖出来的），不是加框，见 §14.6.2 铁律 4。
  >
  > **例外二（2026-09-25 用户拍板）：欢迎行里姓名下面那道装饰笔划。** 它是**加**上去的一条线，正面破这条规矩，
  > 所以在这里登记留痕：
  > - **为什么破**：用户明确要（原话是"不要普通的简单下划线，要手划出来的质感"），
  >   而且它算**有语义的线**——"这一行是欢迎语"，不是装饰性框线；
  > - **代价**：正文面多了一处"线"，与"少画框线"的取向相反；这是与姓名有关的**唯一**一处例外；
  > - **边界**：**只此一处**——姓名出现在 **名册 / 考勤明细 / 演出名单 / 个人栏** 的地方**一律不加**
  >   （与 §14.6.5 姓名字体那条"别扩散"是同一条边界）；
  > - **它没有违反这条规矩的后半句**（"靠留白分层"）：笔划画在 `.wname::after` 的**绝对定位**上，
  >   **不占任何布局空间**——实测加装饰前后姓名盒与职称盒的位移都是 **0.00px**；
  > - 做法见 §14.6.4「页面头部的欢迎行」。
- **间距与圆角全站统一**：`--gap: 20px`、`--radius: 14px`。格间距紧、格内边距松。
- **bento 只用于主页**，且遵守四条：
  **① 只有一个主角格**（两个大的会互相打架）；**② 尺寸种类 ≤ 3**（`2×2 / 2×1 / 1×1`）；
  **③ 每格 5 秒能讲完**（标题 + 一个值 + 一个视觉，需要一段话的就不是格子）；
  **④ 不画边框不加阴影**，靠色调与留白分隔。
  > 依据：眼球追踪显示人在大格子上的停留是等大格子的 **2.6 倍**——**尺寸即重要性**，
  > 它比颜色 / 字体 / 动效都更能定优先级。
- **密集数据仍然用表格**（bento 不适合密集表格）。

#### 侧栏（图标轨 + 悬停展开）

**导航 = 常驻 92px 图标轨 + 悬停在自己「预留位」里展开到 320px。**

- **常驻**：收起时**不滑走**，留一条 92px 的深色图标轨（只露单字图标）。
- **展开**：鼠标移入侧栏即展开到 320px，移开收回。展开发生在**页面为它预留的那块位置里**（见下），
  所以**正文全程一动不动、谁都不遮**。
- ⭐ **展开的判定范围 = 一块「命中区」，宽 `--nav-hit: 180px`**（2026-09-24 改，用户提的）：
  - **为什么改**：原来悬停目标是**侧栏自己**（`.railwrap:hover`），而收起时它只有 **92px** ——
    于是 **x ∈ (92, 320) 是一条死区**：鼠标从右边进来、正落在"展开后文字该出现的地方"，
    **什么都不发生**，得再往左压进 92px 才展开。用户原话："**至少得过它展开后的字的长度的范围吧**"。
    （"保持展开"那一半其实早就是 320px 了——**窄的只有"触发"这一半**。）
  - **180 怎么来的**：`--nav-pad 12 + 图标列 (92−12) 80 + .tx padding-left 2 + 最长标签 4 个汉字 ×17 = 162px`，
    取 180，留 18px 余量。⚠️ **菜单名一旦超过 4 个汉字，这个值要同步调大**
    （现在最长的一批正好 4 字：我的请假 / 考勤统计 / 请假审批 / 活动管理 / 团员管理 / 反馈管理 / 更新公告 / 操作日志）。
  - **怎么落**：`.nav-slot` 补 **`position: relative`**（它现在没有定位 → 里面的绝对定位会以视口为基准、铺满全屏）；
    里面放一个命中盒 `.hit`：`left: var(--rail-w); width: calc(var(--nav-hit) - var(--rail-w))`，
    `top: 0; bottom: 0`，`pointer-events: auto`。规则：
    ```css
    @media (hover: hover) and (pointer: fine) and (min-width: 721px) {
      .railwrap:hover,
      .nav-slot:has(.hit:hover) .railwrap { width: var(--open-w); }
    }
    ```
    - ⚠️ **`.railwrap:hover` 这一半必须保留**：它负责"指针已在 180 之外、但仍在柱子内"时的**保持**——
      少了它，指针停在 200px（柱子已展开到 320）会突然缩回去。
    - ⚠️ **命中盒只铺轨道右边（不铺 x<92）**：铺满整段会**挡住菜单点击**；而且展开后轨道会**盖住**它 →
      hover 丢失 → 往回缩 → 又露出来 → **来回抖**（示例里实测到"卡在 124px"就是它）。
    - ⚠️ **`min-width: 721px` 不能少**：新规则特异性 (0,4,1) 会压过手机段的 `.railwrap { width: 100% }`（(0,1,0)）——
      这个坑本节下面已经记过一次（`band.css` 的 `rail-keep` 那条注释）。
  - ⚠️ **留痕更正**：原话是"悬停目标是**侧栏自己**（不是预留位）——**鼠标划过留白不会误展开**"。
    **这条被推翻了**：用户要的正是"判定范围够宽"。旧理由（防误触）**本身没错**，变的是权衡——
    那 228px 留白本来就是**侧栏的地盘**，划过它展开是**可预期**的；而"落在文字上却不开"是**说不通**的。
    旧文与理由**保留在 `band.css` 的同一处注释里**（同步更正、别抹）。
- **键盘**：`Tab` 进侧栏（`:focus-within`）同样展开——否则键盘用户只看到单字、读不到菜单名。
  ⚠️ **既有 bug，本次一并修（`#46`）**：`.railwrap:focus-within` 这条规则**没有媒体门控**，
  特异性 (0,2,0) **压得过**手机段的 `.railwrap { width: 100% }`（(0,1,0)）→
  **手机上点一下侧栏顶部的头像按钮**（它是个 `<button>`，聚焦即触发 `:focus-within`），
  顶栏就被撑成 **320px**。修法：把这条也放进「精确指针 + `min-width: 721px`」的门控里
  ——手机端侧栏是**常显横排**、根本没有"展开"这回事，这条规则在那里只会帮倒忙。
- **只在"真有悬停能力"的设备上自动展开**：整段 hover 规则必须包在
  `@media (hover: hover) and (pointer: fine)` 里。否则 iOS Safari 上**第一次点按会先触发 hover 态**，
  变成"点一下只展开、没跳转"。
- **尺寸**（只改 `band.css` §1 那组变量）：轨道 92 / 展开 320 / 行高 48 / 图标 20px / 文字 17px /
  头像 52 / 行距 6 / 细环 40 / 肩半径 22 / 轨道左内边距 12。
  ⚠️ **行高 48 与行距 6 是 2026-09-24 从 58 / 8 压下来的**（理由见下面「侧栏为什么不跟正文滚」那段的账）。
- **当前项** = 一块浅色"凹槽"：左端**半圆帽**（半径 = 行高 ÷ 2）+ 右缘两个**肩**。
  浅色用的是**页面底色 `--silk`**，所以它看起来像"从侧栏里挖出一个通向页面的窗口"。
- **肩的写法**（踩过坑，别改回教程那套）：角块边长 = 半径 = `--shoulder`，**圆心取角块自己的角落**，
  用 `radial-gradient(circle at top left / bottom left, transparent …, var(--silk) …)` 画——
  **圆外浅色、圆内透明**。这样弧线与条目的边缘、与侧栏右缘都**相切**，浅色区只有这一条弧。
  ⚠️ **照教程抄"透明盒 + `box-shadow` 补色"会剩下一个直角**（盒子的左上角没做圆），
  小尺寸看不出来、放大一眼就露——2026-09-23 用户就是这么发现的。
- **缓动**：展开用 `340ms cubic-bezier(.4, 0, .2, 1)`，**不要用全站那套 `--ease`**。实测依据：
  `cubic-bezier(.22,.8,.28,1)` 起步太猛——216px 行程里**第一帧就跳 50px**，之后每帧只挪 3–4px，
  眼睛看到的是"猛一下、再慢慢蹭"，观感就是顿；换成两头慢的曲线后第一帧 27px、成钟形，才顺。
  注意**这不是性能问题**：实测两种做法在 200 行表格的重页面上都是 60fps、零丢帧，纯粹是曲线形状。
- **页面要为侧栏预留位置**：`.nav-slot { flex: 0 0 320px }`（永远留着展开宽度），侧栏本身 `width: 92px → 320px`。
  收起时那 228px 是**页面底色**（留白）。代价是**正文永久少 228px 宽**——这是刻意换来的"展开时正文一动不动"。
- ⭐ **侧栏钉在视口上，不跟正文滚**（2026-09-24 改，用户提的）：
  `.railwrap { position: sticky; top: 0; height: 100vh; }`。
  **两个必须遵守的写法**——两个都会让钉住**静默失效**（不报错、只是不生效，最难查）：
  - **必须把 `min-height: 100%` 删掉**：它对着 `.nav-slot` 解析，而 `.nav-slot` 是**文档高**的 →
    `min-*` 会**压过**显式的 `height: 100vh` → 盒子又变成文档高 → **sticky 没有可移动的行程**。
  - **不要给 `.nav-slot` 加 `align-items: flex-start`**：它的 **stretch 正是钉住能生效的前提**
    （`.nav-slot` 必须比侧栏高，侧栏才有"可停靠的行程"）。加上去等于把行程抹平。
  - 配套：`.rail { height: 100%; min-height: 0 }` → **菜单成为侧栏里唯一会滚的东西**。
- ⚠️ **更正 2026-09-23 那条「别写死 `height: 100vh`」**（原文与理由保留在下面的变更留痕里，别删）：
  当时写死 `100vh` **却没钉住**，所以在名册 / 日志这类长页面上，主内容滚过第一屏后，
  左边那 92px **就没有侧栏底色了**——**深色柱子从中间断掉**。
  **这条限制现在改成**：**别只写 `height: 100vh` 而不钉住**。钉住之后**原问题不成立**——
  柱子**常驻视口**，任何滚动位置都在，不存在断掉。
- **矮屏兜底**：菜单仍可内部滚动（`overflow-y: auto` + `overscroll-behavior: contain`，后者保证**滚轮悬在菜单上时只滚菜单、不把正文带着滚**），
  但**收起态不显示滚动条**（收起只有 92px，本来就没地方放，也正是"一直占位观感很差"的那一刻）；
  **展开态给细滚动条**：`.railwrap:hover .menu, .railwrap:focus-within .menu { scrollbar-width: thin; scrollbar-color: … }`
  ——展开态是**真正在导航**的那一态，提示给在那里才有用。
  - ⚠️ **旧的 `::-webkit-scrollbar { display: none }` 要删掉**：Chromium ≥121 里 `scrollbar-width`
    一旦不是 `auto`，`::-webkit-scrollbar` 家族**整个被忽略**——那行是**死代码**，留着会让人误以为
    "滚动条是它藏起来的"，下次出问题就去改错地方。
  - ⚠️ **另一个被否的做法**（记下来免得后人重走）：用 `background-attachment: local/scroll` 的"滚动阴影"做提示。
    `.menu` 有 22px 的 `padding-top`（肩形补偿），阴影会被**画进肩形区**（差 22px、说不清哪里不对），
    而且逼 `.menu` 拥有自己的底色、与侧栏底色耦合。
- **每行不许被压扁**：`flex: 0 0 auto`，否则矮屏上浏览器会把行悄悄缩矮，等于偷偷改了尺寸。
- **高度账（管理员，13 行）**：13 × 48 + 12 × 6 = **696** + 内边距 34 + 头像行 76 + 品牌 36 = **842px**。
  1080p 最大化（可用高 ≈ 990px）**装得下**，余量被 `margin-top: auto` 吃掉、品牌贴底（正是想要的样子）。
  ⚠️ 更矮的窗口、或 1080p 在 **125% 缩放**下（视口 ≈ 775px）**仍会滚** → 所以上面那条"展开态细滚动条"
  是**兜底、不是可选项**。（2026-09-23 那句"768px 高的屏整屏放得下"**只对非管理员角色成立**：
  团员 7 行 = 7×48 + 6×6 = 372px，绰绰有余。）
- ⚠️ **老坑仍在**：状态类**别挂 `<body>`**，要挂 `<html>`。`band-nav.js` 在 `<head>` 里跑，
  **那时 `document.body` 还是 `null`**，碰它会抛 `Cannot read properties of null`、整个脚本中断、
  导航就点了没反应。现在没有持久化的收起状态了，但将来要加任何状态类，仍按这条来。
- ⚠️ **手机上（≤720px）**：本次**只定电脑端**；手机沿用现有"**顶部一条横排、常显、不裁切**"，
  悬停展开在触屏上不生效。**移动端的形态待定**（见 `docs/00` 暂定项与 §14.6.4「个人栏」的底部抽屉写法）。
  ⚠️ **移动端必须显式还原钉住**：那个媒体查询里 `.railwrap` 要加 **`position: static`**
  （那里已有 `height: auto`）。否则 `height: auto` + `sticky` 会把手机端那条顶栏**整篇钉在屏幕顶上**——
  这是**真实的行为变更**，不是 no-op。

**点过菜单项要保持展开（2026-09-23 新增，用户提的）**

**现象**：鼠标移到侧栏 → 展开 → **点某个菜单项** → 跳到新页面后**侧栏自己塌回去了**。

**根因（两层，第一层是几何上的必然）**：
- 展开只有两个来源：`.railwrap:hover`（限精确指针设备）与 `.railwrap:focus-within`（键盘）；
  **没有任何持久化的展开态**（`.open` 那个类是个人栏浮层的，与侧栏无关）。
- ① **几何必然**：展开后侧栏 **320px**，点菜单项时指针大约在 **x≈150px**；
  而新页面里侧栏是 **92px**，`:hover` 的判定目标又正是 **`.railwrap` 本身**——
  **x=150 已经落在它外面了**。所以**就算悬停立刻重挂，指针也不在那个（缩小了的）目标上** → 必然塌回去。
- ② 次因：整页跳转后 `:focus-within` 因焦点重置而消失；`:hover` 在跳转后要等指针**移动**才可靠重算。

**目标行为**：点过菜单项 → 新页面**仍然展开**；**直到指针离开侧栏才收起**。
（⚠️ 上面那条几何事实也说明这个目标是自洽的：**强制展开到 320px 后，
原先那个点击位置 x≈150 又回到侧栏内**——悬停接得上，所以"保持"不是硬撑、
而是**把指针重新罩回目标内**。）

**实现要求（三条硬要求 + 两条细节）**：

1. **新增一个"保持展开"的状态类，挂 `<html>` 上**——⚠️ **不能挂 `<body>`**：`band-nav.js` 在 `<head>` 里跑，
   那时 `document.body` 还是 `null`，碰它会抛错打断整个脚本（见上面的"老坑仍在"）。
   CSS 加 `html.<状态类> .railwrap { width: var(--open-w); }`。
2. **`band-nav.js` 首帧前**读标记并加类（与它现在"首帧前加 `wel-armed`"同一位置、同一套做法）。
   **记标记的时机＝在菜单项上 `mousedown`**：
   - **为什么不是 `click`**：**键盘 Enter 激活链接也会触发 `click`**——键盘用户会被强制展开，
     而他**没有"鼠标移开"这个动作来解除**，等于卡住。`mousedown` 只由真实指针触发，天然排除键盘路径；
   - **为什么不是"悬停侧栏就记"**：那样**在正文里点任何一个按钮**跳页，侧栏也会莫名展开。
   - 标记用 `sessionStorage`（随标签页消亡、不跨会话）；**键名新起**，
     **别复用已废弃的 `band_nav_collapsed`**（"清旧键"那句必须保留）。
3. ⭐ **收起判定 = 「几何判断」，不是命中测试**（2026-09-24 改，用户报"切换动画那一下会乱晃"）：
   在 `mountSkeleton` 里**同步绑一个常驻的 `pointermove`**（`document` 上）；指针**横向**越过命中区右缘
   （`clientX > 命中盒.right + 8`）就收起。**只摘类、绝不清标记**——`sessionStorage` 那个标记
   **只有接收页清**（`band-nav.js` 读到就消费掉）。⚠️ **原文这里写的"收起 + 清标记"是过期的**
   （旧页清标记正是 2026-09-23 那个"时灵时不灵"的根源），本次一并改对。
   - **为什么必须是几何**：原来两条路都是**命中测试**——`.railwrap` 的 `mouseleave`，以及一次性
     `pointermove` 里的 `wrap.contains(e.target)`。命中测试**会被盖住指针的东西骗**：全屏遮罩
     （登录欢迎黑幕、更新公告弹层，都是 `position: fixed; inset: 0`）压在指针下时，
     `e.target` 是遮罩而不是侧栏 → 判定"指针不在侧栏" → 摘掉 `rail-keep` → **栏宽 340ms 缩回去**。
     **同一个坑已经踩过两次**（`debug_log.md` 有记录）：**别再靠命中测试判"指针在不在这儿"**。
   - ⚠️ **绝不能用 `.railwrap` 的 `getBoundingClientRect()` 当阈值**：它的右缘就是那个 92 ↔ 320 的
     **动画值**，阈值每帧都在动 → 又是一种抖。用**恒定的命中盒**（或恒定的预留位）。
   - **+8px 是滞回带**：释放阈值比触发阈值再往右一点，免得指针停在边界上反复横跳。
   - **只判横向就够**（柱子是整屏高），竖向不必判。
   - ⚠️ **绑定时机必须在 `await requireUser()` 之前**：现在它跑在鉴权返回**之后**——那几十~几百毫秒里
     `rail-keep` 已经挂着（首帧前就挂了）却**没有任何监听**，指针这时甩到正文就**卡在展开态**。
     所以要在 **`mountSkeleton`**（同步搭骨架那一步）里绑。
   - ⚠️ **提前绑就必须用事件委托**：`paintNav` 会把菜单的 `innerHTML` **重写两遍**（先缓存、再服务端权威值），
     逐项绑的 `mousedown` 监听会被一起销毁。用
     `layout.addEventListener('mousedown', e => e.target.closest('.menu a') && keep())`。
   - ⚠️ **`mouseleave` 那条删掉**——它正是"动画期间被误触发"的元凶之一（根因见下节「跳页过渡」）。
   - **指针从此不再动 → 保持展开**：这是**承诺的行为**（"指针离开才收"），**不要加定时器兜底**。
4. 细节一：**强制展开时不要播那 340ms 过渡**（首帧就该是展开态），
   否则**每次跳页都会看到一次"拉开"动画**。
5. 细节二：`:focus-within` **保留不动**；整套机制用**同一个门控**
   （`matchMedia('(hover:hover) and (pointer:fine)')`）圈住——
   **手机端（≤720px）侧栏是"顶部一条横排、常显"，根本没有展开/收起这回事**，
   别在移动端引入新形态（`docs/00` T9/T10 仍待定）。

> 于是判断"多一个存储态、本次只做电脑端，不值当"。
>
> **它当时漏了什么**：**点完菜单项整页跳转后，两种展开来源双双失效**（根因①②），
> 侧栏**必然塌回去**。**这不是"多加一个开关"，而是现有交互本身的缺陷**——
> 用户点完就发现"它自己缩了"。
>
> → **新决定**：**点过菜单项则保持展开，指针离开侧栏才收起。**
> **代价**：`band-nav.js` 不再是"只清旧键 + 加 `wel-armed`"那么薄了，多一个状态类与几个监听。
> **缓解**：整套机制**只在精确指针设备下生效**、`sessionStorage` **不跨会话**、
> 且带"指针从未移入也要收起"的兜底（第 3 条）。

**DOM 契约（将来换真图标只改一处）**

```html
<a class="item on" href="/events.html">
  <span class="ic" aria-hidden="true">活</span><span class="tx">活动</span>
</a>
```

- **图标位与文字位分离**：`.ic` 里是**首字占位**（现在没有图标库，先用单字顶着），将来换真图标**只改这一列**。
- **菜单图标字要手写一列、不要自动取菜单名首字**——「活动 / 活动管理」都会出"活"、「名册 / 团员管理」语义会撞。
  建议：活动=活｜我的请假=假｜名册=册｜考勤统计=计｜请假审批=批｜活动管理=理｜团员管理=员｜操作日志=志。
- **取"当前页名"要取 `.tx`**（取整个 `<a>` 的文本会变成"活活动"）。
- 菜单**只渲染一份 DOM**：别为了做动画渲染两遍，否则屏幕阅读器会把每个链接念两次。
- 头像有**两个来源，按优先级**：**① `member.avatar`（预置头像库的标识符）→ ② 姓名首字**。
  首字按**码点**取第一个（`Array.from(name)[0]`，防生僻字 / emoji 被截半）。
  - **没选头像的人保持现状**（首字占位）→ **零迁移成本**，老团员什么都不用做；
  - ⚠️ **用首字的地方有三处，改头像时要一起改**（2026-09-23）：侧栏头像行（`.me .ic span`）、
    个人栏（`.p-av`）、**以及欢迎过渡的落点**。第三处最容易漏——过渡是 FLIP，
    **落点靠 `getBoundingClientRect()` 量那个 `<span>`**，头像变 `<img>` 后**选择器必须跟着改**，
    否则过渡会飞到一个空元素上。
  - 预置头像的**素材、入库规矩与清单**见下面「个人页」一节（`vendor/avatars/`，上游那批 **MIT**）。
- 收起态单字在深木底上的对比度要 ≥ 4.5:1（`--shellmid` on `--shell`，实测约 6.5:1，够）。

#### 跳页过渡（跨文档 View Transition）

**整页跳转时用浏览器原生的跨文档过渡**（`@view-transition { navigation: auto }`，**Chromium 生效**；
其他引擎不认识这几条规则 → 退化成原来的瞬时切换，所以它是**增强**、不是**必需**）。
时长取 §14.6.6 给的"页面切换 300–500ms"预算里的 **320ms**。

⚠️ **规格补记（2026-09-24）**：这套东西**早就在 `band.css` 里实现了**（§4 末尾那一段），
但一直没写进这份规格——登记来源是 `docs/archive/移交事项-2026-09-23.md` §九 #32–#35，
那批在 `交接单.md` 里长期挂着"未核实"，**本次一并结掉**。

**点名谁：只点当前项那块"凹槽"，别点整条柱子**（2026-09-24 改，用户挑定）
```css
/* 删掉原来这条： .railwrap { view-transition-name: rail; }   —— 换成下面两行 */
.rail .menu a.on { view-transition-name: nav-pill; }
html.no-xvt .rail .menu a.on { view-transition-name: none; }   /* 登录那一次连指示条也别点 */
```

- **要什么效果**：跳页时**指示条从旧项"平"到新项**（`translate`），而**柱子本身一动不动**。
- ⭐ **为什么必须把这个名字从 `.railwrap` 上拿掉**——它一次造成**两个**毛病，用户两个都报过：
  1. **横向压扁**：出页 320、入页 92 时（正文里的链接 / 个人栏 / 键盘回车这些**不种 `rail-keep`** 的跳法），
     浏览器把旧柱子的快照**横向缩放进**新盒子，**图标和文字一起被压** → 用户说"**集体往左萎缩**"。
  2. **动画期间乱晃**（用户自己定位到"只在那一下、动画过完就没事"）：**跨文档过渡期间，被快照的内容
     不参与命中测试**（规范把它当 `pointer-events: none`、输入落到文档根）。于是动画期间指针压在侧栏上，
     `e.target` 也**不是 `.railwrap`** → 那两条命中测试判定（`mouseleave` / `contains(e.target)`）
     **双双误判"指针不在侧栏"** → 摘掉 `rail-keep` → 340ms 过渡**重新生效** →
     柱子在**指针底下**缩 → 又因 `:hover` 涨回 → **来回晃**。动画一结束命中测试恢复正常，所以"过完就没事"。
  → **把名字从柱子上挪走，两个毛病一起消失**（不再被缩放，动画期间也恢复可命中）。
- ⚠️ **一个已知风险（由用户用眼睛定，不靠截图猜）**：指示条的两个"肩"是 `::before` / `::after`，
  位置在 `a.on` 边框盒**之外**（`bottom: 100%` / `top: 100%`）；被命名的组默认只覆盖元素的**边框盒** →
  肩**可能被裁掉**，动起来像直角方块。
  - ⚠️ **旧注释把原因写成"伪元素不参与快照"——这个说法是错的**：命名元素的快照**包含**它生成的伪元素。
    真正的风险是"**盒子外面的墨迹**"。**更正留痕**（`band.css` 同一处注释 + 本节），**别抹旧文**。
  - **验收归用户**：落地后点一下菜单项，看指示条滑到一半时**肩还在不在**。
    给实现方一个**数值自检**：量 `::view-transition-group(nav-pill)` 的 rect 高 —— 约 48px ⇒ 肩**没**进快照；
    约 `48 + 2 × --shoulder` ⇒ 进了。**这只是线索，进了也不代表没被裁。**
  - **退路（已想好，别临场编）**：把指示条做成**一个上下各撑出一个 `--shoulder` 的包裹盒**
    （`top/bottom: calc(-1 * var(--shoulder))`，凹槽底与两个肩都画在它**内部**）——
    让整个可见形状都落在被命名的盒子里，就不再依赖"快照会不会包含盒外墨迹"。
- **被否的备选**（记下来免得重走）：**干脆什么都不命名**。柱子会随根快照一起交叉淡入——
  非菜单跳转时是"溶一下"而非跳变；代价是**指示条不再平移**。用户要平移 → 否掉。
- **降级**：`prefers-reduced-motion` 下所有 `::view-transition-*` 动画关掉（指示条**直接到位**）——
  是"减少"不是"删掉"（§14.6.6）。

#### 页面萌宠（oneko 猫）

**登录后的页面上会有一只小猫追着鼠标跑**（纯装饰、无业务作用）。用现成的开源实现，**不自己画**。

- **是什么**：`adryd325/oneko.js`（**MIT**）——单文件 `oneko.js` 6.9 KB + 素材 `oneko.gif` 3.3 KB。
  **不改造它的源码**（保住"本地文件与上游哈希一致"这条入库规矩，将来升级只需重新核一遍哈希）。
- **放哪**：**登录之后的所有页面**（含管理端）。**登录页不放**——那页已经有定音鼓手，两个吉祥物会打架。
- **手机端"不加载"**：用 `matchMedia('(hover: hover) and (pointer: fine)')` 门控，**不满足就"连脚本都不插"**。
  注意是**不加载**，不是"加载了再隐藏"——触屏没有鼠标可追，加载只是白耗流量和电。
- **加载时机**：**欢迎过渡播完再加载**（登录成功后约 2 秒）。为什么：它的 `z-index` 是 `2147483647`（最大整数），
  **会压在所有东西之上**——立即加载的话，登录那一次会看到**一只猫从欢迎过渡的黑幕上跑过去**。
- **它的行为与实测事实**（写下来省得重新查）：
  - 整只猫**追着光标跑**（**不是**"眼睛跟鼠标"那种眼动）；
  - **不挡点击**（它自己设了 `pointer-events: none`，无需我们再处理）；
  - 位置会被记忆（它用 `localStorage` 的 **`oneko`** 键；我们的键都是 `band_*`，**不冲突**）；
  - **空闲几秒后会自己睡觉 / 挠墙**——纯装饰动作，与"不做 idle 动画"冲突，**已按例外处理**（见 §14.6.6 第二条留痕）；
  - 源码自带 `prefers-reduced-motion` 守卫（想减少动效的人不会看到它）——**加分项，别删**。
- **入库方式**（照 §14.2 的硬规矩）：文件放 `src/main/resources/static/vendor/oneko/`，
  **三源下载 + SHA256 一致**才入库，并在该目录写 `SOURCE.md`（版本 / 来源 URL / 两个文件的 SHA256 / 日期 / **许可 MIT**）。
  **2026-09-23 实测的两个哈希**（供核对；第三源请自己再取一份比对）：
  - `oneko.js` — 6,929 B — `e5ef6b4e522da7c6a1f74dda1e7a6396675aa3c997ec4cce5e76f9326be34d81`
  - `oneko.gif` — 3,316 B — `f4c5688eb8ee6f22b08ab8df361222307dc6fe2d5bdcfa12582cea694707e66d`

  （设计原型期用的那两份在 `design-samples/mascot-vendor/`，**只作对照，不要直接拷进 `vendor/`**。）
- **不做的**：不做拖拽 / 喂食之类的扩展；不在登录页放；不在手机端放。

- **入口**：`members.html` 的**姓名与头像都要可点** → `member-detail.html?id=N`。
- **`?id=` 指向自己时**：就是"**我的主页（只读）**"，此时**多一块「最近来看过我的人」**（见下小字）。
- **荣誉团员**：**能看**（`02` §2.3 防腐条款的**第 3 条例外**——与"看名册"同类、纯只读）。
  但**他们的「编辑资料」入口不显示**（他们不能改资料，见 `02` §2.3）。
- ⚠️ **这页显示什么，完全由 `03` §3.4 的「`MemberView` 各字段的可见性表」决定** ——
  尤其是：**不出现联系方式（`contact`）、不出现出勤率 / 统计、生日只到「月-日」**。
  **前端不要自己判**：服务端裁完什么，就显示什么。
- ⚠️ **接口用 `GET /api/members/{id}`**；**绝不能给 `GET /api/me/profile` 加 `memberId`**
  （`03` §3.3 写死的红线：收了就等于开了水平越权）。
- ⚠️ **看别人的主页会留下访客记录**（见下），所以这页的加载**有一次写副作用** ——
  接口那边负责去重（同一人同一天只一条），前端不用管。

###### 「最近来看过我的人」（**只在看自己时出现**）

- **只有被访问者本人能看自己的** —— 管理员 / 团长**也看不到别人的**（`02` §2.3）。
- 内容 = `谁 · 哪天来过`。⚠️ **不显示"来了几次"** —— 去重粒度就是"同一人同一天只一条"，
  显示次数没有意义，而且像在施压（本项目一贯不做攀比式可视化）。
- **本人可以清空自己的**（`DELETE /api/me/profile-visits`）。
  ⚠️ 这是**本项目唯一允许"删"的记录类数据**，与 `11` 的"操作日志只增不改不删"**不冲突**——
  那条规矩是给**业务留痕 / 审计**用的；访客记录是**本人的私人数据**，
  按本项目一贯的"**控制权留在人手里**"给本人一个删除口，**且只能删自己的**。
- ⚠️ **不进操作日志**（按 `11` §11.3 的判据："被操作的对象自己已经记了'谁在何时处理的'，就不必重复记"）
  —— **写在这里是为了免得后人顺手补上**。

#### 登录页（`login.html`）

**登录页是唯一一个"有表演"的页面**：一个站立的小人在五个定音鼓前演奏，它的动作**对应界面状态**，不是装饰。
团员一学期只看两三次（token 30 天），但它是**新团员对这个系统的第一印象**——所以值得做好。

- **外框**：`--shell` 铺满视口（外边距 22px）→ 内层**大圆角面板**
  （`border-radius: 32px` + `1.5px solid var(--edge)` 描边 + `overflow: hidden` 裁住两栏）。
  **不做渐变**——规范一贯"靠留白与色调分隔"，渐变会滑向通用网页装饰。
  窄屏（≤720px）：外边距 10px、圆角 20px。
- **两栏**（>720px 左右各半；**窄屏上下堆叠、表单在上、插画在下并缩小**——团员日常用手机）：
  - **左（`--silk` 浅底）**：团名 → 大标题「排练安排、签到、请假，都在这里。」→ 一句说明
    （「用管理员发给你的账号登录。第一次登录不用改密码。」）→ **简谱线**（`1 2 3 5 0` + 拍号 `4/4`；
    **空拍位写休止符「0」**）→ 账号 / 密码 → **登录按钮 = 朱砂印**（按下时 `scale` 挤压的"落印"）
    → 页脚「忘记密码请联系管理员重置 · 建议把本页加到手机桌面，签到时直接点开」。
    **不做「记住我 / 忘记密码链接 / 第三方登录」**：账号是管理员线下发的，找回密码本来就该找管理员（见 `docs/01` §1.4）。
  - **右（`--shell` 深底）**：插画居中，宽度 `min(660px, 98%)`。
- **插画**（`<svg viewBox="0 0 620 470">`，见下方附录）：线只用 `--shellhi`（2.8px，人物）与
  `--shellmid`（2.2px，鼓与气泡），**不引入新颜色**。
  - **人物**：**站立**、**只微微侧身**（**不画侧脸轮廓**：圆头 + 两颗实心眼）、画得比鼓大；
    **不画嘴、不做微笑——表情只走眼睛**：待机偶尔眨、滚奏时眯起专注、失败闭眼（都用 `scaleY`）。
  - **五面鼓沿半圆环绕人物**：正前方那面**最大最低**、两侧**渐小渐高**（近大远小 = 深度），鼓面≈人物**腰高**；
    鼓形 = 鼓面椭圆 + **内侧一圈"张力圈"**（这一圈是"定音鼓"最强的识别信号）+ 外撇双腿 + 一道横撑。
  - **可动部件白名单**（只允许这些动）：头、躯干、两只眼睛、双臂（**肩与肘两段关节**）、鼓槌、
    五面鼓（`drum-body` / `ring` / `ticks`）、思考气泡。**新增任何会动的东西都要先回这里登记。**
- **发声：只用"图形"，不许出现任何文字**（音名、简谱数字、拟声词都不行）。三招：
  ① **圆环扩散**（`scale .72 → 1.12` + 渐隐，`vector-effect: non-scaling-stroke` 保住线宽）；
  ② **短震动刻线**（击打瞬间 3 条短竖线弹出即收）；
  ③ **鼓面下陷**（被敲那面 `translateY 3px`）。
- **三态状态机**（用户的策略：**待机才循环，用户一动手就切成反应，停手再回到循环**）：

  | 状态 | 触发 | 表演 |
  |---|---|---|
  | **待机** | 默认 | 随机挑一面鼓敲（`0.6–2.2s` 随机间隔，正前方那面概率最高）；偶尔眨眼 |
  | **滚奏** | 账号或密码框获得焦点 / 正在输入 | 左右相邻两面鼓 `105ms` 交替连击；眼睛眯起"专注" |
  | **沉思** | 登录失败 | **收势停下** → 一只手托腮、**闭眼**、垂头 → 头顶浮出思考气泡（气泡里是**画出来的省略号**） |

  **无操作 9 秒自动回待机**；**所有姿态切换走 `transition`（320–340ms）**，不许硬切。
- **止损三条**（缺一不可，见 §14.6.6 的决策变更留痕）：
  ① `prefers-reduced-motion: reduce` → 插画**全部动画 `none`**（**静态图，不是慢放**）；
  ② **页面不可见（`visibilitychange`）或插画滚出视口（`IntersectionObserver`）→ `animation-play-state: paused`**；
  ③ 动画**只动 `transform` / `opacity`**；**零外链、零动画库**（无构建链 + 自托管）。
- **失败文案**（与 `docs/01` §1.4 一致）：密码错 → 「账号或密码错误」；
  **连续输错会延迟约 3 秒，必须给一句可见解释**（如「连续输错会稍微等几秒才能再试（不是把账号锁了）」）；
  账号停用 → 「账号已停用，请联系管理员」。

#### 页面头部的「欢迎行」

页面头部（`.head`）里加一行**大字欢迎行**，位于 `h1` **之上**（"栏目之下" = 内容区顶部）：

- 文案：`欢迎回来，{姓名}{角色}`——角色取 `app.js` 里已有的 `roleNames` 映射（例：`欢迎回来，张伟团员`）。
  ⚠️ **姓名与职称之间不加任何标点**（早期版本用过间隔点 `·`，去掉了）：
  **2026-09-24 起两者靠"字面"分开**（姓名是楷体、职称是黑体），标点与空格都是多余。
  **只给姓名留一点间隙**（`.wname { margin-right: .35em }`）；
- **姓名用楷体子集字体 + 墨色**（`--deep`）。
  ⚠️ **2026-09-24 改**：原先用**朱砂**（`--cinna`、铁律 2 的唯一例外），
  因**"红笔写活人名字"的民俗忌讳**被用户撤销（原委与留痕见 §14.6.2 铁律 2）。
  **字面规格见 §14.6.5「姓名字体」**——只此一处用它，别扩散；
- **姓名下面有一道装饰笔划**（2026-09-25 定稿）：**飞白毛笔**、粗细"粗"、**主色木 `--wood`**（透明度 .72）、
  **紧贴字底**、**登录那一次"划出"（裁切）**。**这是 §14.6.3 版式规矩的例外二**（为什么破、代价与边界见那一节）。
  ⚠️ 同样**只给欢迎行这一处**——名册 / 考勤明细 / 演出名单 / 个人栏的地方**一律不加**。
  **做法（实现方照着做，不用自己拍）：**
  - ⭐ **挂点只能是 `.wname::after`**：名字是 `app.js` 用 **`textContent`** 写进 `.wname` 的
    ⇒ 任何塞进去的**子元素都会被冲掉**；而职称是 `.wname` 的**兄弟 `<span>`** ⇒ 用 `::after` 不会波及它。
  - ⭐ **`.wname` 只加 `position: relative`。** ⚠️ **别动 `display` / `line-height`**——
    实测把它改成 `inline-block; line-height:1` 会让**欢迎行盒子高差 2px**、把页面下方整体顶动 2px；
    而 `inline` 盒的底本来就落在字体的降部线上，正好是笔划该待的位置。**少改一处，就少一处会咬人的地方。**
  - **形状与颜色分离**：形状是一张 SVG，用 **`mask-image`** 贴上去；颜色用 **`background-color: var(--sc)`**
    ⇒ **一个形状文件服务所有颜色**（改色只改 CSS 变量）。黑幕那一份（`.wel-tx .wname`）改用
    **`--shellhi`（"深色上的亮木"）**——否则木色在黑底上根本看不见。
  - ⚠️ **SVG 必须写 `preserveAspectRatio="none"`**：默认的 `xMidYMid meet` 是**等比**缩放，
    会把线宽绑死在横向比例（名字宽 ÷ 300）上——实测线宽只有设计值的 **1/3**，
    而且**把 viewBox 调高完全无效**。写成 `none` 才是非等比拉伸：纵向恒 1:1、横向随名字宽度。
  - ⭐ **零布局影响是硬要求**：笔划必须**绝对定位**（`left/right/bottom` + `height`），**绝不许撑动排版**——
    欢迎过渡的 FLIP 是**运行时量 `.welcome` / `.wel-tx` 的矩形**当落点（`app.js` 的 `playWelcome()`），
    装饰一旦改变行内排版，落点就会偏。
  - 形状源码、几何与"为什么要粗就得整体等比放大"的实测数据，见下面的附录与 `design-samples/name-font/`
    （后者**不进仓库**，只作参照）。
- 字号 **33px / 600**，比页面标题 `h1`（18px、`--mid`）大——**欢迎行是这一屏的主角**，页面名退成小字在下；
- 右侧的 `.greet` **只显示声部**（如 `打击声部`）——姓名与角色都已在欢迎行里，不再重复。

> 为什么欢迎行要**做成页面自己的元素**（而不是只活在过场动画里）：过场只是"把这块内容搬过来"，
> 它得**先有一个真实的家**——否则动画的落点无处可落，刷新一下这一行也就没了。

#### 欢迎过渡（登录成功那一次）

登录成功后**只播这一次**：整页变黑 → 正中浮现头像与欢迎行 → **平移到它们在页面里的真实位置** → 淡出黑底、露出页面。
技术上这是**共享元素过渡（FLIP）**，但**必须做在目标页上**——我们是多页应用，
登录页在跳转前**拿不到目标页元素的屏幕坐标**，硬编码坐标在手机端/不同宽度必然错位。

> **机制订正（2026-09-23）**：本节的 CSS 附录给的是「`.wel { display: flex }` + `.wel[hidden]`」，
> **实现改成了「在 `<html>` 上加 `wel-armed` 类」**：`band-nav.js` 在 `<head>` 里、**首帧之前**判断
> `sessionStorage.band_welcome`，有标记就加上 `wel-armed`（遮罩**从第一帧就是黑的**），没有就保持 `display:none`。
>
> **为什么要改**：原方案**同时满足不了**本节自己提的两个目标——
> 先用 `[hidden]` 藏住 → 首帧是**白的**（闪白）；不藏 → 直接打开目标页也会**闪黑**。
> 而加在 `<html>` 上（不是 `<body>`）还受一条老约束：`band-nav.js` 在 `<head>` 跑时
> `document.body` 还是 `null`（见侧栏那节的"老坑仍在"）。
>
> ⚠️ **「摘掉 `wel-armed`」是硬性兜底要求——任何提前退出的路径都必须摘。**
> 2026-09-23 评审真抓到一个漏：`playWelcome()` **只在 `renderNav` 的成功路径里被调用**，
> 而 `renderNav` 开头 `requireUser()` 一旦拿到非 0 响应（后端 500 / 网络抖动）就**直接 return**——
> **黑幕既没人摘、也还没挂上"点任意处跳过"的监听**，结果页面**全黑且无路可走，只能手动刷新**。
> **新规矩**：`wel-armed` 的移除与 `playWelcome()` 的调用**必须绑在同一条兜底路径上**，
> 与"落点取不到"那个兜底并列；**不许任何一条 return 绕过它**。

**六步**（与原型 `design-samples/rail-hover-pc.html` 一致）：

| # | 做什么 |
|---|---|
| 1 | 登录成功 → 存 token → 写**一次性标记**（`sessionStorage`，键名见 `docs/01` §1.3）→ 跳目标页 |
| 2 | 目标页 `<body>` **最前面**内联遮罩（黑底 + 头像 + 欢迎行）——**首帧就铺黑**，绝不能让页面闪一下 |
| 3 | 页面在遮罩底下正常加载（用户看不到） |
| 4 | 头像淡入（0.24s）→ 0.19s 后欢迎行淡入 |
| 5 | 停 0.27s，再**平移到落点**（0.62s，`cubic-bezier(.44, 0, .2, 1)`）：头像 → 侧栏顶部头像；欢迎行 → 页面里那一行 |
| 6 | 遮罩里的头像/文字**先淡掉**（0.16s）→ **再**淡黑底（0.26s）→ 移除遮罩、清掉标记。合计约 **1.8s** |

**硬规则**：

- **落点必须运行时量**（`getBoundingClientRect()`），**绝不写死坐标**——手机端侧栏变顶部一条时自动适配（实测两边都像素级对齐）；
- **只动 `transform` / `opacity`**；**零外链零依赖**；
- **可跳过**：点页面任意处 / 按任意键 → 立刻到终点；
- **`prefers-reduced-motion: reduce` → 直接不播**（正常显示页面）；
- **兜底**：量不到落点元素（页面结构变了）→ 直接显示页面，**别卡在黑屏**；
- 遮罩里的欢迎行与页面上那行**同号（33px）**→ 飞行时 `scale ≈ 1`，不产生缩放模糊；
  黑底上朱砂对比度不够（≈2.4:1），**遮罩里那行的姓名用提亮的朱红 `#D9644F`**，页面浅底上仍是标准朱砂；
  又因为遮罩的内容**先淡出**、页面那份后出现，这次颜色切换**不会被看到**。
- **不做**：黑屏里放 logo / 转圈加载（多余）；**不在非登录路径播**（每次打开都播会很烦）。
  ⚠️ **2026-09-24 更正**：这条原来还写着"**不做 View Transitions API**（跨文档过渡 iOS Safari 不支持，
  将来若只支持 Chromium 可换成原生 `@view-transition`）"。**后半句已经落地了**——跨页过渡**现在就是**
  Chromium 原生的 `@view-transition`（`band.css` §4 末尾）；规格见本节下面的「**跳页过渡**」。
  这里"不做"的**只剩一件事**：**欢迎过渡本身不用它**（那一次首帧就是全黑幕，再叠一层文档级过渡会互相盖住，
  所以用 `html.no-xvt` 拒绝参与）。

**怎么在真实页面里落地（清单）**

1. **放哪**：遮罩那段 `<div class="wel">…</div>` **内联在目标页 `<body>` 的最前面**（首帧就要铺黑，防闪白）；
   CSS 放进页面 `<style>`（或 `band.css`）；JS 放页面底部。**只有跳转目标页需要它**。
2. **触发**：登录页成功后写 `sessionStorage.band_welcome = '1'` 再跳转（见 `docs/01` §1.4）；
   目标页读到标记就 `play()`，并**立刻 `removeItem`**（保证只播一次）。
3. **落点选择器**（两个，**必须运行时量**）：头像 → 侧栏顶部头像（`app.js` 注入的那一处）；
   欢迎行 → 页面头部的 `.welcome`。**页面结构变了就改这两个选择器**；找不到落点走兜底（直接显示页面，别卡黑屏）。
4. **时长可调点**：只改 JS 里那几个 `after(...)` 的毫秒（当前合计约 **1.74s**：
   黑 0.24 / 头像→文字 0.19 / 停 0.27 / 飞 0.62 / 淡出 0.16 + 0.26）。

> **附录：笔划的形状源码**（做成 data-URI 后填进上面的 `mask`）——**飞白毛笔 · 粗**：
>
> ```svg
> <svg xmlns="http://www.w3.org/2000/svg" preserveAspectRatio="none" viewBox="0 0 300 15.2">
>   <defs>
>     <linearGradient id="f" x1="0" y1="0" x2="1" y2="0">
>       <stop offset="0" stop-color="#000" stop-opacity="0"/>
>       <stop offset="0.07" stop-color="#000" stop-opacity="1"/>
>       <stop offset="0.93" stop-color="#000" stop-opacity="1"/>
>       <stop offset="1" stop-color="#000" stop-opacity="0"/>
>     </linearGradient>
>   </defs>
>   <g fill="none" stroke="url(#f)" stroke-linecap="round" stroke-linejoin="round">
>     <path d="M5.00 6.84 L42.00 4.56 L82.00 9.12 L122.00 6.27 L162.00 5.13 L202.00 7.41 L242.00 6.27" stroke-width="7.22"/>
>     <path d="M10.00 11.21 L62.00 10.07 L122.00 11.78 L172.00 10.45" stroke-width="2.09" stroke-opacity="0.50"/>
>     <path d="M32.00 2.66 L92.00 1.90 L152.00 3.23 L208.00 2.28" stroke-width="1.71" stroke-opacity="0.40"/>
>   </g>
> </svg>
> ```
>
> - **这就是"飞白毛笔"**：中段饱满的主笔（`stroke-width 7.22`）+ 上下两道细"干笔"（`2.09` / `1.71`，半透明），
>   两端由那个 `linearGradient` **渐隐**——所以名字多长，笔划都不会在端头"切一刀"。
> - **转义规则**（照 `design-samples/name-font/_build_strokes.py`，实测可用）：
>   `"` → `'`、`<` → `%3C`、`>` → `%3E`、**`#` → `%23`**（⚠️ `url(#f)` 里那个 `#` 也要转），然后把所有空白折叠成一个空格。
> - ⚠️ **`preserveAspectRatio="none"` 绝对不能省**——这是这份源码里**最容易漏、漏了还完全静默**的一条
>   （理由见上文「SVG 必须写 preserveAspectRatio="none"」）。
> - **几何来历**：上面这串坐标是"基准坐标系（viewBox 高 8、中线 y≈3.5）**整体乘 1.9**"的结果。
>   要换粗细档，就用同一个基准乘对应比例（**细 1.00 / 中 1.45 / 粗 1.90**），并且
>   `height` 取 `8 × 比例` px、`bottom` 取 `-(0.5 + 4 × 比例)` px —— 这样墨迹中心**始终落在姓名盒底下沿**，不随粗细漂移。
>   ⚠️ **必须整体等比放大，不能只调 `stroke-width`**：只加粗线宽的话，抖动与"干笔"还是原来那么大，
>   毛笔画那种随手的手感会不成比例地变细碎。

```js
(function () {
  'use strict';
  var wel = document.getElementById('wel');
  var av = document.getElementById('welAv');
  var tx = document.getElementById('welTx');
  var playing = false, timers = [];

  function clearTimers() { timers.forEach(clearTimeout); timers = []; }
  function after(ms, fn) { timers.push(setTimeout(fn, ms)); }

  /* 落点：**运行时量出来**（换宽度、手机端都会自动对上，绝不写死坐标） */
  function targets() {
    return {
      av: document.querySelector('.rail .me .ic span'),   // 侧栏顶部的头像
      tx: document.querySelector('.welcome')              // 页面头部那一行大字欢迎行
    };
  }

  function place() {
    var t = targets();
    if (!t.av || !t.tx) { finish(0); return; }            // 兜底：找不到落点就直接露页面
    var ra = t.av.getBoundingClientRect(), ca = av.getBoundingClientRect();
    var rt = t.tx.getBoundingClientRect(), ct = tx.getBoundingClientRect();
    av.style.transform = 'translate(' + (ra.left + ra.width / 2 - ca.left - ca.width / 2) + 'px,'
                       + (ra.top + ra.height / 2 - ca.top - ca.height / 2) + 'px)'
                       + ' scale(' + (ra.width / ca.width) + ')';
    tx.style.transform = 'translate(' + (rt.left - ct.left) + 'px,' + (rt.top - ct.top) + 'px)'
                       + ' scale(' + (rt.width / ct.width) + ')';
  }
  function reset() { /* 见原型：清 transform / 透明 / 显遮罩 */ }
  function finish(delay) { /* 见原型：先淡文字、再淡黑底、最后移除遮罩 */ }

  function play() {
    if (playing) return;
    playing = true; clearTimers();
    if (window.matchMedia && window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
      wel.hidden = true; playing = false; return;        // 止损：不播
    }
    reset();
    requestAnimationFrame(function () {
      av.style.transition = tx.style.transition = 'opacity 240ms linear';
      av.style.opacity = '1';
      after(190, function () { tx.style.opacity = '1'; });
      after(700, function () {
        av.style.transition = tx.style.transition =
          'transform 620ms cubic-bezier(.44, 0, .2, 1), opacity 200ms linear';
        place();
        finish(660);
      });
    });
  }
  function skip() { /* 见原型：直接 place() 到终点再淡出 */ }

  wel.addEventListener('click', skip);                   // 点任意处可跳过
  document.addEventListener('keydown', function () { if (playing) skip(); });
  if (sessionStorage.getItem('band_welcome')) {          // 只在刚登录那一次播
    sessionStorage.removeItem('band_welcome');
    play();
  }
})();
```

#### 右上角操作区（反馈 + 更新）

`.head` 的**右侧**放两个**次级入口**（与 `sessions.html` 同属"一年用不了几次"那一类，**不占主导航**）：

| 入口 | 行为 |
|---|---|
| **反馈** | 打开反馈浮层（多行文本框 + 提交）。**提交时自动带当前页路径**（`location.pathname + location.search`）；**设备由服务端从请求头取**，前端不管。成功后提示"已收到，谢谢"并关闭。规则见 `15` §15.4 |
| **更新** | 进 `updates.html`（更新日志）。**有未读公告时带一个小红点**（判定规则见 `15` §15.5）|

- **位置**：`.head` 里欢迎行 / `h1` 的**对侧**，与 `.greet`（声部）同一行区。⚠️ **窄屏下不许挤掉欢迎行**——
  欢迎行是这一屏的主角（见上），空间不够时**只留图标、去掉文字**。
- **文案**：就叫「反馈」与「更新」。**不要**用"意见 / 建议 / 帮助"这类含糊词——用户要的就是**报 bug**。

---

#### 更新公告弹层（登录那一次，**排在欢迎过渡之后**）

触发条件、已读判定与文案在 `15` §15.5；这里只写**视觉与顺序**。

- **形态**：居中浮层 = 标题 + 正文 + 「知道了」。正文**保留换行、纯文本、不解析 HTML / markdown**；
  底下若还有更早的公告，给一个「查看全部更新」→ `updates.html`。
- **z-index = 120**（> 欢迎过渡遮罩的 90，< toast 的 2000、oneko 的最大整数）。**给的是书面值，别自己拍**
  （个人栏那次就因为"docs 无书面值"留了个待办）。
- **可跳过**：点任意处 / `Esc` 都能关（与欢迎过渡同一条规矩：**绝不能不让人关**）；
  `prefers-reduced-motion` 下不播入场动画。
- **没有未读公告时整个环节跳过**：不弹空层、不留空白帧、不留一段停顿。

> ⚠️ **四者顺序（必须写死；2026-09-24 由三者扩为四者）**：
>
> ```
> 欢迎过渡播完（或用户跳过）
>   → 有未读公告则弹「本次更新」
>   → 有今天的寿星则弹「生日通告」
>   → 两个弹层都关掉之后才加载 oneko
> ```
>
> **oneko 必须等两个弹层都关掉**：它的 `z-index` 是最大整数、**会压过一切**，不等就会看到
> "**一只猫从公告浮层的文字上跑过去**"——这与当初"猫从**欢迎过渡黑幕**上跑过去"
> 是**同一个坑**（那条记在本节「页面萌宠」里）。所以要**串起来**，不能各管各的 `z-index`。
> **生日通告接在更新公告之后**——不动上面既有那几步的顺序，新的接在后面。

#### 生日通告（登录那一次，**排在上一节的公告之后**）

**"今天是某（几）位团员的生日"这件事，要在主页上醒目地说出来。**（2026-09-24 新增）

- **形态**：**照抄上面那个更新公告弹层那一套**（居中浮层 + 一个「知道了」+ z-index **120** +
  点任意处 / `Esc` 可关 + `prefers-reduced-motion` 不播入场动画）——**不要另造一套弹层**，
  那会重演"两个浮层争 z-index"的坑。
- **文案**：
  - 一位寿星：`今天是 {姓名}（{职称}）的生日，大家祝他/她生日快乐吧`
  - 多位寿星：`今天是 A、B 的生日，大家祝他们生日快乐吧`
  - **职称**用现成的 `identityTags`（声部 · 乐器 · 角色），与欢迎行、个人栏同源。
- **数据来源**：`GET /api/birthdays/today`（`03` §3.3）。⚠️ **接口不下发 `birthday` 字段**——
  只给姓名与职称，所以"对外只到「月-日」"这条口径**不用改**（`00` §0.6 的 `T17` 保持原样）。
- **去重（按日期、设备级）**：`localStorage.band_seen_birthday = 'YYYY-MM-DD'`，值**等于今天**就不再弹。
  **与更新公告同一口径**（设备级、不是账号级），代价也照写：
  **清浏览器数据 / 换设备 / 换浏览器会再弹一次——这是已知的、可接受的**（理由同 `15` §15.5）。
- **口径**（都是 2026-09-24 定的）：

**这一页要一眼看出「录一段」和「挑一个已有的文件」是两件事。**

#### 我们的专场专页（`showcase.html`，2026-09-26 新增）

**一页滚动的时间线，把历年的专场串成一个故事。**（业务规则、谁能策展、排法为什么是这样，全在 `17`；

- **入口在 `concerts.html` 顶部**，一个文字入口「我们的专场」。

  这是一道**有仪式感的门槛**，不是拦路；所以弹层照抄 §14.6.4「更新公告弹层」那一套

  「我们的专场」标题的位置 → 框与黑幕淡出 → 露出时间线页**。总长约 6s。

  ⚠️ **光标只在编排期间闪**，编排一结束就停 —— **不许变成常驻的 idle 循环动画**（§14.6.6）。

  ⚠️ **遮罩上挂"点任意处跳过"时，触发它自己的那个按钮必须 `stopPropagation`** ——
  否则那次点击会冒泡上来被当场结束（实测踩过：点「重播」phase 立刻变 `done`）。
  ⚠️ **遮罩的延迟关闭（若做）必须可取消**：连着关/开会排出一串定时器，
  其中一些会在**重新打开之后**才触发、把刚开的层又关掉（不报错，只表现为"点开之后用不了"）。
- **时间线本体**（**2026-09-26 按用户描述重定，与上一版不同**）：
  ⭐ **一条竖直的淡白线钉在页面水平正中**；**年份沿中线左右交替**（第 1 个在左、第 2 个在右…）；
  **每个时间点的图摆在"点"的上面**；从**最早 → 最新**往下（**理由在 `17`，不是随便定的**）。
  ⚠️ 中线自己也是那个容器的子元素 ⇒ **左右交替用 `nth-of-type` 而不是 `nth-child`**，否则奇偶整体错开一位。
  **没有策展图的年份不出现**（`17` §17.4）。
  ⭐ **节点的浮现定的就是「A · 上浮」**（2026-09-27 定档）：初始 `opacity:0` + `translateY(26px)`，
  进视口后回原位并淡入，**260ms**，只动 `transform`/`opacity`；
  另两条候选（**B 左移 + 中轴随滚动生长 / C 只淡入**）**不做**，样张里那个 A/B/C 切换器已退休。
  ⚠️ **这一页的背景是"当前年份那张图的放大版"**：**全屏 `position:fixed` + 压暗 + 轻微模糊**，
  **节点越过屏幕中线就换**，且**换的时候是交叉淡入（两层叠着），不是硬切**。规则见 `17` §17.4。
- ⚠️⚠️ **决策变更留痕（2026-09-26）：只此一页允许"图片驱动的深色底"**
  **原条款**：§14.6.2 第 3 条铁律「**底色是暖中性白，不是宣纸黄**」（实测 `rgb(247,243,236)`），
  以及 §14.6.7 与管乐团系统的区分点——两者都是围绕**浅暖底**立的。
  **「我们的专场」专页用全屏照片背景**，**明确背离**这一条。
  **为什么开**：用户明确要这个效果（他见过参考），"视觉诉求优先"是本项目一贯的取舍；
  这一页的**内容本身就是照片**，"图片驱动"在这里是**内容**不是装饰。
  **代价（已知情接受）**：全屏图 + 模糊在低端手机上更吃性能；也打破了"一眼是同一个系统"的统一感。
  **缓解 / 边界（写死）**：① **只此一页**——别的页面**不许照抄**；
  ② 前景一律走**浅色**（`--silk`）并用**压暗层**保证对比度；
  ③ 西文/数字仍走 `plex`、中文仍走系统字体栈（字体系统**不改**）；
  ④ `prefers-reduced-motion` 下背景**仍然在、仍然要换**，只是不做交叉淡入（降级是"减少"不是"删掉"）。
- **方块 → 轮播**：点方块，**整条带子从那张封面长出来、落到屏幕中央**。
  ⚠️ **"椭圆"是裁出来的、不是排出来的**（`17` §17.6 有整节讲这个，别做反）：
  照片**全部同尺寸、一律直立**排成一条横带，靠一层**上下双弧的 SVG 遮罩**把它裁弯。
  ⚠️ **起点是「被点那个方块的封面矩形」，做法是 FLIP，且必须先量终点、再算起点**
  （顺序反了算不准；量之前要 `transition:none`，否则量到的是动画中途的值）。
  关掉时**反向 FLIP 回封面**。
  ⚠️ **不做自动轮播**，只响应**左右手滑 / 拖拽**（`17` §17.6 有"为什么它不算 idle 动画"的三条判据）。
- ⚠️ **拖动面的五条硬要求**（`17` §17.6 逐条写了踩坑经过）：① 一张卡的距离 = 一步（卡宽 + 间距）；
  ② 松手**取最近一张**（**不做惯性**）；③ `preventDefault` + `user-select:none` + 挡 `dragstart`
  （否则指针序列被划选文字抢走、**只收到一两次 `pointermove` 就断、不报错**）；
  ④ **别用 `click` 判轻点**（`setPointerCapture` 会把 `click` 重定向走）——用 `pointerup` 按位移判；
  ⑤ **平移用 `transform: translateX`，不许用 `left`**；无限靠**渲染 3 份 + 平移量取模**，
  **缓停交给 rAF**（取模会跳一个周期，CSS 过渡会把这一跳动画出来）。
- **专注单图**：点轮播里的一张 → 放大 + 显示这一张的策展文案全文；
  ⚠️ **退出时回到刚才那个位置**，不是回到第一张。
- **底部寄语**：「我们的故事尚未完结，敬请期待…」，居中、**安静**（不是主角格那种体量）。
  字体见 §14.6.5「寄语字体」。
- **手机端**：这一页是"手机上看得多"的页面 ⇒ `band.css` §10（`≤720px`）要单独给一块：
  时间线单列铺满、轮播按屏宽、**手势用 pointer 事件 + 显式 `touch-action`**
  （本项目此前**没有任何触摸/手势代码**，这是第一处，别漏 `touch-action` ——漏了会和页面滚动打架）。
- ⚠️ **浮层的 z-index 用书面值，别自己拍**：轮播 / 专注单图那一层取 **`600`**
  （**> 个人栏的 500，< Bootstrap Modal 的 1055，< toast 的 2000**）。
- ⚠️⚠️ **oneko 必须让位**：猫的 `z-index` 是**最大整数、会压过一切**，这一页是**全屏看图**，

### 14.6.5 字体

- **中文原则上不上 webfont。** 中文字体整包 5–20 MB，而我们无构建链 + 自托管 + 手机流量；
  且手机上各家的**系统中文黑体本来就是各平台最好看的那一档**。
- **中文界面的"个性"来自西文 / 数字字体、字重字号对比、排版结构、色彩** —— 不是中文字体。
  > **仅一的例外（2026-09-24 拍板）**：**欢迎行里的用户姓名**上一门**楷体子集字体**。
  > 详见下面「姓名字体」——它只服务**一个元素**，不是"给界面换字体"。
- 西文与数字：**自托管 IBM Plex Sans 拉丁子集**（`static/fonts/plex/`，两个文件共 47 KB，OFL 授权）。
  用 `unicode-range` 把它的职责**钉死在拉丁与数字上**，中文必然落到系统字体。
- **中文字体栈必须列全**（否则华为 / 小米 / OPPO 手机会掉到默认 sans-serif）：
  `HarmonyOS Sans` / `MiSans` / `OPPO Sans` / `PingFang SC` / `Microsoft YaHei` / `Noto Sans CJK SC`，
  最后 `sans-serif` 兜底**不可省**。
- **中文只用 400 / 600**，不写 `500`（多数中文字体只有 400/700 两档，500 是浏览器**伪合成**、渲染发虚），
  也不写 `bold`。
- 行高 **1.7**（中文笔画密，比英文的 1.4–1.6 要松）；正文 `letter-spacing: 0`，**禁负字距**；
  **禁中文斜体**（无斜体字形，强制倾斜 = 把笔画拧歪），已用 `font-synthesis: weight` 关掉。
- 顺带一条文案规则：**盘古之白**——中英文 / 数字之间加空格。

#### 姓名字体（**只给欢迎行里的姓名**，2026-09-24 定）

**服务范围只有一处**：页面头部欢迎行里的用户姓名（§14.6.4「页面头部的欢迎行」）。
⚠️ **别扩散**——姓名出现在名册 / 考勤明细 / 演出名单 / 个人栏的那些地方**一律不用**它。

**为什么它不算破上面那条"中文不上 webfont"**：那条的理由是**整包体积**（5–20 MB）。
这里**只收名册里真正出现过的字**（全团几十人，去重后一两百个汉字）⇒ 子集出来**几十 KB 量级**，
理由不成立；而且这是"给**一个元素**换字面"，不是"给界面换字体"。

> ✅ **定稿（2026-09-24 用户从四档样张里选定）：霞鹜文楷。**
> 样张是**四档真字体并排**（霞鹜文楷 / 思源宋体 / 朱雀仿宋 / 遍玨体），同一套 137 字口径下实测子集体积
> **31.8 / 38.2 / 44.3 / 77.2 KB**——四档都在"≤100 KB"目标内。
> ⚠️ **第四档原本是用户提的京华老宋体，被排除**：它上游没有官方发布仓库，许可是作者自定义的"免费商用"，
> 版权头写 `All rights reserved` 且**禁止修改字形、禁止传播修改版** ⇒ **不能进这个要上线的仓库**，
> 所以换成了同属旧版刻方向、许可干净的遍玨体（OFL 1.1）。

| 项 | 定死 |
|---|---|
| **字体** | **霞鹜文楷（LXGW WenKai）**，SIL OFL 1.1（允许子集化与网页自托管） |
| 备选（可换；代价 = 换文件 + 更新哈希 + 重跑子集） | 思源宋体 / 朱雀仿宋（同属 OFL 系）。**不许**用来源不明、或禁止自托管/子集化的字体 |
| **字重** | **只子集一档**——取该字体实际提供的一档（Bold 或 Medium，以家族实际档位为准）；**重点是"只一档"**，多一档体积翻倍，而强调只需要一档 |
| **放哪** | `static/vendor/<字体名>/`（§14.2 的唯一目录） |
| **该目录的 `SOURCE.md`** | 来源 URL / 版本 / **SHA256** / 许可 / **子集用的字符集清单**（§14.2 硬规矩） |
| **子集内容** | 名册中**所有姓名字符** ∪ **常用姓氏**（百家姓前 100 作缓冲，免得新人一入团就缺字） |
| **子集工具** | `fonttools` 的 `pyftsubset`，**本地跑**（本项目没有构建链，**别为它引进一个**） |
| 输出与目标 | `*.woff2`，**目标 ≤ 100 KB**（明显超了就说明字符集收宽了） |

> **实测参照（2026-09-24，样张页：137 字的同一套子集口径，`pyftsubset --flavor=woff2`）**：
> 霞鹜文楷 **31.8 KB** / 思源宋体 **38.2 KB** / 朱雀仿宋 **44.3 KB** / 遍玨体 **77.2 KB** —— 四档都在目标内。
> 作为对比：这些字体的**整包**是 11–75 MB。**子集化是这套方案成立的前提，不是优化。**

**写法**（与 `plex` 并列，加在 `band.css` 的 `@font-face` 区）：

```css
@font-face {
  font-family: 'BandName';
  src: url('/vendor/wenkai/wenkai-name-subset.woff2') format('woff2');
  font-weight: 600;        /* 与 .wname 的字重一致 → 浏览器不会伪合成 */
  font-display: swap;      /* 名字短，换字面那一下的跳变可接受；且绝不让它"先空着" */
}
```
```css
/* 欢迎行里的姓名（浅底）；与职称靠**字面**分开，不用标点，只留一点间隙 */
.wname { font-family: 'BandName', var(--font-ui); color: var(--deep); margin-right: .35em; }
/* 黑幕过渡里那一份：同一门字面；黑底上墨色看不见 → 换浅色 */
.wel-tx .wname { color: var(--silk); }
```

- ⚠️ **`@font-face` 的 `font-weight` 必须与 `.wname` 用的字重一致**，否则浏览器会**伪合成**——
  而 §14.6.5 明令中文禁伪合成（描边发虚）。**宁可降字重，也不许让它合成。**
- **不写 `unicode-range`**：子集里本来就没有拉丁与数字；**缺字按字符回退是浏览器默认行为**——
  真缺字时它落回 `var(--font-ui)` 的中文栈（**回退成黑体，绝不会变成方框**）。

#### 寄语字体（**只给专页底部那一句**，2026-09-26 定）

**服务范围只有一处**：`showcase.html` 底部那句「我们的故事尚未完结，敬请期待…」。

- ⚠️ **不能直接套上面那个姓名字体**：`wenkai-name-subset.woff2` 是**按名册姓名裁的**，
  字符集只有「名册姓名用字 ∪ 常用姓氏前 100 ∪ `·`」——**那句话里的字绝大多数不在里面**，
  直接套上去会变成"**少数几个字楷体、其余全黑体**"的花脸。
- **做法**：**同一份源（霞鹜文楷）另出一个子集**，字符集 = **那句话用到的全部字符（含标点）**；
  输出放同一个目录 `static/vendor/wenkai/`，文件名如 `wenkai-motto-subset.woff2`；
  **新起一个 `@font-face` 家族名**（如 `BandMotto`，**别复用 `BandName`**——两者字符集不同，
  共用家族名会让浏览器按第一个命中的 `@font-face` 取字形，缺字行为变得不可预期）；
  该目录的 `SOURCE.md` **补记这个文件的 SHA256 与字符集清单**（§14.2 硬规矩）。
- **子集工具**：改 `tools/build_name_font.py` 的字符集即可——**同一个脚本、同一套 `pyftsubset` 口径**，
  **不要为它再引一个工具**。
- ⚠️ **维护义务（与姓名字体同款，而且同样是"漏了不报错"）**：**那句话一改，就得重跑子集**。
  漏了的表现只是那几个字**回退成黑体**——不报错、不出方框、也不影响功能，**所以没人会发现**，只能靠这条记着。
- 字重一致、`font-display: swap`、**不写 `unicode-range`**、中文禁伪合成 —— 写法与上面「姓名字体」**完全照抄**。
- **字体栈里必须紧跟 `var(--font-ui)`**（它已含全套中文栈 + `sans-serif` 兜底），别只写字体名。

**⚠️ 三条容易漏的维护项（都不报错，全靠流程）：**

1. **名册变动后重跑一次子集**（新人入团 / 改名 / 首次出现某个字）。
   **不重跑只是那几个字悄悄回退成黑体**，其余字仍是楷体（"半截不艺术"）。
   ⚠️ **改人名的接口不会触发它**（`docs/03` 的建号 / 改名都不管字体）⇒ 这条**只能写进 §14.6.8 速查表**靠人执行。
2. **换字体三件套**：换 `vendor/` 里的文件 + 更新 `SOURCE.md` 的 SHA256 + 重跑子集。
3. **文件缓存**：本项目未配 `spring.web.resources` 的缓存期，静态资源默认**只有 ETag / Last-Modified**
   ⇒ 每个页面都会为这个字体发一次**条件请求**（命中 304，很小但确实有一次往返）。
   想省掉就配 `spring.web.resources.cache.cachecontrol.max-age`——**这是可选优化，不做也不影响正确性**。

**⚠️ 与欢迎过渡（FLIP）的时序耦合（2026-09-24 实测修正过口径，见下）：**

`app.js` 的欢迎过渡**运行时测量真实欢迎行的矩形**当落点（`app.js:845-852` 的 `getBoundingClientRect`）。
字面若在测量**之后**才换上去，矩形就可能与测量时不同 ⇒ 落点偏。

> **⚠️ 口径修正（2026-09-24，样张页实测）**：我原先在这里写的是「**字面一变宽度就变**，这条真会咬人」——
> **说重了**。实测（33px、名字「沈知微」）：
>
> | 档 | 系统字面下 | 该档字面下 | 差 |
> |---|---|---|---|
> | 霞鹜文楷 / 思源宋体 / 朱雀仿宋 | 99.00px | 99.00px | **0** |
> | 遍玨体 | 99.00px | 101.39px | **2.39px** |
>
> 原因：**全角汉字的 advance 就是 1em**（33px 字号即每字 33px），所以「3 个字＝99px」与用哪款字体**无关**。
> ⇒ **换字面通常并不改变名字的矩形**；只有**字宽 ≠ 1em 的字体**（如遍玨体，实测每字约 33.8px）
> 或**名字里含拉丁 / 数字 / 标点**（那些字符宽度随字面差异大）时才会偏。
> **结论**：这条从"真会咬人"降级为"**只在两种情况下才咬人**"；但下面那个要求**照旧保留**——
> 它的成本只有一次 `await`，而漏了它的代价是"只在首次访问时看得出来"的错位，属于最难查的那类。

**要求**：**测量之前先等字体就绪**（廉价保险，别省）：

```js
// 播放过渡前（量矩形之前）
try { await document.fonts.load('600 33px BandName'); } catch (e) { /* 拿不到就照旧播，绝不因此卡住 */ }
```

- `document.fonts` 不存在（老浏览器）→ **直接跳过**，**不许因此把黑幕留在屏幕上**（黑幕本就有"点任意处跳过"的兜底）。

### 14.6.6 动效与声音

**总原则：动效是沟通，不是装饰。每个动画都在回答一个用户没问出口的问题——做不到就砍掉。
装饰性动效是负债。惊喜来自具体，不来自装饰。**

- 时长：微交互 **150–250ms**、状态变化 200–300ms、页面切换 300–500ms（>500ms 显迟钝）。
- **只动 `transform` / `opacity` / `filter`**，绝不动 `width` / `height` / `left` / `top`
  （后者每帧触发布局重排，这是"顺滑还是卡顿"的分界）。
- **一次只动一个焦点**；列表逐个出现错开 **40ms**、**最多 5 个**。
- **不做 idle 浮动 / 呼吸 / 弹跳**（**唯一例外见下方"决策变更留痕"**）；**不使用弹跳缓动**；不打彩纸屑。
- **声音**：
  - 只挂在**"确认"类**动作上（签到成功等）；**不挂** hover / 滚动 / 导航（会变成噪音）；
  - **现场合成、零音频文件**（Web Audio）；全页**只有一个 `AudioContext`**；
    包络用**指数衰减**（线性到 0 会有爆音）；
  - 必须有**独立开关**（存 `localStorage`）+ **视觉等价物**（印章 + 文字）。

- ⭐ **另有一类声音不受上面三条约束**：**用户主动发起、持续可控的声音**——目前只有**练习录音页的节拍器**。

| 对比项 | 确认类声音（签到等） | 用户主动发起的持续声音（节拍器） |
|---|---|---|
| 何时响 | 某动作**成功**后响一下 | 用户按了开始，**一直响到他按停** |
| 谁来开 | 系统 | **用户本人**——那个按钮就是他按的 |
| 「独立开关」要不要 | **要**（`band_sound`） | **不要**——他的"开始"本身就是同意 |
| 「视觉等价物」要不要 | **要**（印章 + 文字） | 要**拍点指示**，但那是它**功能的本体**、不是替身 |

**生产规矩两类共用**：现场合成、零音频文件、**全页唯一 `AudioContext`**、**指数衰减**包络。
⚠️ **节拍器不受 `band_sound` 约束是显式例外**（不是漏写）：一个开了却不出声的节拍器，看起来就是坏的。

- **`prefers-reduced-motion` 必须降级**——是"减少"不是"删掉"：下落改成淡入，功能照旧。
  **降级清单**（截至 2026-09-26）：① **侧栏展开/收起**的宽度过渡时长归零；
  ② 按钮与表格行的过渡；③ 印章动画缩短；
  ④ ⭐ **页面过渡（`::view-transition-*`）整个关掉**——跳页不再有动画，**指示条直接到位**（见 §14.6.4「跳页过渡」）；
  ⑤ ⭐ **欢迎行那道笔划不"划出"**——**直接就在**（因为触发它的那个 `.draw-on` 类压根不加，见 §14.6.4）；
  ⑥ 节拍器的**拍点指示**改成**瞬时变色**、不做缩放或闪烁——⚠️ **但声音不许静音**（降级管的是动画，不是音频）。
  ⚠️ ⑥ 随 `#67` 落地，在那之前它还不存在，**别照它判断现状**；
  ⑦ **专页的三处动效全部退化**：转场变**普通跳页**、椭圆轮播**直接切图**、方块**不做浮现**。
  ⚠️ ⑦ 随 `#72` 落地，在那之前它还不存在，**别照它判断现状**。

> **决策变更留痕（2026-09-23）：idle 动画的例外**
>
> **原条款**：「不做 idle 浮动 / 呼吸 / 弹跳」——理由是装饰性动效是负债（分心、耗电）。
> **新条款**：**只允许"登录页那一个定音鼓手角色"做循环动画**，且必须同时满足三条止损
> （`prefers-reduced-motion` 下**完全静止** / 页面不可见与插画离屏**暂停** / **只动 `transform`·`opacity`**）；
> **其余页面、其余元素仍一律禁止 idle 动画**。
> **为什么改**：用户明确要"让页面灵动起来"，并自己定下了折中策略——**待机才循环，用户一动手就切换到"反应"动作**，
> 无操作再回到循环（详见 §14.6.4「登录页」）。他要的是"有生命的乐器演奏"，不是通用装饰。
> **代价（已知情接受）**：手机端持续重绘（耗电）；同屏多人看容易分心。
> **缓解**：三条止损 + **只此一处** + 角色的动作都**有语义**（敲鼓/滚奏/沉思各自对应界面状态），不是无意义摆动。

> **决策变更留痕（2026-09-23 · 第二条）：页面萌宠的空闲小动作**
>
> **原条款**：同上（不做 idle 浮动 / 呼吸 / 弹跳；理由：装饰性动效是负债——分心、耗电）。
> **新例外**：**只允许"页面萌宠"这一个角色保留它自带的空闲动作（睡觉 / 挠墙）**。
> ⚠️ **如实说明：这条例外比上一条更松。** 定音鼓手的动作**有语义**（待机/输入/失败各自对应界面状态），
> 而猫的睡与挠墙是**纯装饰**。所以它只是**第二处**例外，**不是**把规则改成"可以随便加 idle 动画"。
> **为什么开**：① 用户明确要（沿用既有逻辑"**用户明确要，视觉诉求优先**"）；
> ② 那是**上游文件自带**的行为，**不改造它的源码**才能保住"文件与上游哈希一致"这条入库规矩——
> **开一条窄例外，比改上游文件划算**。
> **代价（已知情接受）**：鼠标停几秒它就会自己动（分心）；持续重绘（耗电）。
> **缓解**：**只在桌面端加载**（手机端连脚本都不下）、**只在登录后**、**过渡播完才加载**、**不挡任何点击**。

> **决策变更留痕（2026-09-25 · 第三条）：笔划的"划出"用了 `clip-path`**
>
> **原条款**：「**只动 `transform` / `opacity` / `filter`**，绝不动 `width` / `height` / `left` / `top`」
> （理由：后者每帧触发布局重排）。`clip-path` **不在**这份白名单里。
> **新例外**：**欢迎行姓名那道笔划的"划出"，用 `clip-path: inset()` 实现**（见 §14.6.4）。
> **为什么开**：备选是 `transform: scaleX()`——它**在**白名单里，但会把毛笔画**横向拉伸**，
> 质感明显变味（样张里"裁切"与"拉伸"两档并排给用户看过，**他选了裁切**）；
> 而 `clip-path` 是"把已经画好的笔划一格一格露出来"，是这一档**唯一既保住质感、又不重排**的写法。
> **代价（已知情接受）**：出了白名单——`clip-path` 的变化不走纯合成路径。
> **缓解**：**只此一处**、**只那一次**（只在**登录那一次**的名字落位上播，其余页面加载**一律静态**，
> 见 §14.6.4「页面头部的欢迎行」）、且 `prefers-reduced-motion` 下**完全静止**（触发类压根不加）。
> **为什么它不算"装饰性动效"**：它绑在"名字落位"这件事上——说明这条笔划属于这个名字，是**沟通**不是摆设；
> 每页都播才会退化成纯装饰，所以规格明确写死"只在登录那一次"。

> **决策变更留痕（2026-09-26 · 第四条）：节拍器的拍点指示不算"idle 动画"，也不算第三条例外**
>
> **原条款**：「**不做 idle 浮动 / 呼吸 / 弹跳**」（理由：装饰性动效是负债——分心、耗电）。
> 节拍器的**拍点指示**是**循环**的，字面上会撞上这条。
> **新条款（是"划清界限"，不是开口子）**：**拍点指示不是 idle 动画**。判据三条，缺一条就退化成装饰：
> ① **用户主动开始、用户主动停**——不是"待机一会儿就自己动"；
> ② **有语义**：每闪一下对应**一拍**，它是这个功能**功能的本体**（没有它，节拍器就只剩声音）；
> ③ **不重排**：只动 `transform` / `opacity`。
> ⚠️ **它既不需要新开一条 idle 例外，也绝不能被引作"可以加 idle 动画"的先例**——
> 上面两条例外（定音鼓手、萌宠）是**松**的，这条是**严**的，别混为一谈。
> **`prefers-reduced-motion` 下照常降级**（瞬时变色），但**声音不静音**——降级管的是动画。

> **决策变更留痕（2026-09-26 · 第五条）：滚动驱动动效——一个本规格从没设想过的新类别**
>
> **原条款**：本节的规矩全是围绕"**一次交互 → 一段动画**"写的（微交互 150–250ms、页面切换 300–500ms、
> **一次只动一个焦点**）。而「我们的专场」要的是**滚动驱动**：方块随滚动位置浮现、图片随手势位移——
> **它没有"开始"和"结束"，只有"当前滚到哪"**。
> ⚠️ 所以这一条**不是"违反了某一条"**，而是"**压根没有对应的条**"。写在这里是为了让它**有据可依**，
> 免得实现者以为自己在违规、或者以为"没写就是随便做"。
> **新条款**：**只允许「我们的专场」专页**用滚动驱动 / 手势驱动动效，且必须同时满足四条：
> ① **只动 `transform` / `opacity` / `filter`**——这条**没有破**，仍是底线；
> ② **用户驱动**：只有用户滚动 / 滑动才动，**没有 idle 循环**（椭圆轮播的三条判据见 `17` §17.6）；
> ③ **`prefers-reduced-motion` 下整段退化成静态**（降级清单 ⑦）；
> ④ **只此一处**：别的页面**不许拿这条当先例**——这一页是**叙事**，滚动位置在这里**等于时间轴**，
> 所以它是**沟通**不是装饰；别的页面没有这个语义。
> **为什么开**：用户明确要"丝滑好看"的观感（"视觉诉求优先"是本项目一贯的取舍）；
> 而且这个页面本身就是一次"**沿着时间往下翻故事**"，滚动在这里**是有语义的**。
> **代价（已知情接受）**：滚动驱动动效在低端手机上会掉帧；它也比"一次交互一段动画"更难测。
> **缓解**：只动合成属性；`prefers-reduced-motion` 全量退化；
> **动效档次先出样张对比、由用户挑**（`交接单` §一 `#76`）——挑的过程本身就是在验"值不值得"。

> **决策变更留痕（2026-09-27 · 第六条）：允许一处 ~6s 的长转场**
>
> **原条款**：「时长：微交互 **150–250ms**、状态变化 200–300ms、**页面切换 300–500ms**（>500ms 显迟钝）」。
> 而「我们的专场」的**入场编排**约 **6s**（黑幕合拢 → 搜索框升起 → 打字 → 删 → 改打 → 模拟搜索
> → 飞到标题 → 揭幕）—— **超出这条一个数量级**。
> **新条款**：**只允许这一处**（`showcase.html` 的入场）用长编排，且必须同时满足三条：
> ① **可跳过**（点任意处 / Esc ⇒ 直接到结尾状态）；
> ② **只此一处** —— 别的页面、别的交互**一律仍按 300–500ms**；
> ③ **`prefers-reduced-motion` 下整段跳过**（见下面那条专门说明）。
> **为什么开**：用户明确要（"我需要的就是一种比较沉浸的感觉"，且已知情接受"过程长些"）；
> "视觉诉求优先"是本项目一贯的取舍，而这一页本来就是**叙事**（沿着时间线讲一个故事）。
> **代价（已知情接受）**：每次进这一页都要等约 6 秒；低端手机上这一段更吃性能。
> **缓解**：可跳过；只此一处；整段**只动 `transform`/`opacity`**。
>
> ⚠️ **这条留痕里要专门写清一处降级**：这一段的 `prefers-reduced-motion` 降级是「**整段跳过**」
> （**一帧黑幕都不出**），**而不是"减少"**。
> 理由：本节的"**是减少不是删掉**"那条**保护的是功能**，而这段编排**里面没有任何功能**
> —— 纯装饰，跳过它一个功能都不少。**对纯装饰，跳过才是正确的降级。**
> 写在这里，免得后人拿"是减少不是删掉"来质疑它。

### 14.6.7 与管乐团系统的区分点（**别撞**）

学校**管乐团**另有一套系统，两边要能一眼分开：

| | 他们（管乐团） | 我们 |
|---|---|---|
| 主色 | 靛蓝 + 橙（暖） | **木与丝**（木褐 + 朱砂），**不碰蓝** |
