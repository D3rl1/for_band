# 18 · 乐器调音器

> **本板块是一批"原样搬进来"的静态工具页**，不改表、不改端点、不新增角色。
> 它的**规格主体在另一个仓库**（`desktop_agent`）——本节管的是"**怎么进系统、怎么进得去、以后怎么维护**"，
> 不管"调音算法怎么写"。

## 18.1 这个板块解决什么

团员在**系统里**打开自己那件乐器的调音器：登录后「日常 · 工具 · 调音器」→ 一个竖排目录 →
点自己那件 → 进调音器，对着乐器出个声就能把弦调准。

**它顺带结掉三桩悬案**（这是"为什么放进来"而不是"另开一个站点"的理由）：

| 悬案 | 怎么被它结掉 |
|---|---|
| 调音器**怎么发给乐团成员**（要 https 才能申请麦克风） | 系统本来就在 **https** 上（`12` §12.2 的 LE 证书），不再需要另找托管 |
| 八件一直**没有一个统一入口**（此前每件各自一个 `启动调音器.bat`） | 系统的导航就是那个入口——**不为它另建总入口**（`14` §14.6.4 已有「工具」组） |
| `交接单 #160` 未完成项 ⓑ「**功能集合子菜单（调音器要用）**」 | 本轮不需要子菜单：**一个菜单项 → 一个目录页**（见 18.3） |

**与 `14` §14.5 里那个「调音器」占位页的关系**：就是它，本轮把它从「建设中」变成真页。

> ⚠️ **`metronome.html`（节拍器）不在本板块**。它是另一件占位页、另一条线，别顺手一起做。

## 18.2 数据模型与接口清单

**两者都是"无"，这是刻意的，不是漏写。**

- **数据模型：无。** 调音器不落库——不记"谁调过音"、不记历史、不传文件。
  所以 `13-数据模型总表.md` 一个字不动，也没有新表要登记（闸门 R13 不涉及）。
- **接口清单：无。** 调音器**不调后端任何接口**——八件都是**零依赖单文件**，算法与 UI 全在页面里。
  所以 `10-接口规范与错误码.md` 不动，`ErrorCode` 不动（闸门 R10 不涉及）。

> **唯一的"服务端参与"是把静态文件发出去**——这与 `favicon.ico` 同级，不是接口。
> 静态资源不存在必须回 404 而不是 500，见 `14` §14.4。

## 18.3 页面清单与落点

**一个入口页 + 八个成品页。入口页占一个菜单项，成品页不占菜单**（它们是"从入口点进去的详情页"，
与 `event-detail.html` 同类，见 `14` §14.5 那句「详情页靠从列表页链过去过关，不必进导航」）。

| 页面 | 作用 | 占菜单 |
|---|---|---|
| `static/tuner.html` | **入口页**：竖排目录，八件各一行（**本轮从占位页改成真页**） | 是（**已在**「日常 · 工具」组） |
| `static/tuner/ruan.html` | 阮（中阮 / 大阮 / 自定义） | 否 |
| `static/tuner/guzheng.html` | 古筝（21 弦，六调） | 否 |
| `static/tuner/erhu.html` | 二胡（D-A 两弦） | 否 |
| `static/tuner/pipa.html` | 琵琶（标准北琶四弦） | 否 |
| `static/tuner/liuqin.html` | 柳琴（四弦高音） | 否 |
| `static/tuner/datiqin.html` | 大提琴（C-G-D-A） | 否 |
| `static/tuner/diyintiqin.html` | 低音提琴（E-A-D-G，含五弦预设） | 否 |
| `static/tuner/tongyong.html` | **通用调音器**（不分乐器，给定音鼓等用） | 否 |

**目录名与 slug 都用拼音**（`static/tuner/` 下不许出现中文文件名——静态资源的路径要能直接抄进 URL）。

**导航一个字段都不用改**：`band-shell.js` 的 `menu` 里那行调音器**已经在了**
（`view:'日常' / group:'工具' / href:'tuner.html' / icon:'audio-waveform' / roles: NAV_ROLES.all`）。
⚠️ 别为了"更像功能集合"去加八个菜单项——那会撞 `AGENTS.md` 前端第 6 条（**一个 icon key 不许两页共用**）
且把侧栏撑爆；**一个入口页是刻意的**。

## 18.4 资产形态与单一事实源（★ 本节最要紧）

**八件成品都是"零依赖单文件 HTML"**：CSS、JS、算法、图形（内联 SVG）全在**同一个 `.html` 里**，
不引 CDN、不引字体、不 `fetch`、不 `import`。所以搬进系统里就是**放一个文件**，
天然满足 `14` §14.2 的硬规矩「**不许引外链（CDN）**」。

**但它们的"家"不在这个仓库。** 事实源在 `desktop_agent`：

```
desktop_agent/
├── shared/core.js                     ← 乐器无关的那部分（音名换算 / MPM 测音 / 匹配），唯一一份
├── design-system/民乐调音器/MASTER.md  ← 视觉事实源（纸感 / 夜墨 / 组件契约）
└── <乐器>/
    ├── src/{config.js, app.js, index.template.html}   ← 该乐器的源
    ├── build.py                        ← 把 shared/core.js + src/* 拼成一个 index.html
    └── index.html                      ← ★ 产物（就是搬进来的那个文件）
```

**三条铁律：**

1. **搬进来的 `static/tuner/*.html` 是产物，谁都不许手改。**
   在这里改一行，下次从源重新生成就没了——**改了等于没改**。
2. **要改算法 / 改界面 / 改定弦，一律回 `desktop_agent` 改源，重跑 `build.py`，再重新拷成品。**
   （`build.py` 把 `shared/core.js` + `src/config.js` 逐字拼进产物里那对
   `/*==CORE-START==*/ … /*==CORE-END==*/` 标记之间；产物自带校验，见下。）
3. **`shared/core.js` 与各 `src/` 不许搬进本仓库。**
   搬进来就会出现**同一份算法两处并存**（源一份、每个产物里还各压着一份）——
   正是调音器家族一路在防的"平行实现会漂"（`MASTER.md` 记过这个教训）。

> **为什么"只搬产物"不等于"丢了算法"**：产物里**逐字**压着 `shared/core.js` 的全文
> （`build.py` 拷进去的），所以算法一点没少。这条已实测核对过。

**每件产物自带一道自检**（`verify_<slug>.mjs` 的第 0 条，在 `desktop_agent` 里跑）：
产物必须**逐字**包含 `shared/core.js` + `src/config.js` + `src/app.js` 三份源，且各出现恰好一次。
**改了源忘了重跑 `build.py` → 这道自检当场拦下。**

## 18.5 入口页规格（`tuner.html`）

**排布 = 竖排目录**（用户 2026-10-07 拍板），八件各一行：

```
阮            中阮 / 大阮        →
古筝          21 弦             →
二胡          D-A 两弦          →
琵琶          四弦              →
柳琴          四弦高音           →
大提琴        C-G-D-A           →
低音提琴      E-A-D-G           →
通用调音器     不分乐器           →
```

- **每行三样**：乐器名 + 一条**副标题**（弦数 / 定弦，一眼能认出是哪件）+ 箭头；
  整行可点（点行进对应成品页）。
- **为什么选竖排目录而不是九宫格**：副标题是"找自己那件"的关键信息，格子里塞不下。
- **本页套系统的壳**（`band-nav` / `band-shell` / `band.css`，与其它页面**逐字同一串** → 闸门 R12 管它），
  所以它有侧栏、能返回。**成品页不套壳**（见 18.7）。
- 图标沿用菜单项已有的 `audio-waveform`，**不新增图标 key**。

## 18.6 登录与权限

**沿用菜单项现有的角色口径**：`roles: NAV_ROLES.all`——**全角色可见（含荣誉团员）**。
理由：调音器是**只读工具**，不产生内容、不碰任何数据，与荣誉团员"只读"的定位不冲突。

**⚠️ 成品页要自己带一道登录闸门。** 成品页是零依赖单文件、**不含 `band-*.js`**，
所以拿不到 `band-core.js` 里那道"没 token 就跳登录"的检查（`band-core.js:164`）；
不补的话，**直接开 `/<前缀>/tuner/ruan.html` 会绕过登录**。

**收口方式**（源在 `desktop_agent` 的模板里，一行内联、仍零依赖）：

```js
if (location.pathname.startsWith('/tuner/') && !localStorage.getItem('band_token')) location.replace('/login.html');
```

- **判据是"路径前缀"**：只在系统里部署到 `/tuner/` 下才生效；
  **本地双击（`file://`）或本地 `http://localhost:8123` 打开时路径不以 `/tuner/` 开头 → 不触发**，
  所以"拿去本地用"这条链路不受影响。
- token 键名 = `band_token`，与 `band-core.js` 一致。
- **它是一行、零依赖**，不破坏"零依赖单文件"这条形态。

> ⚠️ **如实说明**：全站的静态页登录本就是**客户端约定**（`band-core.js` 里跳转），不是服务端强制
> ——`AuthInterceptor` 只拦 `/api/**`。调音器与全站**一致**，不是更弱。

## 18.7 与既有机制的关系（为什么**不需要给任何闸门开例外**）

这一节是给实现者与后来人看的：**别以为"新加九个页面"要动闸门**。

| 机制 | 为什么天然管不着 / 天然通过 |
|---|---|
| `tools/spec_check.py` **R12**（带导航页的脚本串必须一致） | R12 只看 `static/*.html` **顶层**，且**跳过没有 `id="navbar"` 的页**。成品页在子目录、且没有导航 → **不进扫描**。入口页 `tuner.html` 有 `id="navbar"`、脚本串照抄多数页 → 通过 |
| `tools/spec_check.py` **R11**（菜单图标） | 本轮**不新增任何菜单项**（入口已在）→ 不触发 |
| `refresh.sh` **[4/5] 页面可达性** | 它 `for f in "$STATIC_DIR"/*.html` —— **只扫顶层、子目录不看** ⇒ 八个成品页**根本不在它的检查面内**。入口页 `tuner.html` 是顶层页、且本就来自菜单（判据是"名称出现在 `band-shell.js` 的 menu 或别的 html 里"）⇒ **不变** |
| **`band-shell.js` 的 `offMenuTitles`** | **不需要挂**。它的用途是"当前页在侧栏显示什么标题"，而这八页**不含 `band-shell`**（零依赖单文件、无导航）⇒ 挂了也没人读。入口**只靠 `tuner.html` 里那八条链接** |
| **R1 / R5**（文档↔端点） | 无新端点 |
| **R10 / R13**（错误码 / 表） | 无新错误码、无新表 |
| `14` §14.2 硬规矩「不许引外链」 | 成品是零依赖单文件，本就不引 |

**成品页与系统的视觉边界（有意为之）**：成品页**保留调音器自己那套视觉**
（纸感 / 夜墨，见 `MASTER.md`），**不套 `band.css`**——
它们是"**全屏工具**"，要尽量把屏幕让给读数与轮盘（一屏装下是硬约束），
套上系统的页头/侧栏会把它挤出去。**入口页才是系统的样子。**

## 18.8 搬运与维护流程

**成品从哪来、搬到哪：**

| 步骤 | 谁 | 做什么 |
|---|---|---|
| 1 | 规格侧（在 `desktop_agent`） | 改源 → 跑 `python build.py` → 跑 `verify_<slug>.mjs` 全过；产出 `<乐器>/index.html` |
| 2 | **搬运** | 把 `<乐器>/index.html` **逐字**拷成 `for_band/src/main/resources/static/tuner/<slug>.html` |
| 3 | 实现方 | 写 `tuner.html` 正文（18.5 的竖排目录 + 指向八页的链接）；跑 `python tools/spec_check.py`（应无新 ❌）。⚠️ **不必改 `band-shell.js`**——入口那行已在 `menu` 里，八页也不挂 `offMenuTitles`（见 18.7） |

> ⚠️ **搬运这一步是"文件放置"，不是"写代码"**——不许在搬运时改字节、加行、格式化。
> 拷错一个字节，"产物逐字含三份源"那条自检就再也对不上了。

**以后要改调音算法**（比如乐团标准音变了、某件定弦修正了）：

1. 回 `desktop_agent` 改 `shared/core.js` 或该件 `src/config.js`；
2. 跑该件 `build.py` + `verify_<slug>.mjs`；
3. **重新拷** `static/tuner/<slug>.html`（**这一步最容易忘**——忘了就是"网页上还是旧的"）。

**以后要加第九件乐器**：回 `desktop_agent` 把该件做完（源 + `build.py` + `verify`）→
拿到产物 → 按上表 2/3 走 → 在 `docs/18` §18.3 与 `docs/14` §14.5 **各登记一行**。

## 18.9 刻意不做

- **成品页不加「返回目录」按钮。** ❌ 不做（一屏装下是硬约束——琵琶在 `360×640` 上余量只剩**个位数像素**，
  加一行就溢出；手机浏览器自带返回手势）。
- **不记调音历史 / 不做后端记录。** ❌ 不做（调音器不落库，见 18.2；要记录是另一个需求，另议）。
- **不做离线 / PWA 安装。** 见 `T11`（本板块不另开一条口径）。
- **不把 `shared/core.js` / `build.py` / 各 `src/` 搬进本仓库。** ❌ 不做（理由见 18.4 第 3 条）。
- **不新增菜单项、不建"功能集合"子菜单。** （`#160` ⓑ 这条以"不需要"结案——一个入口页够了）。
