# 12 · 部署与备份

## 12.1 这个板块解决什么

让服务能跑起来、数据**不丢**。
对这个项目来说，**"数据丢了"的概率比"被攻击"高得多**——所以备份是这一块的重心。

## 12.2 两个阶段

### 阶段一：本机（**现在这个阶段**）

```bash
mvn spring-boot:run
```

- 本机 MySQL 8.0
- **不做容器化**（Docker 对本项目是没必要的复杂度，见 `DECISIONS.md`）
- 手机浏览器访问 `http://<本机局域网 IP>:8080` 验证移动端效果

**本机开发库（期 0 已建立，2026-09-21）**：

- 库名 **`band`**（utf8mb4），应用账号 **`band_app`@`localhost`** 仅授权 `band.*`，
  应用不用 root 连库（见 §12.4）。密码放在 `application-local.yml`（已 gitignore，
  新机器需手工重建此文件）
- 建表脚本 **`sql/schema.sql`**（表结构以 `docs/13` 为唯一权威），执行：
  `mysql -uband_app -p band < sql/schema.sql`
- 首次启动时应用自动写入 **7 个初始声部**（打击声部 / 提琴声部 / 胡琴声部 / 吹管声部 /
  古扬声部 / 阮声部 / 琵琶声部），逻辑幂等，表非空则跳过
  （⚠️ 因此**改了声部名单后，已有库不会自动更新**——需清空 `section` 表再重启，
  或直接改数据。见 `docs/03` §3.2）

> ⚠️ **校园网的两个已知坑**（来自作者另一个项目的踩坑记录）：
> ① 校园网客户端会劫持流量，未认证前请求会撞死本机端口（报 `WinError 10061`，那是本机拦截不是超时）；
> ② 代理（如 `127.0.0.1:7890`）不稳时会影响联网操作。
>
> **对策很具体**：**Maven 配置阿里云镜像**、npm 用国内源，
> 别让"拉依赖"这一步就在校园网里卡死。

### 阶段二：云服务器（**路线已定：先走 IP**）

- **上线路线**：**先用服务器自带的公网 IP + HTTPS 上线**（免域名、免备案、最快），
  域名与备案**以后再说**（`docs/00` 暂定项 T14；换域名时按 §12.2.2 换证书即可，服务器不用动）。
- **当前决定（2026-09-23）**：**服务器暂缓购买**，等期 1 的代码收尾再买（见 `docs/00` §0.4 的分期）。
- 国内云学生机，Ubuntu LTS；**`jar` + systemd**（开机自启 + 崩溃自动重启），**不用 Docker**
- **全程 HTTPS，不经过公网明文阶段**（为什么——见 `DECISIONS.md` D19）

#### 买什么服务器（2026-09 核实；**下单前重查一遍价格与政策**）

| 项 | 建议 | 说明 |
|---|---|---|
| **配置** | **2 核 4G 起** | 2 核 2G 跑 JVM + MySQL + 40 人偏紧（备份/统计时会卡） |
| **IP** | **固定公网 IP + 包月/包年** | 买服务器自带、无需额外租；**别选按量付费的临时 IP**——证书绑 IP，**IP 一变证书当场作废** |
| **系统** | Ubuntu LTS / Debian | 与本文命令一致 |
| **价格（学生机，需学信网认证）** | 阿里云 2 核 2G 约 **38–68 元/年**；腾讯云 2 核 2G 约 **75 元/年**、2 核 4G 约 **156 元/年** | 2026-09 核实的行情，**动手前重新查** |
| **香港 / 海外节点** | 免备案，约 **34–38 元/月** | **大陆访问取决于线路**（默认 BGP 非优化可能很差），校园网无实测数据；要选就先 ping 测过再买 |

> ⚠️ **下单前必须确认的一件事（这不是小事，可能白花钱）**：
> 国内云对"**没有备案的站点**"会不会拦 80/443，**官方口径是矛盾的**——
> 腾讯云官方文档写的是拦**域名**（未提纯 IP），阿里云 FAQ 却说"无论用 IP 还是域名、未备案前均不允许开通网站访问"；
> 社区实测是"**纯 IP + 非标端口**一般长期可用，**纯 IP + 80/443** 有被扫到后阻断的报告"。
> → **下单前找客服确认，或者先买最短周期实测**（别直接付一年）。
> 若确实被拦，可选的退路：先用非标端口顶（不合规、仍有风险）、或换香港节点、或走域名 + 备案。

#### 12.2.1 上 HTTPS：用 Let's Encrypt 的 **IP 地址证书**

**不需要域名、不需要备案**：Let's Encrypt 自 2026-01-15 起为 **IP 地址**签发证书。
将来若办了域名，再换成域名证书（同一个 Nginx 换证书路径 + 加 `server_name`，其余不变）。

**前置条件**：

- **固定的公网 IP** —— 买服务器时自带，**不需要额外租**；买**包月 / 包年**套餐即可
  （别选按量付费的临时 IP）。**证书绑的就是它，IP 一变证书当场作废。**
  这只与买服务器有关，**与域名 / 备案无关**。
- **80 端口对公网开放** —— webroot 验证走 `http-01`，Let's Encrypt 会回来访问
  `http://<IP>/.well-known/acme-challenge/…`。
- **certbot ≥ 5.4**（webroot 支持 IP 地址的版本；`--ip-address` 是 5.3 新增，
  `--preferred-profile` 是 4.0 新增）。

**步骤**：

1. **Nginx 先只配 80 端口**，并在其中留出 ACME 验证目录：
   `location /.well-known/acme-challenge/ { root /var/www/certbot; }`。
   ⚠️ **不要一上来就配 443** —— 443 段要引用证书文件，而证书还没签出来，Nginx 会起不来。
   **顺序必须是：先起 80 → 签证书 → 再加 443 段。**
2. **先用 staging 试跑**（不消耗正式额度、先把流程验证通）：
   ```bash
   certbot certonly --staging --preferred-profile shortlived \
     --webroot --webroot-path /var/www/certbot \
     --ip-address <你的公网IP>
   ```
   ⚠️ **不许加 `--nginx`** —— nginx / apache 插件**尚不支持 IP 地址**，只能用 `--webroot`
   （或 `--standalone`，但那要求先停掉占用 80 端口的 web server）。
3. 通了之后**去掉 `--staging`** 再跑一次，拿正式证书。
4. **手工**在 Nginx 里指向证书（`certbot` 目前**只签发、不安装**）：
   `/etc/letsencrypt/live/<IP>/fullchain.pem` 与 `privkey.pem`；然后补上 443 段
   （反代到本机 `8080`）与 80 → 443 跳转，`nginx -s reload`，
   浏览器开 `https://<IP>` 确认有锁头。
5. **配 deploy hook**，让每次自动续期后 Nginx 重载：
   往 `/etc/letsencrypt/renewal-hooks/deploy/` 放脚本执行 `nginx -s reload`。
6. **配「续期失败」告警**（**这条不能省**）：
   IP 证书只有 6 天有效期，一年要成功续期约 60 次；失败若没人察觉，
   6 天后团员打开看到的是"不安全"警告页，而作者最后才知道。
   可用作者已有的 Telegram 机器人推送，或退化为邮件。
7. **上线前必须真的跑通一次**：staging 签发成功 → 正式签发成功 → **手工触发一次续期**
   → 确认它自动重载了 Nginx。**"配置写好了"不等于"跑通了"。**

**一个容易混淆的点**：**不能用 `--nginx` 插件 ≠ 不用 Nginx。**
插件只是 certbot"顺手帮你改 Nginx 配置"的便利功能，它不支持 IP 证书，所以那两行 `ssl_certificate`
要手工写。**Nginx 本身照旧干这五件事**：

- **反向代理**：对外 443 → 本机 `8080`（Java 应用本身照旧跑 HTTP，不需要改）
- **TLS 加解密**：证书由 Nginx 加载并使用
- **80 → 443 跳转**、静态文件、限流、访问日志
- **转发真实客户端 IP**（一行配置的事，漏了会**静默失真**）：反代之后应用拿到的
  `getRemoteAddr()` 是 `127.0.0.1`——**"我的登录设备"里显示的 IP 会退化成 `127.0.0.1 *`**，
  按 IP 的登录限流也会被拉平成同一条。所以 Nginx 要送 `X-Real-IP` / `X-Forwarded-For`，
  应用侧只在**确实处于反代之后**时才信任这两个头——**无条件信任等于让客户端自己填 IP**。
- **webroot 模式下应答 ACME 的验证请求**——所以 Nginx 是签发环节的必经之路

#### 12.2.2 将来换成域名证书

办到域名后：Nginx 加 `server_name` + 把证书指向域名证书即可，反代与其它配置都不用动。
（域名路线的前置条件与坑：能备案的服务器须**大陆节点 + 累计订阅 ≥ 3 个月 + 有公网带宽**；
域名须**国内注册商 + 个人实名且与备案人一致**；**个人备案的网站名称不得含"协会 / 俱乐部 /
团体 / 工作室"等字样**（"乐团管理系统"很可能被判"与主体性质不符"而驳回）；
工信部短信核验须 **24 小时内**完成；取得备案号后须放网站底部，且**上线 30 日内还要做公安联网备案**。）

## 12.3 配置管理

用 **`application.yml` + Spring profile + 环境变量**。

> ❌ **反面教材**：作者另一个项目里有段 `load_env()`，逐行读 `.env` 并**静默覆盖同名系统环境变量**。
> 那在多环境部署时是隐患——**不要照抄这种做法**。
> 正确姿势：环境变量优先级高于配置文件，且加载过程要显式、不静默覆盖。

## 12.4 安全加固

见 `SECURITY.md` 的 **F 节**，上线前逐条打勾。要点：

- SSH 密钥登录、禁 root、改默认端口
- 防火墙只开 22 / 80（+443）
- **MySQL 只监听 `127.0.0.1`**，不暴露公网
- 应用不用 root 连库，单独建低权限账号
- **日志轮转**：logback 按天切分 + 保留 30 天（防日志吃满磁盘）

## 12.5 备份（**这一节最重要**）

### 三层

| 层 | 做法 | 频率 | 保留 |
|---|---|---|---|
| 服务器本地 | `mysqldump --single-transaction` 全库 | **每日凌晨** | 14 天 |
| **异地** | **拉回作者本机** | 每周 | 8 周 |
| 兜底导出 | 管理员在后台点"导出全量数据"（JSON） | 按需 | 自己存 |

**文件目录（`/data/band/uploads/`）也要一起备份**——录音和照片不在数据库里。

### 三条硬要求

#### 1. **必须做「删库 → 从备份恢复」演练**

在一台临时库上把备份恢复出来，抽查 3 条数据能对上。

> **没演练过的备份等于没有备份。** 这是最容易自欺的一步——
> 备份命令天天成功执行，但恢复时才发现备份文件是空的或者结构不对，这种事非常常见。

**演练频率**：上线前一次；之后每季度一次。

#### 2. **备份文件本身当作机密保管**

它包含 `member.initial_password` 明文（未激活账号的初始密码，见 `01-认证与账号.md`）。
**备份文件泄露 = 未激活账号的初始密码泄露。**

→ 备份目录权限收紧；异地传输走加密通道。

#### 3. **备份失败必须可见**

后台首页显示 **"上次成功备份时间"**，超过 **48 小时**标红。

> 通知渠道由作者自行安排，**系统只负责把这个状态显示出来**，
> 不要做成"失败了但谁也不知道"。

## 12.6 第一天上线的逐步手册

> **这一节和下面的 §12.7 检查清单是一对**：这里说"**怎么做**"，清单说"**做完了没**"。
> 前提：你已经按 §12.2 选了服务器（见那节的「买什么服务器」）。

**0）上服务器之前，先在本机把这套跑通一遍**（`mvn package` 出 jar、`java -jar` 起得来、`/api/health` 通）。
   **别把"第一次跑通"留到服务器上**——本地能复现的问题，在服务器上排查要慢十倍。

1. **SSH 安全基线**（照 `SECURITY.md` F 节做：密钥登录、禁密码登录、改默认端口、防火墙只开必要端口）。
2. **装运行时**：JDK 17 与 MySQL 8。MySQL **只监听 `127.0.0.1`**（`SECURITY.md` F3），**不要暴露公网**。
3. **建库与建表**：建库 `band` + 低权限账号 `band_app`，执行 `sql/schema.sql`（脚本可重复执行）。
4. **传 jar 与配置**：jar 放 `/opt/band/`；**数据库密码只放在服务器本地的 `application-local.yml`**（不进 git，见 §12.3）。
5. **配 systemd**（开机自启 + 崩溃自动重启；**不用 Docker**）：

```ini
# /etc/systemd/system/band.service
[Unit]
Description=ForBand 乐团管理系统
After=network.target mysql.service

[Service]
User=band
WorkingDirectory=/opt/band
# application-local.yml 放在同目录，密码不进命令行（ps 看不到）
ExecStart=/usr/bin/java -Xms256m -Xmx768m -jar /opt/band/band.jar --spring.profiles.active=prod,local
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

   `systemctl daemon-reload && systemctl enable --now band` → `systemctl status band` 确认在跑。
6. **配 Nginx 反代**（`SECURITY.md` §12.4 的要求都在里面：真实 IP 转发、静态资源、限流留白）：

```nginx
# /etc/nginx/conf.d/band.conf
server {
    listen 80;
    server_name _;                      # 用 IP 访问，不配域名
    client_max_body_size 60m;           # 录音/照片上传，留足余量

    location / { proxy_pass http://127.0.0.1:8080;
                 proxy_set_header Host $host;
                 proxy_set_header X-Real-IP $remote_addr;   # 登录设备列表要显示真实 IP
                 proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }

    location /.well-known/acme-challenge/ { root /var/www/certbot; }   # 给 certbot webroot 用
}
```

7. **签 IP 证书 + 补 443 段**：**严格按 §12.2.1 那 7 步做**（顺序不能反：**先起 80 → 签证书 → 最后才加 443**；
   `--webroot` 而不是 `--nginx`；签完配 deploy hook 重载 Nginx）。
8. **改掉默认管理员密码**（`docs/01` §1.4 的"首次部署"那节）：`AdminSeeder` 的初始密码**上线前必须换成只有管理员知道的强密码**。
9. **跑一遍 §12.7 的检查清单**，每一项都在备注里写上**验证方式**（命令 / 操作 / 截图）。
