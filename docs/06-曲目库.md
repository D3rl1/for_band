# 06 · 曲目库

## 6.1 这个板块解决什么

集中管理乐团要练、在练、练过的曲子，并挂在曲目下的**参考音频与谱子**供团员下载。

---

## 6.2 数据模型

### `piece`（曲目）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `title` | varchar(64) | 曲名 |
| `composer` | varchar(64) NULL | 作曲 |
| `arranger` | varchar(64) NULL | 编曲 / 移植 |
| `category` | varchar(32) NULL | 体裁（合奏 / 独奏 / 协奏 / 序曲 / 组曲…） |
| `difficulty` | tinyint NULL | 难度（1~5） |
| `duration_sec` | int NULL | 时长（秒） |
| `status` | varchar | 见 §6.4 |
| `note` | text NULL | 备注 |
| `created_by` / `created_at` / `updated_by` / `updated_at` | | |

索引：`idx_status`、`idx_title`

### `piece_attachment`（曲目附件）

| 字段 | 说明 |
|---|---|
| `id` | PK |
| `piece_id` | |
| `kind` | `AUDIO` 参考音频 / `SCORE` 谱子 |
| `file_id` | 关联 `file`（见 `08-练习录音与文件存储.md`） |
| `uploaded_by` / `uploaded_at` | |

## 6.3 接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/pieces` | 登录 | 曲目列表（分页）。支持 `?status=&keyword=` |
| GET | `/api/pieces/{id}` | 登录 | 曲目详情（含附件列表） |
| POST | `/api/pieces` | 管理员 / 团长 / 指挥 | 新建曲目 |
| PUT | `/api/pieces/{id}` | 管理员 / 团长 / 指挥 | 修改 |
| POST | `/api/pieces/{id}/attachments` | 管理员 / 团长 / 指挥 | 上传音频或谱子（走统一文件上传接口） |
| DELETE | `/api/pieces/{id}/attachments/{aid}` | 管理员 / 团长 / 指挥 | 删除附件 |

## 6.4 业务规则与边界

### 曲目状态（四态）

| 状态 | 含义 |
|---|---|
| `CANDIDATE` 备选 | 想排但还没排 |
| `REHEARSING` 在练 | 当前正在排练 |
| `READY` 已成熟 | 能上台了 |
| `PAUSED` 已停排 | 练过但暂时不演了 |

### 曲目库的范围

**「在练的」+「想排的备选」。**

备选是很重要的一半——团长平时想排什么可以随手记进来，以后排期时直接从里面挑。

### **不做「曲目 → 版本」父子结构**

民族管弦乐里同一首曲子的不同编曲 / 配器版本差异极大（配器、难度、时长都不同）。
最初的设计建议做成父子结构（一个曲目挂多个版本），**用户否掉了**：

> 他们会**自己上传音频和谱子**，版本差异靠各自上传的附件体现即可，不需要系统来表达版本关系。

因此如果《金蛇狂舞》有刘文金版和李复斌版，就是**两条独立的 `piece` 记录**，
靠曲名相同自然归组。**不要**为版本关系建表。

### 附件与文件存储

音频与谱子都走**统一文件存储**（`08-练习录音与文件存储.md` F4）：

- **上传**：`POST /api/files` → 返回 `file_id`
- **下载**：`GET /api/files/{id}`，**必须鉴权**；严禁暴露公开静态目录

### 可见性（**待定项 T3**）

| 现状 | 备注 |
|---|---|
| 谱子与音频**对全团公开**（登录即可下载） | 用户标注为**暂定**，理由：他们自己会上传，还没想清楚是否全部公开 |
| **荣誉团员：一律不可看 / 不可取** | 2026-09-23 定：用户原话"账号只是为了让他们追忆往事，**跟谱子扯不上关系**"。**曲名与演出曲目单仍可看**，只有附件（谱子 / 音频）不可 |

> ⚠️ 记住这条的含义：**公开 = 任何登录团员都能下载转发。**
> 将来若要收紧，**改的是权限模型而不是界面**，所以 `piece_attachment` 的可见性
> 从数据层就要预留表达空间。

### 谱务：只有电子谱

**本项目没有纸质谱管理。** 用户确认"我们现在没有纸质谱"，全部使用电子谱，
因此原本规划的"谱务板块"（纸质分谱的库存与借还）**已取消**，功能并入本板块的附件。
