# 00 · 总览与架构

> **阅读顺序**：`README` → `AGENTS.md` → `docs/00`（本文件）→ `交接单.md` → `docs/13` → `docs/01`~`docs/15`。
> **待办与"做没做"看 [`交接单.md`](../交接单.md)**，本目录只管"要做什么"。

> **读 `docs/` 前先知道**：规格条目可能带状态标记（`🚧` / `⏸` / `❌` 三个符号），
> **不带标记的默认就是「要实现，且已实现」**。含义与三条硬规矩见 **§0.9**；执行者 `tools/spec_check.py`。

## 0.1 项目是什么

给学校**山水民族管弦乐团**（约几十人）做的管理系统。全团团员登录使用。

核心用途：看排练与声部课安排、签到、查自己的出勤、上传练习录音、看曲目与谱子、回顾演出。
管理层维护名册、安排活动、统计考勤、管理曲目与演出档案。

## 0.2 架构

```
        ┌──────────────────┐
        │   后端 API 服务    │   Spring Boot + MySQL
        │   唯一数据源       │   所有业务逻辑与权限都在这一层
        └─────────┬────────┘
                  │  REST + Bearer Token
        ┌─────────┴─────────┐
        │                   │
   ┌────▼─────┐       ┌─────▼──────┐
   │  网页端   │       │  安卓 App   │
   │ 所有设备  │       │  安卓团员   │
   └──────────┘       └────────────┘
```

### 两条必须守住的架构约束

1. **两个客户端吃同一套接口，后端不为任何客户端做特化。**
   一旦某个接口为了 App 开特例，前后端分离就白做了。
2. **权限判定集中在 `PermissionService` 一处。**
   绝不散落成 `if (role == ADMIN)`——角色定义还会改（见 0.6 暂定项），散着写必然漏改。

## 0.3 技术栈

| 层 | 选择 | 说明 |
|---|---|---|
| 语言 | Java 17 (LTS) | |
| 框架 | Spring Boot 3.2.x | **不追最新版**——教程与搜索结果最多，卡住时能搜到答案 |
| 数据库 | MySQL 8.0 | |
| 持久层 | MyBatis-Plus | 国内 JD 出现率高、SQL 显式可见。理由与被否掉的 JPA 见 `DECISIONS.md` D2 |
| 鉴权 | 手写拦截器 + BCrypt | 期 1 不引 Spring Security。见 `DECISIONS.md` D6 |
| 网页端 | 原生 JS + Bootstrap 5（**自托管**） | 不引构建链；第三方文件随仓库走。见 `DECISIONS.md` D7 |
| 安卓端 | **Java WebView 壳**（`android/`，aapt2→javac→d8 打包，**无 Gradle**） | 期 2 原定的 **Kotlin + Retrofit 原生版没有落地**；现为打开线上 `/events.html` 的壳。2026-10-22 按仓库现状订正；**是否改回原生待定** |
| 部署 | `jar` + systemd + Nginx + certbot | **全程 HTTPS**（用 IP 地址证书过渡，免域名免备案）。见 `DECISIONS.md` D19 |

**认证方式**：`Authorization: Bearer <token>`，token 是**服务端存储的不透明随机串**（不是 JWT）。
理由见 `DECISIONS.md` D4 / D5。

> **排序原则**：按"最快产生真实价值"排，**不按技术依赖排**。
> 网页端先做是因为它覆盖所有人（含 iPhone / 鸿蒙）、开发最快，而且**它逼着你把接口定稳**——
> 之后 App 接一套已经稳定的接口，比两个客户端同时改轻松得多。
>
> **请假审批流排在期 1 的后半段**：它是"申请单 + 审批 + 状态机 + 两个界面"，会明显拉长工期。
> 先把签到跑起来让团员真用，再做请假。
>
> **2026-09-23 补一行「期 1.5 上线」**：原先"团里有人签到过一次"这个完成标志挂在期 1 上，
> **但网页端不部署到服务器就没人访问得到**——所以上线其实是它的**前提**，单独排一期（内容见 `docs/12`）。
> 部署是"一次性的活"，不放进期 1 里跟业务功能抢时间。
>
> **2026-09-23 把「反馈 + 更新公告」也归入期 1.5**（`15`）：理由是**它们在上线那一刻价值最高**——
> 团员一用就会发现问题，问题渠道**从第一天就接得住**；而你上线后必然要连续修 bug、加东西，
> 公告正好用来告诉团员"这次改了什么"，省掉"咦怎么变了""我之前提的修了没"这两类来回问。
> **关键：这两件事都不依赖通知渠道 T12**（一个是在系统内公开、一个是进系统时看到），**不会互相卡住**。
> **2026-10-26 补**：反馈渠道已升级为 **「问题讨论」公开栏**——"改没改"由状态与回帖公开回答，
> 不再需要把处理结果单独推回给谁（见 `15` §15.1 / §15.8）。
>
> **2026-09-23 再把「个人页面」也归入期 1.5**（`14` §14.6.4「个人页」）：理由同样是
> **上线时价值最高**——团员第一次进来，侧栏顶上那个头像不再是冷冰冰的"姓名首字"，
> 而是他自己挑的一个小动物；这也让系统**第一眼就更像个正经产品**（对作者的求职作品也加分）。
> **它同样不依赖期 2–6 的任何模块**：用**预置头像库**绕开了尚未实现的文件上传基建
> （见 `14` §14.6.4 的说明——真正上传自己的照片要等期 5）。
> **2026-10-22 核对**：统一文件上传基建后来已经落地（`FileController` 的 `/api/files`），
> 上面这句保留为**当时的取舍理由**；「换自己的照片」仍按原计划排在期 5。
>
> **2026-09-24 补一行「期 1.6 个人主页批次」**：用户在系统**已经上线、有人真用**之后提的
> 一组补充需求（荣誉团员口径 / 生日通告 / 看别人的主页 / 访客记录）。
> 单排一期是因为：**它们全是"用起来之后才想得到"的东西**，而在此之前谁也不知道该要什么
> ——这正是"不压硬日期、以'被真人用起来'为完成标志"的回报。
> ⚠️ **它同样不依赖通知渠道 T12**：生日通告是**进系统时看到的页面内弹层**，不是推送。
>
> **2026-09-26 补一行「期 1.7 我们的专场批次」**：用户在期 1.6 之后提的**展示类**需求——
> 一条能一年年长下去的时间线，把历年的专场串成一个故事（规格见 `17`）。
> **为什么单排一期、而不是塞进 `07-演出.md`**：它读的虽然是演出的数据，
> 但**是"展示与策展"板块**——用途、权限、照片存储三样都与 `07` 的"档案运维 + 全员晒图"不同
> （分工表见 `17` §17.1）。塞进去会让 `07` 一半在讲 CRUD、一半在讲滚动动画。
> ⚠️ **两条边界**：① **它不依赖通知渠道 T12**（纯展示页）；
> ② **它不是 `09-历届成员.md` 的复活**——那份整份 ❌ 不做、别再引用它当先例。
>
> **2026-09-27 补一行「期 1.8 界面打磨批次」**：用户在专页那一批之后提的**观感**需求——
> "我想让整个界面看起来更活一些"，第一句就是"让数字动起来（比如 37 就从 0 数到 37）"。
> **为什么单排一期、而不是塞进某个页面文档**：它**横跨多个页面**（统计 / 活动 / 活动详情 / 个人栏 /
> 各种列表），没有单一归属；且它**碰的是 `14` §14.6.6 的红线**（数字滚动改文字内容、
> 与"一次只动一个焦点"有张力）⇒ 需要**独立的第七条留痕**与验收，塞进任何一页都会被漏掉。
> ⚠️ **两条边界**：① **三样都只在"首次出现"播一次**（重刷不重播）——这条不许为了让"更活"而放宽；
> ② ⚠️ **`14` §14.6.6 总原则"装饰性动效是负债"是当面引用过的**，用户知情后仍然选了"出勤横条"
> （与点阵重复）⇒ 记成**已知情接受**并写进 `DECISIONS` **D22**，**别当成"可以再加别的装饰"的先例**。

## 0.6 暂定项汇总（**实现时不许当既定事实**）

**本表是暂定项的唯一权威**（2026-09-24 收口）：编号 `T<N>` 全局递增、**永不复用**。
各板块文档里的"待定项"小节**只是指针**，内容一律以本表为准。
⚠️ **照别处的旧说法判断会出错**——2026-09-24 之前实测漂过：`07` 曾被迫自己声明
"已从本表移出、别再照那里的旧说法判断"，这正是"同一条写在两处"的必然结果。
`tools/spec_check.py` 有一条规则核"正文里的 `T<N>` 必须在本表里找得到"。

这些条目是**当前按最简单方案实现、但已知将来会改**的。每一条都附了替补方案，
条件明朗后一次性拿出来讨论。

| # | 暂定内容 | 现方案 | 将来可能的改动 | 改动影响面 |
|---|---|---|---|---|

### 0.7.1 "做成桌面应用" = 给网页套一个壳

我们这套前端（原生 HTML/CSS/JS、零框架零构建链、动画只用 CSS `transform`/`opacity` + SVG）**移植性极好**：
没有 `:has()` / `backdrop-filter` / View Transitions 这类挑引擎的特性，`Web Audio`、`localStorage` 在任何 WebView 里都有。

> ⚠️ **2026-09-24 更正**（上面那句要拆成两档看，**别整句删掉**）：
> - **必需特性**：不支持的引擎会**功能残缺**。这一档里**确实没有**挑引擎的东西 —— **上面那句在这一档仍然有效**。
> - **增强特性**：不支持的引擎只是**少一点好看**，功能照旧。**已经用了两处**：
>   ① **跨文档 View Transition**（非 Chromium 退化成瞬时切换，见 `14` §14.6.4「跳页过渡」）；
>   ② **`:has()`**（侧栏展开命中区那一条；不支持的引擎退回"只有 92px 轨道能触发"，
>      就是改之前的老行为，见同节「展开的判定范围」）。
> **规矩**：新增的挑引擎特性**只能落在"增强"这一档**——不许拿它承载"不支持就没法用"的功能。
所以"套壳"之后**网页代码一个字都不用改**（VS Code、Slack、微信桌面版都是这么做的）。

| 做法 | 效果能否原样照搬 | 体积 | **手机能用吗** | 电脑体验 | **以后怎么更新** |
|---|---|---|---|---|---|
| **PWA**（最薄） | ✅ 就是浏览器本身 | 0（不用装） | **能，且这是它的主场** | Edge/Chrome"安装"后是独立窗口 + 图标 | **改网页即全员生效**，无人需要重装 ✔ |
| **Tauri**（中等） | ✅（Windows 上是 WebView2 = Chromium；macOS 是 Safari 内核，我们没用到它不支持的东西） | 几 MB | 不能（移动端仍实验） | 独立窗口 + **托盘 / 开机自启 / 系统通知** | 每次发版要**重新分发安装包** + 自动更新 + 未签名会被 Windows 拦 |
| **Electron**（最厚） | ✅ 逐像素一致 | 150–250MB | 能但很重 | 同 Tauri | 同 Tauri |
| **JavaFX / Compose Desktop** | ❌ **搬不过来**（要用 Java 把界面重画一遍） | — | — | — | — |

**倾向：PWA 优先**，两条理由：① **团员日常用手机**——PWA 是唯一能在手机上给出"全屏 + 自己的图标"、又不用发安装包的路；
② **不改变现在的更新方式**（改网页即全员生效；Tauri / Electron 会把这条优点换成"每次发版都要用户重装"，对小项目是**倒退**）。
**Tauri 何时才值得**：真的需要**托盘常驻 / 开机自启 / 桌面系统通知 / 一个能发给别人的 `.exe`** 时。**Electron 不推荐**（体积与维护都不划算）。

**两个硬前提（动手前必须知道）**：

1. **壳必须加载"服务器地址"**：页面里的资源与接口**全是绝对路径**（`/band.css`、`/api/auth/me`…），
   用 `file://` 打开本地页面会**全部 404**。所以壳要做的是"打开我们的网址"，**不是**"打包本地文件"。
2. **HTTPS 已经有了**（`docs/12` 的 IP 证书）：手机上"添加到主屏幕"没问题；
   但**纯 IP 地址下浏览器会不会给"安装"提示，要真机实测**——本节**不做承诺**。

**真要做 PWA，"最薄的一层"是什么**（~~将来开工照这个做~~ → **2026-10-19 已被推翻，见下方留痕**）：
~~`manifest.webmanifest` + 图标集 + `display: standalone`，**先不碰 service worker**（零维护零风险；离线能力等真有需要再加）。~~

> **📌 2026-10-19 留痕：为什么推翻"先不碰 service worker"**
> - **用户诉求变了**：这次不是"最薄一层"，而是明确要 **① 装成壳 ② 断网能看 ③ 新版本有提示**（见 `19` §19.1）。
>   离线与更新提示**技术上只能靠 service worker**，绕不开。
> - **原顾虑（缓存一致性负担）用三条闸门关住**，写进 `19`：
>   ① **`/api/` 一律不缓存**（防换账号串数据，也是安全红线）；
>   ② 缓存只存**页面骨架 + 静态资源**，且页面按路径名去重；
>   ③ 更新**必须用户点「刷新」**，`install` 里绝不 `skipWaiting`，绝不自动 reload。
> - **另一处更正**：manifest 文件名用 **`manifest.json`**，不用 `manifest.webmanifest` ——
>   Spring Boot 对 `.json` 的 MIME 有稳定默认值，`.webmanifest` 可能被当二进制下载导致 Chrome 不认。
> - **范围边界**：仍然**不碰后端**、不做 Web Push（T12）、不做桌面壳。


### 0.7.2 通知渠道（排练安排等提醒）

**先纠一个方向**：**"要通知"不等于"要桌面壳"**。Tauri / Electron 的系统通知**只有装了那个客户端的人收得到**，
而团员在手机上 ✗。手机上要收提醒，走的是 **Web Push**——而它的门槛恰好是 **iPhone 必须先"添加到主屏幕"**
（iOS 16.4 起支持）→ **所以这条需求反而指向 PWA**，不是桌面壳。

**候选与代价**（这块是**独立的一整件事**，不是套壳的附属）：

| 渠道 | 门槛 | 代价 / 现实 |
|---|---|---|
| **团里现成的群**（微信群等） | 零 | 触达率通常**比任何推送都高**；但不在本系统里，做不到"按人 / 按角色精准提醒" |
| **邮件** | 有邮箱即可 | 不即时、容易被忽略；适合当"重要事项"的兜底 |
| **Telegram Bot** | 需装 Telegram | 作者另一个项目已有"**触点 + 去重状态表**"的成熟做法，可照搬 |
| **Web Push**（配 PWA） | HTTPS + 用户**授权** + iPhone 需先加到主屏幕 | 服务端要新增"**设备订阅存储 + VAPID 发送端**"；**送达率不保证**（用户拒绝、系统省电都会吞掉） |
| **桌面壳的系统通知** | 需装桌面客户端 | **对团员无效**（他们在手机上） |

**结论口径**：真实做法是"**推送 + 兜底**"——推送负责即时，兜底用团里现成的群 / 邮件。

**与本项目既有条目的衔接**：`docs/13` 的 `notification_log` **继续只留表、不实现发送端**；
`docs/01` 的 **U-1**（新设备登录告警）就卡在"渠道未定"——**渠道一旦定下来，这两处都能解锁**。

### 0.9.1 状态标记：**只标例外**

`docs/` 里写的每一条规格项，**默认含义 = 「要实现，且已实现」**（所以绝大多数条目不标）。
只有当一条**不是**这个默认状态时，才在它所在行的**行尾**加一个标记：

| 标记 | 含义 | 必须附什么 | 例 |
|---|---|---|---|
| （无） | 要实现，且已实现 | —— | 绝大多数条目 |
| `🚧` | 规格已定、**已交给实现方**、代码还没做 | **交接单编号** | 请假理由必填 → 交接单 #10 |
| `⏸` | 要做，但**依赖别的事**，现在不做 | **原因** | JSON 全量导出随部署暂缓 |
| `❌` | **刻意不做**（含用户取消） | **原因** | 期 6 历届成员（用户 2026-09-23 取消） |

三种标记的**字面写法**（照这个形状写，脚本按它认；`#N` 必须是 `交接单.md` 里真实存在的编号）：

```
🚧 待实现（#10）
⏸ 暂缓（随部署）
❌ 不做（用户 2026-09-23 取消）
```

> ⚠️ **加粗可以，但关键词别拆断**（2026-09-24 踩到）：标记与「待实现 / 暂缓 / 不做」之间**允许加 `**`**
> （本项目文档处处加粗，写成 `❌ **不做（原因）**` 很正常，脚本认）。
> 但**关键词本身要连在一起**：一旦写成脚本认不出的形状，标记会被**静默忽略**——
> 它既不算 `❌`、也不再算"无标记"，于是脚本转头按"**无标记 = 已实现**"要求它**必须存在**，
> **报错方向正好相反**，而且很难联想到"是我标记的写法不对"。
> **判据**：挂完标记跑一次 `python tools/spec_check.py`，**确认它真的核到了你那条**——
> 想验得更实，就把标记故意写坏一次，看它报不报（本项目对闸门的硬规矩）。

**三条硬规矩**：

1. **`🚧` 必须能在 `交接单.md` 里按编号找到同一事项**——找不到就是漏交接，
   由 `tools/spec_check.py` 报警。这是整套机制里**最值钱**的一条，它挡的正是"规格改了但没交出去"。
2. **`❌` / `⏸` 的条目，不许在别的文档里被当成「既有先例」引用**。
   2026-09-24 抓到过实例：期 6 历届成员整体取消后，`03` 与 `14` 还在拿它的「毕业寄语」当先例论证——
   引用比实现活得久，所以脚本对这两类标记要做**跨文档引用检查**。
3. **状态变了就当场改标记**（实现方交回时删掉 `🚧`、`交接单.md` 那行改 `✅`）。
   标记不跟着变，它就变成一句谎言——这比不标更坏。

### 0.9.2 `交接单.md` 是**状态的唯一权威**

- `docs/` 是**规格**的权威（"要做什么"）；`交接单.md` 是**状态**的权威（"做了没"）。
  两者冲突时**以 `docs/` 为准**（这条是 `AGENTS.md` 规格优先原则的延伸）。
- 老的两份（09-23 的 `修正清单` / `移交事项`）**已归档到 `docs/archive/`**（那里有 `INDEX.md` 说明谁取代了谁），
  未办条目已并入 `交接单.md`；**以后不再新建日期命名的交接文件**（否则内容重叠、且没人知道以哪份为准）。

### 0.9.3 交出去的东西必须有回执

实现方交回时，必须在 `交接单.md` 对应行填回执，**四样缺一不可**：

1. 改了哪些**文档段落 / 代码文件**；
2. **`mvn test` 的实际数字**（写 `117/117`，**不许写"全绿"**）；
3. 新增了哪些**测试名**（动了权限 / 角色 / 表结构的，按 `AGENTS.md` 硬规矩必须有**反例**测试）；
4. 本次**没做完**的项（没有就写"无"）。

> **为什么第 2 条不许写"全绿"**：`AGENTS.md` 里原本写死过一个测试条数（还标着"全绿"），
> 而 2026-09-24 实测的条数是它写的**近四倍**——**"没改坏的唯一凭据"这个凭据，它自己的数字是错的**。
> 所以规矩是：**会漂的数字不许写死在文档里**，要写就写实测那一刻的值。

### 0.9.4 刻意不做的（免得后人以为漏了）

- **不给每条规格项都打状态**：默认状态不标是**刻意的**——十几篇逐条维护标记，成本远大于收益。
- **不引入覆盖率 / 圈复杂度 / 变异测试这类门禁**：本项目由不读代码的人维护，
  闸门建在「**文档说的和代码里有的对不对得上**」，不建在「代码质量度量」上。
  执行者只有 `tools/spec_check.py` 一个，**改完 `docs/` 跑一次**即可。

### 0.9.5 闸门查什么（`tools/spec_check.py`，共十六条）

R1–R5 与 R10 查「**文档 ↔ 代码**」，R6–R9 查「**文档体系自己乱不乱**」，R11–R13 查「**前端页面的隐式契约**」，
R14–R16 查「**文档会不会再长回去**」：

| 规则 | 查什么 |
|---|---|
| **R1** | 没标状态的表 / 列（含 `NOT NULL` 约束）/ 端点 → 代码里必须存在 |
| **R2** | 带 `🚧` 的条目，括号里**必须写交接单编号**（只写理由不算）；那个编号要在 `交接单.md` 里找得到。⚠️ **反向漏标只提示不判罚**（2026-10-07 补，`#96`）：`交接单` §二 里未办、却在任何 docs 里找不到对应 `🚧` 的条目，报进末尾「需人扫一眼」——**不 fail**，因为 §二 本来就有无需挂标记的条目（纯规格条、实现方自查发现的 bug） |
| **R3** | `❌/⏸` → 代码里不许存在；**完整路径**被别的文档引用才报错（只提到同资源根降为提示） |
| **R4** | 正文不许写死会漂的测试计数 |
| **R5** | 反向：Java 里有的端点，文档端点清单里必须有（实现跑到规格前面 = 漏回补） |
| **R6** | `docs/archive/` 里出现的每个 `#N` → `交接单.md` §五 来源对照表里必须有（防条目凭空消失） |
| **R7** | 正文里的 `T<N>` → §0.6 暂定项汇总表里必须有（防暂定项两处存放后漂移） |
| **R8** | 根目录每个 `*.md` → `README.md` 的「怎么读」表里必须被提到（防再平铺一份同类文档） |
| **R9** | `docs/archive/` 下每个文件前 6 行必须有 `🧊 已冻结` 横幅 |
| **R10** | `docs/10` §10.5 的 (码, HTTP, message) → 必须与 `ErrorCode.java` **逐条一致**（双向：文档有代码没有要报，代码有文档没列的也要报）。<br>⚠️ **§10.5 区域里挂着 `🚧` 标记时整块降为"提示"**——那标记的意思就是"已交接、代码还没做"；**实现方把那行删掉后自动变严格** |
| **R11** | `band-shell.js` 的菜单：图标 key **不许被两个不同页面共用**（`AGENTS.md` 前端第 6 条）、同一页在两视图下必须同图标、key 必须在 `vendor/icons/manifest.json` 里（否则空图标）、菜单项不许指向不存在的页面、菜单项不许重复 |
| **R12** | 带导航的每个页面：`<script src="/band-*.js">` 的**集合与顺序**必须一致（页头脚本串是隐式契约，**少抄一个 / 顺序抄错不报错、只出怪症状**） |
| **R13** | `sql/schema.sql` 建的每张表 → `docs/13` 里必须有 `` `表名` ``（表结构的唯一权威、"加一个模块"的第一步；建了表不登记 = 权威当场过期，而没有任何东西会报错） |
| **R14** | **体积预算**（兜底）：`交接单` ≤100 KB、`交接单-已办` ≤800 KB、`work_log`/`debug_log`/`更新告示` ≤120 KB、`DECISIONS` 与其它根 `*.md` ≤60 KB、`docs/*.md` ≤200 KB。超了就**轮转**，不要调大预算；既有超预算的登记在 `GRANDFATHERED` 里（现在只有 `docs/14`），**降回预算内必须自己删掉**，不许永久豁免 |
| **R15** | **台账卫生**（真正防回涨的那条）：`交接单` §二/§三 状态为 `✅` 的行数必须为 **0**（已办当场搬进 `交接单-已办.md`）；`交接单` 单行 >8 KB 判罚、>4 KB 提示；`work_log` 只许出现**当月**日期节、`debug_log` 只许出现**当季**复盘；`work_log` 单条 >5 KB 判罚、>1.5 KB 提示（存量只提示，从新条目起收紧） |
| **R16** | **大文件节索引**：任何 `docs/*.md` 或根 `*.md` 超过 **2000 行**（`Read` 会静默截断）必须带顶部节索引，且索引行号与实际 `##`~`####` 标题逐条一致。改完正文跑 `python tools/doc_index.py <文件> --write`。目前只有 `docs/14` 命中 |

三个标记的字面写法（**上面那张表里故意不写全**——脚本会认表格行/`###` 标题里的标记，
把语法本身写进表格行会被自己当成一条真标记，2026-09-24 当场踩到；**代码围栏里的不算**）：

```
🚧 待实现（#12）        ← 已交出去、代码还没做；括号里必须是交接单编号
⏸ 暂缓（随部署）        ← 缓办；括号里写原因
❌ 不做（期 6 已取消）   ← 刻意不做；括号里写原因
```

另外每次都打印一段**只提示、不判罚**的「需人扫一眼」：规格条目行里出现"未实现 / 待实现"
这类词却**没挂标记**的行。这类词在散文里合法（"证书还没签出来"），做成 fail 会天天爆红被无视。

> ⚠️ **两条反假阳性的设计**（2026-09-24 实测调过，改动前先读这段）：
> ① R3 对**引用块行（`>` 开头）且含"已取消 / 已作废 / 更正"类词**的**一律豁免**——
> 那种行本身就在说明"这东西已作废"（本项目反而要求留痕），报它等于逼人删留痕。
> ② R3 报的**行号是文件真实行号**（代码围栏行在缓存里占位而非跳过），
> 行号错位会把人送去改错地方。
> **假阳性会杀死闸门**：一条"喊狼来了"的规则会让整份报告被无视——宁可少报，不可乱报。

### 0.9.6 模块标准形（加一个业务模块照这个形状）

> 2026-10-06 登记（`交接单` `#172`）。这一节是**后端模块的"标准形"**——全项目重构后每个域都是这个形状，
> 新加模块照它写；`AGENTS.md` 的「**加一个模块**」按这七条给出**次序与闸门兜底**。

| # | 形状 | 说明 |
|---|---|---|
| 1 | **一域一包** | 每个业务域一个包（`com.forband.<域>`）：Controller / Service / DTO /（必要时）Lookup 都在这一个包下。**不按"控制器层 / 服务层"横切** |
| 2 | **Controller 只路由 + 鉴权注解** | Controller 只做"接路径、`@RequireRole` 声明角色、调 Service、包 `ApiResponse`"。**不写业务、不查库**；写操作挂 `@OpLog`（留痕，见第 6 条） |
| 3 | **Service 承载业务与权限** | 业务规则、可见范围裁剪、跨表校验都在 Service；**写操作一个 `@Transactional`**（门面方法签名与事务边界最稳，重构时不动它的就是这条） |
| 4 | **DTO = `<域>Dtos` 嵌套 record** | 一个域的 DTO 收进一个 `final class <域>Dtos`，用**嵌套 `record`**（如 `ConcertDtos.ConcertRequest`）。⚠️ **Entity 不外泄**——出参一律 View / Row record，**不把数据库实体（`@TableName` 那个）直接回给前端** |
| 5 | **分页统一 `PageResult<T>`** | 分页端点回 `PageResult<T>`（`?page=&size=`）。⚠️ **名册是"有意例外"**（它一次取全量再前端分页，见 `03`），**别拿它当反例去改别的域** |
| 6 | **留痕走 `log/OpAction`** | 操作日志**只用 `@OpLog(action = OpAction.XXX, …)` 注解 + `com.forband.log` 那套机制**，**别在 Service 里手写日志表插入**；新增留痕动作 = 在 `OpAction` 枚举里加一项 |
| 7 | **跨域读走 Lookup** | 一个域要读**别的域**的数据，走那个域暴露的 **`<域>Lookup`**（如 `common.SectionLookup`、`member.MemberLookup`），**不直接查别名域的表 / 不注入别名域的 Mapper**——避免域间耦合与循环依赖（`MemberShowcaseCountController` 单独住 `concert` 包，就是为破"concert ↔ member"这个环） |

> ⚠️ 这七条是**形状**、不是新规矩：重构后代码本来就长这样，本节只是把它**写下来**——
> 好让"加模块"有依据、也让 `docs/00` 的这张表与 `AGENTS.md` 的次序表**对得上**。
