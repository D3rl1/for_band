# 13 · 数据模型总表（**全库唯一权威**）

> ## ⚠️ 这份文件是唯一权威
>
> 规格分散在 13 份文档里，**实现者很容易在 A 文档加了个字段、忘了在 B 文档同步**——
> 写规格阶段就已经踩过一次这个坑（`event` 合并之后，旧表还留在别的文档里，
> 导致同一份规格里有两套表结构）。
>
> **规则**：任何表结构改动，**先改这里，再改对应板块文档**。
> 落地前必须拿这份总表把所有文档对齐一遍。

**共 22 张表**——其中 **18 张在期 1 就要建**，**2 张在期 1.5（上线配套）建**
（`feedback` / `release_note`，见 `15`），**`event_piece` 已建**（2026-09-24 更正：原先写"期 3 才建"，
实际随期 3–5 一起落地了，`sql/schema.sql` 已有这张表），
**`notification_log` 刻意不建**（本项目只留表设计与去重规则，不实现通知发送端，见 `00` §0.6 T12）。

表名用 `snake_case`，字段用 `snake_case`（Java 实体用 camelCase，由 MyBatis-Plus 映射）。

### ① `section` 声部

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigint | PK, AUTO_INCREMENT | |
| `name` | varchar(32) | NOT NULL, UNIQUE | 声部名 |

> **有意不带 `created_at` / `updated_at`**：声部是纯字典表，只有管理员偶尔增删改，不为它加审计列。
> **别顺手补齐**——那会制造一次无意义的表结构迁移。

初始数据（**平级，无上下级**）：
打击声部 · 提琴声部 · 胡琴声部 · 吹管声部 · 古扬声部 · 阮声部 · 琵琶声部

> **声部不设层级**（没有 `parent_id`）。曾考虑过"弹拨声部下辖阮声部 / 琵琶声部"的两级结构，
> **已否掉**——实际使用中直接就是阮声部、琵琶声部两个平级声部，多一个上级只是麻烦。
> 「古扬声部」含古筝与扬琴，两者差异记在 `member.instrument`，不再细分声部。

| `instrument` | varchar(32) | NULL | 乐器 |

| `role` | varchar(20) | NOT NULL | `ADMIN`/`LEADER`/`CONDUCTOR`/`SECTION_LEADER`/`MEMBER`/**`HONORARY`**（荣誉团员，见 `02` §2.3 与下方说明） |
| `status` | varchar(12) | NOT NULL | `ACTIVE`/`PAUSED`/`LEFT`/`GRADUATED` |
| `account` | varchar(32) | **UNIQUE**, NULL | 登录名；系统账号必有 |
| `password_hash` | varchar(72) | NULL | BCrypt |
| `initial_password` | varchar(16) | NULL | **仅未登录期间有值**，首次登录成功后置 NULL |
| `last_login_at` | datetime | NULL | |
| `is_system` | tinyint(1) | NOT NULL DEFAULT 0 | 管理员系统账号标记 |

| `alumni_message` | text | NULL | **毕业寄语**（历届成员页展示） |
| `honorary_until` | date | NULL | **荣誉团员的登录有效期**（2026-09-23 新增）。**授予时必须填**（默认毕业后 2 年）；**为空或已过期 → 不可登录**（fail-closed），但数据照留。非荣誉团员本列为 NULL |
| `note` | varchar(255) | NULL | 备注 |
| `avatar` | varchar(32) | NULL | **预置头像的受控标识符**（如 `fluent-frog`），见下方说明。为空 → 界面回退**姓名首字** |
| `intro` | varchar(100) | NULL | **个人简介 / 签名**（本人可写） |
| `contact` | varchar(128) | NULL | **联系方式**（一个自由文本框，本人自己写"微信 x / QQ y"），本人可写 |
| `birthday` | date | NULL | 生日。**默认只本人 + 管理员可见；对外只到「月-日」、不显示年份** |
| `created_at` | datetime | NOT NULL | |
| `updated_at` | datetime | NOT NULL | |

索引：`uk_account`(UNIQUE) · `idx_section_id` · `idx_status` · `idx_role` · `idx_is_system`

> **绝不物理删除本表行。** 退团/毕业用 `status` 标记。

> **个人资料四列（2026-09-23 新增）** —— `avatar` / `intro` / `contact` / `birthday`。
> 页面与视觉规则见 `14` §14.6.4「个人页」，权限见 `02` §2.3。
> **谁可写：本人 + 管理员**——先例是 `alumni_message`（`09` §9.3 的端点权限就是「本人 / 管理员」）。
>
> ⚠️ **`avatar` 存"受控标识符"，不是 URL、不是路径**——这是这套方案**零安全面**的全部秘密：
> 存标识符就不存在"客户端塞外链 / 路径穿越"的可能，服务端只需校验
> **`值 ∈ 预置头像清单 ∪ {null}`**。**预置清单是唯一权威**（与素材一起放在 `14` §14.6.4 指定的目录）。
> **别改成"存 URL"**——那会把一个枚举校验退化成一段要自己维护的白名单过滤逻辑。

> **`role = HONORARY`（荣誉团员）的语义**（2026-09-23 新增）：
> - **给"因毕业离团"的人保留一个只读身份**：`status` 仍是 `GRADUATED`（已离团），`role` 标成 `HONORARY`；
> - **只有 `status = GRADUATED` 的人才能被设为荣誉团员**（退团 `LEFT` / 休团 `PAUSED` 不适用）；
>   这条是**双向**的——已授予之后，也不允许把状态改成非 `GRADUATED`（见**不变式 13**）；
> - **权限 = 团员权限的只读子集**（"只减不增"），逐项见 `02` §2.3 的权限矩阵；
> - 他们**可以登录**（这是对 `01` §1.4「非在团禁止登录」的**有意例外**），
>   但受 `honorary_until` 约束：**到期即不可登录**，管理员可续期；
> - **不计考勤**，但**可以被列入演出名单**（见 `07`）。
>
> **实现方要一起改的两处**（规格点名，避免只改一半）：`sql/schema.sql`（`role` 的注释/枚举 + `member` 新列）
> 与 `src/main/resources/static/band-core.js`（`roleLabel` 含"荣誉团员"）+ `band-shell.js`（菜单白名单，见 `14` §14.6.4）。

### ④ `user_token` 登录令牌

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigint | PK | |
| `token_hash` | varchar(64) | NOT NULL, **UNIQUE** | **只存哈希，不存原文** |
| `member_id` | bigint | NOT NULL, FK→member | |
| `issued_at` | datetime | NOT NULL | |
| `expires_at` | datetime | NOT NULL | 签发 + 30 天 |
| `revoked_at` | datetime | NULL | 非空即失效 |
| `user_agent` | varchar(255) | NULL | 登录时的 UA，**粗解析**成"设备"展示（解析粒度与"认不出来怎么办"见 `01-认证与账号.md` §1.4） |
| `ip` | varchar(45) | NULL | 登录 IP（IPv6 最长 45）。**存完整值**（审计用），**只有展示时打码**（见 `SECURITY.md` B9） |
| `last_seen_at` | datetime | NULL | **最后活跃时间**，用于"我在哪儿登录过" |

索引：`uk_token_hash`(UNIQUE) · `idx_member_id`

> **三条实现约定**（都影响这个表的用法）：
> 1. **多设备共存，不限制条数**：正常登录只签新行、**不撤销旧的**。
>    理由见 `01-认证与账号.md`「多设备与会话管理」。
> 2. **`last_seen_at` 粗粒度更新**：在鉴权拦截器里，该列**为 NULL 时立即写**（登录后第一个请求就会填上），
>    此后**距上次超过 1 小时才写一次**。否则每个 API 请求都会多一次 UPDATE（40 人量级虽扛得住，但没必要）。
> 3. **过期 / 已撤销的行不删**：它们就是**登录流水**（谁、何时、从哪个 IP 登过），留着有审计价值。
>    **"我的登录设备"列表只展示有效会话**（`revoked_at IS NULL` 且未过期）。

### ㉓ `profile_visit` 主页访客记录（**期 1.6 建**）

规则见 `14` §14.6.4「别人的主页」与 `03` §3.3 的两个端点。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigint | PK | |
| `viewer_id` | bigint | NOT NULL, FK→member | 谁来看的 |
| `host_id` | bigint | NOT NULL, FK→member | 看了**谁**的主页 |
| `visit_date` | date | NOT NULL | **显式的日期列**——去重键要用它（见下） |

> **为什么必须有 `visit_date` 这个显式列**：去重要靠唯一键，而 `DATE(visited_at)` 这种**函数表达式进不了唯一键**
> ——所以把日期单独存一列。（同一条道理在 `05` 的"签到窗口"上也用过：能写死就别用函数表达式。）
>
> **口径（2026-09-24 定）**：
> - **同一人同一天对同一人只记一条**（`visited_at` 记当天第一次）→ 靠**唯一键**保证，**不靠代码判重**
>   （代码判重挡不住并发）。
> - **本人看自己的主页不记**。
> - **只有被访问者本人能看自己的访客记录**——管理员 / 团长**也看不到别人的**。
> - **本人可以清空自己的**（`DELETE /api/me/profile-visits`）。⚠️ 这是本项目**唯一允许"删"的记录类数据**：
>   与 `11` 的"操作日志只增不改不删"**不冲突**——那条规矩是给**业务留痕 / 审计**用的；
>   访客记录是**本人的私人数据**，按本项目一贯的"**控制权留在人手里**"给本人一个删除口，**且只能删自己的**。
> - **不记 IP / UA**（"谁 + 何时"就够，少记隐私）。
> - **不进 `11` §11.3 的操作日志清单**——按那条的判据："被操作的对象自己已经记了'谁在何时处理的'，就不必重复记"。
>   **写在这里是为了免得后人顺手补上。**

## 13.4 跨表的不变式（**实现时必须保证**）

| # | 不变式 | 违反后果 |
|---|---|---|
| 1 | `attendance` 的 `(event_id, member_id)` 唯一 | 重复签到、出勤率算错 |
| 2 | `member.account` 唯一 | 登录歧义 |
| 3 | `member.is_system=1` 的行**不出现在团员名单、不参与考勤统计** | 管理员被算进应到人数 |
| 4 | `member.status ≠ ACTIVE` ⇒ **禁止登录 + 作废其全部 token** | **安全漏洞**：退团的人还能看团里数据 |
| 5 | `event.section_id` 非空 **当且仅当** `kind = SECTION_CLASS` | 可见性判定出错 |
| 6 | 声部课的请假只生成 **1 条** `leave_approval`；排练生成 **2 条** | 审批流卡住或漏审 |
| 7 | 考勤出勤率按 **`joined_at` ~ `left_at`** 划边界计算；**声部课的应到名单还必须按 `event.date` 在 `member_role_history` 回溯"当时属于该声部"的人** | **出勤率算出 >100%**；以及**换过声部的人，其历史声部课两个声部都算错** |
| 8 | 变更角色时**必须**同时写 `member_role_history` | 历届成员页"历任职务"缺失 |
| 9 | 文件下载**必须鉴权**，磁盘文件名随机 | **权限模型形同虚设** |
| 10 | `operation_log` 只增不改不删 | 留痕失效 |
| 11 | 已取消（`CANCELED`）的活动**不可签到**，且统计时**整场排除** | 取消的场次还算人缺勤 |
| 12 | `event.start_time < event.end_time`，且**单场活动不跨天** | 签到窗口（`end + 2h`）在跨午夜活动上直接失效 |
| 13 | `member.role = HONORARY` **⟺** `member.status = GRADUATED`（**双向**）；非荣誉团员 `honorary_until` 恒为 `NULL` | 把荣誉团员的状态改成 `ACTIVE` 后，`01` §1.4 的登录闸门**第一步就放行**（`status = ACTIVE`）→ **`honorary_until` 当场失效＝永久可登录**；且 `ACTIVE` 会让他重新进应到名单、**能签到**，与 `02` §2.3「签到 ❌」直接冲突 |
| 14 | **补录历史活动必须同时补录考勤**（`event` 与 `attendance` 成对写入，流程见 `05` §5.3）；且**应到名单只含当前 `status = ACTIVE` 的人，并排除 `is_system` 的管理员与 `role = CONDUCTOR` 的指挥** | 只补活动不补考勤 → **分母凭空变大、老团员出勤率暴跌**——正是不变式 7 那个坑的**镜像**（那边是分母变小、算出 >100%；这边是分母变大、算出畸低）。**管理员的排除依据是不变式 3；指挥的排除见 `02` §2.3（指挥是外聘/老师，不是团员）** |
| 15 | **`profile_visit`：同一人同一天对同一人只记一条**（靠 `uk_viewer_host_date` **唯一键**保证，**不是靠代码判重**）；**本人看自己的主页不计入** | 靠代码判重挡不住并发插入（两个人同时打开同一页就会写两条）；而"本人看自己"若也计入，等于每天给自己的主页刷一条，那份记录就没意义了 |
