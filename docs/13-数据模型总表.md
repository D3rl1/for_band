> 页面与视觉规则见 `14` §14.6.4「个人页」 / 「秋日树框」，权限见 `02` §2.3。
> **谁可写**：`avatar` / `intro` / `contact` / `birthday` 本人 + 管理员——先例是 `alumni_message`（`09` §9.3 的端点权限就是「本人 / 管理员」）；`avatar_frame` 当前**本人可写**（管理端编辑表单暂未开放框字段，接口也不接收）。
>
> ⚠️ **`avatar` / `avatar_frame` 存"受控标识符"，不是 URL、不是路径**——这是这套方案**零安全面**的全部秘密：
> 存标识符就不存在"客户端塞外链 / 路径穿越"的可能，服务端只需校验
> **`值 ∈ 对应预置清单 ∪ {null}`**。**预置清单是唯一权威**（与素材一起放在 `14` §14.6.4 指定的目录）。
> **别改成"存 URL"**——那会把一个枚举校验退化成一段要自己维护的白名单过滤逻辑。
> 两个字段**互相独立**：换头像不会清框，换框不会动头像；框不在头像清单里，也不能塞进 `avatar`。

> **`role = HONORARY`（荣誉团员）的语义**（2026-09-23 新增）：
> - **给"因毕业离团"的人保留一个只读身份**：`status` 仍是 `GRADUATED`（已离团），`role` 标成 `HONORARY`；
> - **只有 `status = GRADUATED` 的人才能被设为荣誉团员**（退团 `LEFT` / 休团 `PAUSED` 不适用）；
>   这条是**双向**的——已授予之后，也不允许把状态改成非 `GRADUATED`（见**不变式 13**）；
> - **权限 = 团员权限的只读子集**（"只减不增"），逐项见 `02` §2.3 的权限矩阵；
> - 他们**可以登录**（这是对 `01` §1.4「普通毕业账号禁止登录」的**有意例外**），
>   但受 `honorary_until` 约束：**到期即不可登录**，管理员可续期；
> - **不计考勤**，但**可以被列入演出名单**（见 `07`）。
>
> **实现方要一起改的两处**（规格点名，避免只改一半）：`sql/schema.sql`（`role` 的注释/枚举 + `member` 新列）
> 与 `src/main/resources/static/band-core.js`（`roleLabel` 含"荣誉团员"）+ `band-shell.js`（菜单白名单，见 `14` §14.6.4）。

### ④ `user_token` 登录令牌

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigint | PK | |

| `issued_at` | datetime | NOT NULL | |

| `ip` | varchar(45) | NULL | 登录 IP（IPv6 最长 45）。**存完整值**（审计用），**只有展示时打码**（见 `SECURITY.md` B9） |
| `last_seen_at` | datetime | NULL | **最后活跃时间**，用于"我在哪儿登录过" |

索引：`uk_token_hash`(UNIQUE) · `idx_member_id`

> **三条实现约定**（都影响这个表的用法）：
> 1. **多设备共存，不限制条数**：正常登录只签新行、**不撤销旧的**。
>    理由见 `01-认证与账号.md`「多设备与会话管理」。
> 2. **`last_seen_at` 粗粒度更新**：在鉴权拦截器里，该列**为 NULL 时立即写**（登录后第一个请求就会填上），
>    此后**距上次超过 1 小时才写一次**。否则每个 API 请求都会多一次 UPDATE（40 人量级虽扛得住，但没必要）。
> 3. **过期 / 已撤销的行不删**：它们就是**登录流水**（谁、何时、从哪个 IP 登过），留着有审计价值。
>    **"我的登录设备"列表只展示有效会话**（`revoked_at IS NULL` 且未过期）。

### ⑥ `attendance` 考勤

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigint | PK | |
| `event_id` | bigint | NOT NULL, FK→event | |
| `member_id` | bigint | NOT NULL, FK→member | |
| `status` | varchar(12) | NOT NULL | **四种值**：`PRESENT` 出勤 / `PARTIAL` 遗憾离场 / `LEAVE` 请假 / `ABSENT` 缺勤（2026-10-18 扩） |
| `marked_at` | datetime | NOT NULL | 签到时间点 |
| `marked_by` | bigint | NOT NULL, FK→member | **代签留痕**；本人签时 = `member_id` |

索引：**`uk_event_member`(UNIQUE: event_id, member_id)** · `idx_member_id`

> **缺勤默认不存，靠推导**（应到名单里没有记录 = 缺勤）。这一条不变。
> 唯一例外是 `ABSENT`：只用于把**已存在的**考勤行人工改判成缺勤（例如误签成了 `PRESENT`），
> **不给无记录的人补一行 `ABSENT`**——补录只走代签。统计的缺勤数按 `应到 − 出勤 − 请假` 算，
> `ABSENT` 行天然落进这个减法，**不会和推导缺勤双算**。
> `PARTIAL`（遗憾离场）计入出勤（`present = PRESENT + PARTIAL`），不单列。口径见 `DECISIONS.md` D33。
> 那个唯一索引**一物两用**：既防重复签到，又保证幂等。理由见 `DECISIONS.md` D9。
> 类型 `varchar(12)` 容得下四种值、且无 CHECK 约束，**本次不需 DDL 迁移**。

>   访客记录是**本人的私人数据**，按本项目一贯的"**控制权留在人手里**"给本人一个删除口，**且只能删自己的**。
> - **不记 IP / UA**（"谁 + 何时"就够，少记隐私）。
> - **不进 `11` §11.3 的操作日志清单**——按那条的判据："被操作的对象自己已经记了'谁在何时处理的'，就不必重复记"。

按声部、按周布置作业，录音可以关联到某一条作业，用来算「未交 / 部分交 / 已交」。

### ㉚ `member_status_history` 状态切换事实（#249，2026-11-05 用户拍板）

| `after_status` | varchar(12) | NOT NULL | 修改后状态，四态枚举同 `member.status` |

### ㉛ `avatar_grant` 纪念头像发放关系（#266，2026-11-16 用户批准结构）
