# 03 · 团员与声部

## 3.1 这个板块解决什么

维护"谁是这个团的人、在哪个声部、现在还在不在团"，并让**历史记录不因为人员变动而失真**。

---

## 3.2 数据模型

### `section`（声部）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `name` | varchar(32) | 声部名 |
| `order_no` | int | 显示顺序 |

**初始数据**（山水民族管弦乐团，**7 个声部、平级**）：
打击声部 · 提琴声部 · 胡琴声部 · 吹管声部 · 古扬声部 · 阮声部 · 琵琶声部

> ⚠️ **声部必须是数据（一张表），绝不能写死在代码里。** 各团编制不同、还会调整；
> 写成枚举的话，以后连加一个声部都要改代码。

> ⚠️ **声部是平级的，没有上下级**（表里没有 `parent_id`，不要加）。
> 曾经考虑过"弹拨声部下辖阮声部 / 琵琶声部"的两级结构，**已否掉**——
> 实际使用中直接就是两个平级声部，多设一个上级只是麻烦（用户决定）。
> 因此**"本声部"在权限判定里始终只有一个含义**，不用考虑递归子声部。
> 「古扬声部」同时含古筝与扬琴，两者差异记在 `member.instrument`。

展示"曾任二胡声部长"这类信息需要它——`member.role` 只有**当前**角色。

| 字段 | 说明 |
|---|---|
| `id` | PK |
| `member_id` | |
| `role` | 当时的角色 |
| `section_id` | 当时所属声部 |
| `from_date` | 生效日期 |
| `to_date` | 结束日期（NULL = 仍在任） |

## 3.4 业务规则与边界

### 状态四态

`ACTIVE` 在团 · `PAUSED` 休团 · `LEFT` 退团 · `GRADUATED` 毕业

### 软删除：**绝不物理删团员行**

退团、毕业的人，其考勤、录音、演出历史都还挂着；物理删人会把历史一起切断。
一律用 `status` 标记。

### 状态变更的连带动作（**重要，容易漏**）

| 状态变化 | 必须同时做的事 |
|---|---|
| 任何状态 → 非 `ACTIVE` | ① **禁止登录** ② **立即作废其全部 token** |
| `ACTIVE` → `LEFT` / `GRADUATED` | 写入 `left_at`（**考勤统计靠它划边界**，见下） |
| 回到 `ACTIVE` | 清空 `left_at`（重新计算时按新的区间） |

> 第一条是安全漏洞的修补：不同时作废 token 的话，退团的人拿着 30 天有效期的旧 token
> 照样能看谱子、录音、成员手机号。

### `left_at` 与考勤统计的关系

考勤出勤率按**个人视角**计算：分母 = 该成员**「`joined_at` ~ `left_at`」区间内**的应到场次。

> **为什么不能按"当前在团成员"算应到**：某人退团后，他过去所有场次都不再算应到，
> 但他那时的签到记录还在 → **出勤率会算出超过 100%**。这是设计阶段自审抓出来的问题。
> 详见 `05-签到与考勤.md`。

### 兼声部

**不允许。** 一人一个声部。
好处：表结构最简单，且"本声部"在权限判定里只有一个含义。
兼声部的人归到他主要的那个声部即可。

### 声部长不设冗余字段

**声部长 = `role = SECTION_LEADER` 且 `section_id = X` 的那个人**，由两个字段直接推出。

**"每个声部最多一个声部长"这条约束在应用层校验**（改角色时检查该声部是否已有声部长）。

> 不单独存一个"本声部负责人"字段的理由：**存两处就会有两处不一致的可能**。

### 名单维护权限

**仅管理员**（建号 / 停用 / 改声部与角色）。见 `02-权限模型.md` T8。

### 账号唯一性

建号前先查重，重复返回 409。重名示例：两个张伟 → `zhangwei` / `zhangwei2`。
