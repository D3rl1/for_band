# 17 · 我们的专场

## 17.1 这个板块解决什么

**一条可以一年年长下去的时间线，把乐团历年的「专场」串成一个故事。**
点开一个方块 → 那场的图片放大到屏幕中央 → 变成左右手滑的轮播；点单张 → 专注看这一张和它配的文字；
滑到最后，是一句「我们的故事尚未完结，敬请期待…」。

**它和 `07-演出.md` 的分工**（别搞混，两件事）：

| | `07-演出.md` | 本板块 |
|---|---|---|
| 管什么 | **演出档案的运维**：建/改演出、曲目单、参演名单、**全员晒图**、复盘 | **门面的展示与策展**：时间线怎么排、上哪几张图、配什么文字 |
| 照片 | `concert_photo`（**全员可传**、不排序、将来挂点赞评论） | `showcase_photo`（**仅管理员**策展、**有顺序**、**有长文案**） |
| 谁在用 | 日常在维护档案的人 | **看的人**——尤其是已经毕业、想回来翻翻的人 |

> ⚠️ **本板块不是"历届成员"那个板块的复活。** `09-历届成员.md` 整份是 ❌ 不做的，
> 别引用它、也别照它写。这里只做"专场的呈现"。

## 17.2 数据模型

**表结构以 `13-数据模型总表.md` 为唯一权威**，本节只列用到什么、不重复定义：

- `concert.is_showcase`（`13` §13.3 ⑫）——**1 = 这场是专场**，在时间线上占一个节点
- `showcase_photo`（`13` §13.3 ㉔）——策展图：`concert_id` / `file_id` / `sort_no` / `note`(text) / `created_by`
- `file`（`13` §13.3 ⑨）——图片本体，**走 `08` §8.5 的统一文件存储**

**这张专页不新增任何"年份"表**：年份是 `concert.date` 分出来的，**不是独立实体**
（一年一场还是几场，全由实际数据决定，不给它加约束）。

## 17.3 接口清单

### 展示（**登录即可，含荣誉团员**）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/showcase/timeline` | 登录 | 时间线：把 `is_showcase = 1` 的专场**按年份聚合**；每个节点给 **`year` / 该年策展图张数 / 封面 `fileId`**（= 该年排序第一张） |
| GET | `/api/showcase/years/{year}` | 登录 | **该年全部**策展图（`fileId` + `note` + `sortNo`），**按「演出日期 → `sort_no`」排** |

> ⚠️ **2026-09-26 改过一次，留痕**：这两个端点原先是**按场**写的
> （`GET /api/showcase/{concertId}`，一个节点 = 一场专场）。用户看过样张后定了
> **"一个时间点 = 一年"**，所以展示侧改成**按年**。
> **策展单位不变**——照片仍然挂在**某一场专场**上（它本来就属于那场演出）；
> 变的只是**展示怎么聚合**：一个年份节点的图 = **该年所有专场策展图串起来**。
> 👉 副作用是"**开新时间点**"更顺了：**在那一年建一场专场，年份节点自然就有了**，
> 管理员不需要额外"开一个年份"这种东西。

### 策展（**仅管理员**）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/admin/showcase` | 管理员 | **开一个新时间点**：建一场 `is_showcase = 1` 的演出。请求体 = **`{name, date, venue?}`**（**`name` 与 `date` 必填**，其余留空，后面用 `07` 的接口补） |
| PUT | `/api/admin/showcase/{concertId}` | 管理员 | **把这场设为 / 取消专场**：请求体 = **`{isShowcase: true \| false}`**。⚠️ **必须双向**——只做"撤下"的话，撤错了就再也标不回来（`POST` 那条是**新建**，不能用来重新标记既有的演出）。⚠️ **只翻标记、绝不删演出档案** |
| GET | `/api/admin/showcase/{concertId}/candidates` | 管理员 | 这场演出**已有的晒图**（`photoId` + `fileId` + 已有 `caption`），供"从已有的里挑"。⚠️ **只读，不改 `concert_photo` 一个字** |
| POST | `/api/admin/showcase/{concertId}/photos` | 管理员 | 加一张策展图。请求体 = **`{fileId, note?}`**；`sort_no` 由服务端**追加到末尾**（不要求前端算） |
| PUT | `/api/admin/showcase/{concertId}/photos/order` | 管理员 | **整批设顺序**：请求体 = **`{photoIds: [...]}`**（按数组顺序即最终顺序，**whole-replace**，照 `07` 的 `PUT .../program` 那条先例）。⚠️ 数组里的 id **必须都属于这场专场**，否则 `10001` |
| PUT | `/api/admin/showcase/{concertId}/photos/{photoId}` | 管理员 | 改这一张的文案 |
| DELETE | `/api/admin/showcase/{concertId}/photos/{photoId}` | 管理员 | 把这张移出专页。⚠️ **只删关联行，不删 `file`**（同一张图可能还在晒图墙上） |

> 📌 **2026-10-06 补记（请求体校验）**：上表 `PUT .../photos/order` 的请求体 **`{photoIds: [...]}`** 已挂 `@Valid`——
> **`photoIds` 为 null → 422 `10001`**（"photoIds 不能为空"）；数组可为空；**数组里的 id 必须都属于这场专场**，否则也是 `10001`。（`交接单` `#158`）

> **为什么"开新时间点"不塞进 `POST /api/concerts`**：那条是 管理员 / 团长 / 指挥 三方可用，
> 而"开一个新节点"**只给管理员**（`02` §2.3）。做成一条独立的、字段很窄的接口，
> 权限就是一个干净的类级 `@RequireRole(ADMIN)`，**不必在既有的建演出流程里塞一个条件分支**。
> ⚠️ 但**它建出来的就是一条普通演出记录**——建完之后照常由 管理员 / 团长 / 指挥 用 `07` 的接口维护。

> ⚠️ **没有任何新错误码**：权限走 `30001`、字段校验走 `10001`、找不到走 404，全部复用现有码。
> `POST /api/admin/showcase` 时若该演出已经是专场 → `10001`（**幂等失败要说得出来，别静默成功**）。

> ⚠️ **新端点要同步登记到 `10-接口规范与错误码.md` 的端点清单**（闸门 R5 双向核这条）。

## 17.4 业务规则与边界

### 可见性

**全团登录可见，含荣誉团员。**

⚠️ **这不是给荣誉团员新开的口子**——它就是 `02` §2.3 里「看演出档案（节目单 / 参演名单 / **照片** / 复盘）」
那一格的**同一个权限**，专页只是换一种呈现方式（策展文案与"复盘"同属纯只读的演出信息）。
**所以别去 `02` 的例外清单里加一行**（清单与默认混起来就失去意义了）。

### 时间线的排法（**2026-09-26 按用户描述重定，与上一版不同**）

**⚠️ 这一节整个改过一次**：上一版是"左对齐竖线 + 年份分组 + 整宽卡片"，
用户看过样张后给出了他要的形态（他见过参考效果），下面是**按他的描述定的**。

- **一个时间点 = 一个年份**（不是一场专场）。
  一年里若有多场专场，**该节点的图就是那几场策展图串起来**（`17.3` 的按年聚合）。
- ⭐ **【桌面】一条竖直的淡白线钉在页面水平正中**（不是靠左）。⚠️ 是**浅色线** ⇒ **这一页的底色是深的**（见下面那条留痕）。
- ⭐ **【桌面】年份沿中线左右交替**：第 1 个在**左**、第 2 个在**右**、第 3 个在左……一直往下。
  ⚠️ 实现上注意：中线本身也是那个容器的一个子元素，
  **用 `nth-of-type`（按元素类型数）而不是 `nth-child`**，否则奇偶会整体错开一位。
- ⭐ **【手机】中轴靠左（`18px`）+ 单列铺满**（2026-09-28 定）：上面"水平正中 + 左右交替"
  是**桌面**形态；**390px 这类窄屏上左右交替会把图和年份都挤成一条**，所以手机改成
  **中轴靠左 `18px`、年份一律靠线右、单列往下铺**。
- ⭐ **每个时间点的图摆在"点"的上面**（节点 = 上面一张图 + 下面年份与场次）。
  从节点伸一根短横线接到中轴，轴上有个小点。
- **方向：从最早 → 最新，往下滑 = 往现在走。**
  ⚠️ **这不是随便定的**：底部那句「我们的故事尚未完结，敬请期待…」**只有在"滑到底 = 滑到现在"时才成立**；
  反过来排（最新在上），那句话就变成悬在中间的空话。
- **节点之间留足间距**，让"一次基本只看得到一个节点"成立——否则下面的换背景判据会在两个节点之间抖。

### ⭐ 背景：全屏固定的图片层，**越过屏幕中线**就换

**这一页的背景不是纯色，是"当前那个年份的图放大版"。** 四条规矩：

1. **主背景层 `position:fixed` 铺满视口**，放当前节点的那张图。
2. **压暗 + 轻微模糊**（不然年份、连线、节点上的图都读不清）。模糊时**顺带放大一点点**，
   免得模糊糊到边缘、露出底色。
3. ⭐ **切换判据 = 屏幕中线**（2026-09-26 用户定）：节点**中心越过视口中线**，就换成它的图。
   ⇒ "当前是哪一年"就是**最后一个中心已越过中线的节点**；页面刚打开时取第一个。
   ⚠️ **这个判据要挂在 DOM 上可量**（把当前年份写在背景层的 `data-year` 上）——
   否则"什么时候换"这件事没法测（见 `17.6` 的验收）。
4. **换的时候必须是交叉淡入**（新图淡入、旧图淡出），**不是硬切**——这一下是这一页"高级感"的主要来源。
   做法：**两层叠着**，切换时改"当前是哪一层"。⚠️ 改完 class 要**逼一帧再淡入**，
   否则浏览器会把两步合成一步、过渡根本不跑。

### ⚠️ 没有策展图的**年份**，**不出现在时间线上**

管理员可能先建了专场、图还没加。这时**那个年份不上时间线**（不能出现一个空节点或坏图）。
👉 **代价是"建了但看不见"，所以管理页必须明确提示**："这一年还没加图，**不会**上时间线"。
**不许静默**——这是本项目一贯的要求（看不到的东西必须有人告诉你为什么）。

### 方块里**先只放照片**

点开方块 = 照片轮播，**不带曲目单 / 参演名单 / 复盘**（2026-09-26 定：第一版专注把时间线与轮播做好）。
⚠️ 数据其实是现成的（`07` 那三样都在），**将来要加是加一块内容的事，不用改表**——写在这里免得后人以为漏了。

### 别和晒图墙混起来

- 专页的图**不参与**点赞 / 评论——点赞评论是**演出页晒图墙**的事（`07` 批 2）。
- 专页的图**可以**是晒图墙上已经有的同一张（`file_id` 相同），**不重复占磁盘**。

### 这一页没有侧栏、没有页头（正文占满；桌面与手机都是）

**2026-09-28 用户拍板**：这一页**不要侧栏、也不要页头**（**桌面与手机都是**），正文占满整幅。
用户原话："还能看得到侧边栏，我想的是隐藏这个侧栏，然后把这个屏幕再拉伸开。手机上也不要这个侧边栏。"

- 落地：`body.page-showcase .nav-slot{display:none}`、`body.page-showcase .head{display:none}`。
- `.main` 的内边距改成 **`36px 24px 44px`**，**左右对称**（各 `24px`）。
  ⚠️ **左右不等会把中轴推离视口中线约 6px**——这就是这句"对称"的全部意义。
- ⚠️ 连带（口径）：这一页**自己不挂任何导航外壳**，所以**在这一页里**看不到侧栏菜单、
  也看不到页头右上角的「更新」（**有意为之**，不是漏做；2026-10-26 起页头那一侧只剩更新公告，
  旧「反馈」已随反馈信箱退役，见 `15` §15.11）。
  进 / 出这一页的两处门户只剩：**演出页（`concerts.html`）顶部的入口（进）**
  与**页尾这一行（出，见下）**。

### 退出：页尾的一行「回归现实」

**页面最下方一行「回归现实」**（2026-09-27 用户定名），就压在寄语
「我们的故事尚未完结，敬请期待…」**下面**；点了回**网站首页 `index.html`**
（该页再 `replace` 到活动页，见 `14` §14.5）。

- ⭐ **2026-09-28 改，这条正式推翻原规格那句"必须 `position:fixed`"**：
  它现在是**在流**元素（`position:static`、**不带 `z-index`**），**不是**左上角的固定按钮。
  代价是"**想走得先滑到底**"（浏览器**后退键仍在**）——**用户知情并选了这个**。
- ⇒ "**轮播 / 专注层开着时它被盖住**"是**天然**的：那两层是**满屏 `fixed` + `600` / `650`**，
  一个在流元素自然落在它们下面。**不需要也不许**再为它专门抬层级。
- **就是一个普通链接**（`<a href="index.html">`）：不需要 JS、不需要新端点、不需要新权限
  ——它不碰任何数据，只是"离开这一页"。所以 `02` 的权限矩阵**不加行**。

## 17.5 策展规则（**谁能做什么**）

**策展 = 仅管理员**（开新时间点 / 加图 / 排序 / 改文案 / 撤下，全部）。

### 加图有两条路，两条都要有

1. **从已有的里挑**：把这场演出**晒图墙上已经有的**照片勾进专页（复用同一个 `file_id`）。
2. **直接传新的**：走统一上传接口 `POST /api/files`（**前端必须先压缩**，`08` §8.5），再挂进专页。

### 顺序

`sort_no` 决定顺序，管理页要有**上移 / 下移**。
⚠️ **方块封面 = 顺序里的第一张**——所以"想换封面"就是"把那张挪到第一"，**不另设"指定封面"字段**。

### 文案（`note`）

- **每张图一段**，存 `text`（比晒图的 `caption` 长，能放一整段）。
- **单张上限 2000 字**，超了走 `10001`。理由：防的是"**误粘一整篇文章进来**"——
  `text` 装得下不代表该收，而这个字段会**跟着图片一起发给每一个看专页的人**。
- **从外部批量导入是刚需**（用户明确要求），管理页要有**批量粘贴**：
  **按当前顺序、以空行分段，依次配给第 1、2、3… 张图**。
  ⚠️ **段数与图片数不一致时必须明确报错**（**2026-09-28 用户拍定：这道校验"只在前端挡"**），
  **不许静默错配**——错配了没人会发现，比报错坏得多。
  👉 **为什么只在前端**：策展接口里**根本没有"批量"这个动作**（`17.3`）——文案是**逐张**
  `PUT .../photos/{photoId}`、**每次只带这一张的文案**，`note` 单张校验（上限 2000 字）也在这一步；
  **服务端手里没有"段数"这个量可比**。而错配只可能发生在"**人往页面里粘**"这一步，
  那一步只有页面有。⚠️ 因此**不加批量端点**（上一轮提的那条路**已否**），
  `docs/10` 与 `17.3` 的端点清单**不需要动**。

### 页面与入口（两页，别挂错）

| 页面 | 挂哪儿 | 为什么 |
|---|---|---|
| `showcase.html`（展示页） | **`band-shell.js` 的 `offMenuTitles`**（`'showcase.html': '专场'`，**不进菜单**） | **唯一入口 = `concerts.html` 顶部那张「我们的专场」入口卡**（⚠️ **2026-09-30 改：入口本身要"显眼"，从一行小字改成占满宽的入口卡，2026-10-01 已落地**，`14` §14.6.4「我们的专场专页」/ `交接单` `#116`）。⚠️⭐ **2026-11-16 用户拍板（留痕）**：侧栏那栏删了——原话「侧边栏中的专场那一栏不要摆出来了，只保持演出里的那个入口就行，不然平常会不小心点进去」。这是 **2026-10-06「进菜单」的反向调整**（那条旧口径原文即"从 `offMenuTitles` 改成进菜单"，现改回）；`offMenuTitles` 那一条**必须留着**，否则沉浸页的页头标题会回退成本人姓名 |
| `admin-showcase.html`（策展页） | **`band-shell.js` 的 `menu`**（管理 ·「活动与演出」组，标题「专场策展」，白名单 **`admin`**，图标 **`images`**） | 管理员需要能**直接进去干活**，不能只藏在某个页面里。⚠️ 图标现在是**自托管图标库的 key**（`14` §14.6.4「DOM 契约」，物料 = `vendor/icons/`，Lucide 1.49.0），**一一对应、不许与别的页面共用一个**——⚠️ **它尤其不能与「活动管理」共用一个**：样张里这两项都用了 `◈`、**撞了**，而"活动 / 活动管理"这类语义撞车正是这条规矩存在的理由 |

⚠️ **两页都要登记进 `14` §14.5 的页面清单**——只挂入口不登记、或只登记不挂入口，
`refresh.sh` 的 `[4/5]` 都会告警（**只警告、不中断**，所以漏了不会有人告诉你）。

### 撤下

把 `is_showcase` 置 0 ⇒ 它从时间线消失，**但演出档案、晒图墙、节目单一样不删**。
⚠️ **本项目不做"顺手把演出档案也删了"**——撤下时间线是展示层的动作，与删档案是两回事。

## 17.6 动效与降级

**三处动效已全部定档**（2026-09-27，用户对着样张 `design-samples/showcase-mock.html` 逐档切完挑定；
原先那套"遮罩淡出"三档整个作废，样张里的 A/B/C 切换器已退休）。**下面逐条写死形态 + 边界。**

### ⚠️⚠️ 「椭圆」是**裁**出来的，不是**排**出来的（2026-09-26 定，**这条是本页最要紧的认识**）

**一开始做错了、白做两轮**，写在这里免得后人再走一遍：

- ❌ **错的做法**（第一、二版样张）：把每张照片按角度摆到一条椭圆轨迹上、
  **逐张缩放**、加前后景深——做出来是"封面墙/扇形"：会缩小、会散开、会互相遮住。
  用户对照参考后判为"**不是我想要的效果**"。
- ✅ **对的做法**（参考源码读了之后定的）：**照片全部同尺寸、一律直立**，排成一条**普通横带**；
  真正让它看起来是"椭圆/弧形"的，是带子上一层**上下双弧的遮罩**——**同一根直带子被裁弯了**。
  ⇒ **排布是平的，"弧"是裁剪的错觉。**

**具体三层**（样张 `design-samples/showcase-mock.html` 是真值）：

| 层 | 干什么 |
|---|---|
| `.strip`（横带） | `display:flex` + `gap`，卡片 `flex:0 0 auto` **同宽同高**；**用 `translateX` 整条平移**（⚠️ **不许用 `left`**） |
| `.band`（遮罩层） | 一道**自己画的** SVG 双弧遮罩（`mask` + `-webkit-mask`），把带子裁成"中间窄、两头宽" |
| `.bandwrap`（外壳） | 入场/退场的 **FLIP** 作用在它身上 —— 连那道弧一起长出来 |

- **带子比卡片高**（卡片占带高的 **72%**，照参考的比例）：**卡片上下各有 14% 的留白**，
  所以弧要"切进画面"得先吃掉这段留白——这是下面那几个数能成立的前提。
- ⭐⭐ **弧的形态：中轴满高、两翼对称收窄**（2026-09-27 改，方向反过来了）。
  ⚠️ **老版是反的，"腰"落在屏幕正中**：路径在 `viewBox` x=500 处只留 **216/400**（54%），
  两翼反而满高 ⇒ **正中间那张被上下各削约 25%**、而弧在两翼抬得很陡、**侧边照片被斜着切一刀**。
  用户看过样张后判为"**这中间的形状不知道被扭曲成啥样了**"。**这条留痕就是给后人看的**：
  "椭圆"的效果来自**两翼收窄**，不是中轴收窄——**照片本来就在中段，把中段压掉等于切主角**。
  **现在的几何**（样张 `design-samples/showcase-mock.html` 的 `--arc` 是真值）：

  | 参数 | 值 | 为什么 |
  |---|---|---|
  | `viewBox` | `0 0 1000 400` + `preserveAspectRatio="none"` | 遮罩横向按比例拉伸到满屏宽 |
  | **完整窗口** | x ∈ **[240, 760]**（中间 **52%** 宽、**满高**） | 卡片宽是 `min(46vw, 400px)` ⇒ **最宽时正好占 46% 屏宽**、在 `viewBox` 里最多跨 [270, 730] ⇒ **任何屏宽下中间那张都整个落在窗口内**（两侧各余 30 单位） |
  | **两翼收窄** | 到 x=0 / 1000 时收到 **82 单位**（可见高 236/400 = 59%） | 82 单位 = 带高的 **20.5%** ⇒ 切进卡片约 **9%**：看得出"弯过去了"，又不至于把照片砍烂 |

  ⚠️ **一句实话（别当成漏了）**：掩膜是**固定在屏幕上**的，所以**跨在收窄段上**的侧边照片，
  左右两端被削的深度仍不完全相等 ⇒ **侧边照片仍有一点点斜切**。这是"带子弯开去"本身带的，
  不是 bug；它现在**又浅又缓**（整个屏幕跨度内才升 ~20%），不是老版那样在正中陡起。
  👉 用户若仍觉得碍眼，退路是**整道弧拆掉**（平带子），说好了一句话就能换。
- **无限滑动 = 渲染 3 份副本 + 平移量按一个周期取模**：
  ⚠️ **不要照参考那样把 DOM 搬来搬去**（它为此留了一串"回退时 transform 该不该加"的补丁注释，还用了 `left`）。
  取模之后数值永远落在中间那份里、接得上，**代码少一半**。
- ⚠️ **缓停不能用 CSS 过渡**：取模会让平移量"差一个周期"地跳一下，CSS 过渡会把这一跳也动画出来
  （整条带子刷地滑一屏）。**缓停用 rAF 逐帧逼近**，跳变就看不见了。

### ⚠️ 轮播的交互规则（2026-09-26 在样张里实测定下来的）

这几条**不是"实现细节"，是手感规格**——每一条都对应一个踩过的坑，复盘见 `debug_log.md`（2026-09-26 那两条）。

- **唯一状态是「第几张在最前」**（整数，拖动时可带小数）；位置由它算出来。
  ⚠️ **不许同时维护两套语义状态**：样张第一版同时维护"当前角度"与"目标角度"，
  吸附时在弧度上直接取整、又补了个负号 ⇒ **"拖一步却跳到最后一页"**
  （6 张的环上 `−1` 与 `5` 是**同一张**，所以"偏一步"的表现是"跳到另一头"，症状离根因极远、极难查）。
  （rAF 里那个"渲染用的插值"不算第二套语义状态，但**必须只由那个唯一状态派生**。）
- **一张卡的距离 = 一步**（卡宽 + 间距）。这是"手感正常"的定义：
  **拖一张卡的距离 ≈ 正好进一张**。
- **松手只做一件事：取最近的整数张**（`round`）。**明确不做惯性**——
  试过"受限惯性"，但它的速度估计不可靠（同一甩动结果不稳定、**写不出确定判据**），
  而 **1:1 跟手 + 精确吸附是可预测的**；用户报的"滑得特别快、飞到某一张"正是要避免的东西。
- **拖动面必须 `preventDefault` + `user-select:none`**（并挡掉 `dragstart`）：
  否则浏览器会把指针序列**抢去划选文字 / 原生拖拽**，**只收到一两次 `pointermove` 就断**，
  **且不报任何错**（表现是"点开之后拖不动"）。
- **不要用 `click` 判"轻点这一张"**：拖动面一旦 `setPointerCapture`，浏览器会把 `click`
  **重定向到捕获元素**，挂在卡片上的 `click` **永远不触发**。正解：`pointerdown` 记下起点与命中元素、
  `pointerup` 按**位移 < 8px** 判轻点（触摸端本来也只能这么做）。
- **浮层的延迟关闭必须可取消**：连按几次 `Esc` 会排出一串"延时关层"定时器，
  其中一些会在**浮层重新打开之后**才触发、把刚开的层又关掉（表现同样是"拖不动"，**不报错**）。
- **`z-index` 用书面值 `600`**，且**浮层内的工具与「关闭」要摆在不同位置**——
  **别靠抬高层级去抢**（样张里顶栏 900 压住浮层的「关闭」，按钮就全点不动了）。
- **别漏 `touch-action: pan-y`**：横向归自己、纵向留给页面滚动。
- ⚠️ **`mask` 不进命中测试**（Chromium）：它是**绘制期**效果，
  `elementFromPoint` 在被裁掉的区域**照样命中原元素**。
  ⇒ **要验证"那道弧真的在裁"，只能用像素取样**（截图取点比较），**别用命中测试**
  ——样张探针第一版就栽在这：量出"两头和中间一样"，**看着像通过、其实是假判据**。
  （判据要"能红"：弧的方向反了，`yLeft < yMid` 这条就会翻过来。）

### 不许越过的线（`14` §14.6.6）

- **只动 `transform` / `opacity` / `filter`**，绝不动 `width` / `height` / `left` / `top`。
- 时长：微交互 150–250ms、页面切换 300–500ms（>500ms 显迟钝）。
- **不做 idle 循环动画**；**不用弹跳缓动**。
- **`prefers-reduced-motion` 必须降级**：转场退化成**普通跳页**、轮播**直接切图**、方块**不做浮现**。
  ⚠️ **是"减少"不是"删掉"**——功能一样都不能少（`14` §14.6.6）。
- **不引第三方库、不引 CDN、不加构建链**（`14` §14.2 / `DECISIONS` D7）。
  👉 Bootstrap 自带 Carousel **用不上**（它做不了椭圆 3D），这个轮播是**手写**的。

### ⚠️ 椭圆轮播**不是 idle 动画**（这条要写清楚，否则会被误判违规）

判据三条，缺一条就退化成装饰（照节拍器那条留痕的同一套口径）：

1. **用户主动开始、用户主动停止**——**不做自动轮播**（用户已定），只响应左右手滑；
2. **有语义**：轮播就是"翻这一场的照片"，功能本体；
3. **不重排**：只动 `transform` / `opacity`。

⇒ 所以它**既不需要新开一条 idle 例外，也绝不能被引作"可以加 idle 动画"的先例**。
