# 10 · 接口规范与错误码

## 10.1 这个板块解决什么

**前后端分离能落地的前提，就是这份约定。**

没有统一的响应体和错误码表，网页端和安卓 App 会对同一个错误各写一套处理逻辑——
以后加第三个客户端时，还得再写第三套。**这份文档就是那份"共同的合同"。**

---

## 10.2 统一响应体

**所有接口**（成功与失败）都返回同一个外壳：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 说明 |
|---|---|
| `code` | **业务错误码**。`0` 表示成功；非 0 见 §10.5 |
| `message` | 给人看的提示语，**可以直接显示在界面上** |
| `data` | 业务数据。失败时为 `null`（或带补充信息） |

---

## 10.3 HTTP 状态码

**HTTP 状态码与业务码各司其职**：HTTP 状态码表达"这类请求的结果性质"，业务码表达"具体是哪种情况"。

| 状态码 | 用途 |
|---|---|
| **200** | 成功 |
| **400** | 请求格式错误（JSON 解析失败等） |
| **401** | **未登录 / token 失效** → 客户端据此**跳登录页** |
| **403** | **已登录但无权限** → 客户端提示"你没有权限执行此操作" |
| **404** | 资源不存在 |
| **409** | 冲突（账号重复、重复签到等） |
| **422** | 参数校验失败（类型、长度、必填） |
| **500** | 服务端异常 |

> ⚠️ **401 与 403 必须区分清楚**：401 是"你是谁我不知道"，403 是"我知道你是谁，但你不能做这个"。
> 客户端对这两者的处理完全不同（前者跳登录，后者弹提示）。

---

## 10.4 通用约定

| 项 | 约定 |
|---|---|
| **路径前缀** | 一律 `/api/` |
| **认证头** | `Authorization: Bearer <token>` |
| **时间格式** | **ISO 8601 字符串**，如 `2026-09-21T19:00:00`。**不用时间戳**——避免时区歧义 |
| **日期** | `YYYY-MM-DD`；**时间**（无日期）`HH:mm:ss` |
| **分页请求** | `?page=1&size=20`（`page` 从 **1** 开始）。**`size` 上限 100**，超出按 100 处理——否则一个请求就能把整张表捞走 |
| **分页响应** | `data: { list: [...], total: 100, page: 1, size: 20 }` |
| **默认排序** | 未显式指定排序时：**按业务时间倒序**（活动/演出按 `date` 倒序、其余按 `id` 倒序）。**必须写死**，不能靠数据库默认顺序——否则同一页会飘 |
| **空列表** | 返回 `[]`，**不返回 `null`** |
| **字段命名** | 一律 **camelCase**（Java 侧默认，减少转换层） |

### 导出格式

规格里写"导出 Excel"的地方（账号导出、考勤导出），**实现为 CSV 即可**：

- **UTF-8 带 BOM**（`﻿` 开头）——Excel 双击打开不乱码；
- 逗号分隔、首行表头、字段含逗号或引号时用双引号包裹并转义；
- **不为导出引入 POI 等 Excel 库**（一个几十行的导出不值得加一个重依赖）。

即：**"导出 Excel" 的验收标准是「Excel 能直接打开且内容正确」，CSV(BOM) 视为满足。**

### 幂等

以下写操作必须**安全可重试**（弱网重试、用户狂点都不能出问题）：

| 操作 | 幂等做法 |
|---|---|
| 签到 | `UNIQUE(event_id, member_id)`；冲突时返回 `40002 已签到`（**HTTP 409，不是 500**；前端按成功处理） |
| 建号 | 账号名唯一；重复返回 **409** |
| 提交请假 | 同一人对同一场活动只允许一条有效申请 |
| **踢登录会话** | 目标会话**已失效、或 id 根本不存在时，一律返回成功**（不报错）——用户连点两下、或两台设备同时操作，都不该看到红字。**但不属于自己的会话 → 403 `30002`**（越权样板同 `SECURITY.md` A2）：**「幂等」不等于「谁都能踢」** |
| 踢掉其他所有会话 | 同上；**当前这条**始终保留（自己把自己踢下线是荒唐的） |

## 10.5 错误码表（**前后端共用**）

**分区间**，便于一眼看出错误类别：

| 区间 | 类别 |
|---|---|
| `0` | 成功 |
| `1xxxx` | 通用 / 参数 |
| `2xxxx` | 认证与账号 |
| `3xxxx` | 权限 |
| `4xxxx` | 活动与考勤 |
| `5xxxx` | 文件 |
| `6xxxx` | 其他业务 |

> **口径（2026-09-25 定）**：**`code` 与 HTTP 状态是硬契约**；`message` 一列是**规格要求服务端返回的文案**，
> 逐字以本表为准（实现上就是 `ErrorCode.java` 的 `defaultMessage`）。两者都由闸门 **`R10`** 逐条核，**不许再漂**
> ——本次已把历史上漂开的 **12 处**一次对齐（清单见 `交接单.md` `#54`）。
> ⚠️ **例外**：抛异常时可以传**更具体**的文案去覆盖它（例如列明允许的扩展名、或具体上限是多少），
> 那种"因地制宜"的文案本表不列——本表列的是**默认**文案。

### 通用（1xxxx）

| code | HTTP | message | 说明 |
|---|---|---|---|
| `10000` | 400 | 请求格式有误 | JSON 解析失败等 |
| `10001` | 422 | 参数校验失败 | 具体字段放 `data.field` |
| `10002` | 404 | 资源不存在 | |
| `10003` | 500 | 服务器开小差了，请稍后再试 | 统一兜底，**不暴露堆栈** |

### 认证与账号（2xxxx）

| code | HTTP | message | 触发场景 |
|---|---|---|---|
| `20001` | 401 | 账号或密码错误 | 登录失败 |
| `20002` | 401 | 登录已过期，请重新登录 | token 无效 / 过期 |
| `20003` | 403 | 账号已停用，请联系管理员 | `status ≠ ACTIVE` |
| `20004` | 409 | 该账号名已存在，请换一个 | 建号查重 |
| `20005` | 422 | 旧密码不正确 | 改密码 |
| `20006` | 422 | 新密码至少 8 位 | 密码强度 |

### 权限（3xxxx）

| code | HTTP | message |
|---|---|---|
| `30001` | 403 | 你没有权限执行此操作 |
| `30002` | 403 | 只能操作自己的数据 |
| `30003` | 403 | 只能操作本声部的数据 |

### 活动与考勤（4xxxx）

| code | HTTP | message | 触发场景 |
|---|---|---|---|
| `40001` | 409 | 本场活动已取消 | 对已取消场次签到 |
| `40002` | 409 | 已签到 | **幂等返回，非错误**（前端按成功处理）。**已有任意状态的考勤行都走它**——包括被改判成 `ABSENT` / `PARTIAL` / `LEAVE` 的行；返回时**不覆盖原状态**（改回只能管理员走 `PUT /api/attendance/{id}`，见 `05` §5.3） |
| `40003` | 409 | 当前不在签到时间内 | 超出签到窗口 |
| `40004` | 409 | 你已提交过请假申请 | 重复提交 |
| `40005` | 409 | 活动已开始，无法撤回 | 请假撤回超时 |
| `40006` | 409 | 该申请已处理完毕 | 重复审批 |
| `40007` | 422 | 该声部已有声部长 | 角色约束 |
| `40008` | 422 | 该团员此场已请假，或已提交请假申请 | **代签被拒**：目标团员在这场活动上有**生效中的请假**（`PENDING` / `APPROVED`）。见 `05` §5.3「有请假的人不出现代签」 |

### 文件（5xxxx）

| code | HTTP | message | 服务端现在会产生吗 |
|---|---|---|---|
| `50001` | 422 | 文件类型不支持 | ✅ 会（扩展名不在白名单，或内容与扩展名不符） |
| `50002` | 422 | 文件超过大小限制 | ✅ 会（音频 20MB / 图片 8MB / 谱子 20MB） |
| `50003` | 422 | 录音时长超出限制 | ❌ **当前不会**——见下 |

> **`50004` 已删除（2026-09-25）**：它（"无权访问该文件"）与 `30001`（"你没有权限执行此操作"）**是同一个条件**，
> 而代码一直用的就是 `30001`。立一条口径：**同一条件不许有两个码**——只有"调用方可能需要**分别处理**"的才单独立码
> （"类型不支持"与"太大"是两种不同的补救动作，所以各占一个码）；**细分交给 `message`**
> （例如越权下载文件时，用 "没有权限看这个文件" 而不是新开一个码）。

> ⚠️ **`50003` 为什么"当前不会产生"**：录音 3 分钟上限是**暂定项 T5**，而规格自己写着**服务端不解析音频**
> （不引库、不转码，见 `docs/08` §8.3）⇒ **上限只在前端拦**（`recordings.html` 录完自己判秒数）。
> 码**保留为备位**：哪天真要落到服务端校验，就用它。**别在客户端按它判分支之后以为"服务端会回"**。

> 📌 **本轮之前的实情（留痕，别抹）**：`ErrorCode.java` 里**曾经一个 5xxxx 都没有**——上传/下载失败实际返回的是
> `10001`（校验类）+ `10003`（落盘失败），外加一句具体中文。于是这张表是"**承诺了但不存在**"的：
> 照它写的客户端分支**永远命中不了**。2026-09-25 定：**以本表为准，让代码补齐**——
> 理由见 `交接单.md` `#54`（核心是**期 2 有原生安卓客户端，按 `code` 判分支才稳**；按中文文案判分支，改个标点就崩）。

#### 落盘失败必须留日志（2026-09-24 补，起因是一次真实故障）

`POST /api/files` 的**落盘**失败**不能只回一句话就完事**。现状：
`FileStorage.java:64` 把 `IOException` 压成 `BusinessException(INTERNAL_ERROR, "文件写入失败")`，
而 `GlobalExceptionHandler.java:18-22` 处理 `BusinessException` 时**一个字都不打**（它只管转响应）——
于是这条 500 在日志里**没有堆栈、没有目录、没有文件名**，只能上服务器反查。
（2026-09-24 线上真踩：管理员传一个 5MB 的 mp3 报「文件写入失败」，
而**请求已到后端、角色/体积/格式全部合规**，日志里却查不到任何线索。）

**要求**（三条都做到才算合格）：

| 要求 | 为什么 |
|---|---|
| 抛之前先 `log.error`，打出**落盘目录 + 目标文件名 + 完整异常（带堆栈）** | 这是"**磁盘满** / **目录不可写** / **文件系统转只读**"三者**唯一**的区分依据 |
| 日志里必须看得见**原始异常类型**（`AccessDeniedException` ↔ 属主/权限；`FileSystemException: … No space left on device` ↔ 磁盘） | 两者**修法完全不同**，压成同一句话就白记了 |
| **响应仍然不暴露内部路径**，`message` 只说人话（如「文件写入失败，请联系管理员」） | 与本节的「**不暴露堆栈**」一致；目录属服务器内部信息，不给任何登录用户看 |

⚠️ 排查入口因此变成一条命令：`grep 文件写入失败 /opt/band/logs/app.log`（或 `journalctl -u band`）。
**规格要的是"这个错误下次能自己说话"，不是"下次再派个人上去猜"**——实现见 `交接单.md` `#47`。

## 10.6 接口文档

**期 1 起，每个接口都必须在对应板块文档里写明：方法 / 路径 / 权限 / 入参 / 出参 / 错误码。**

到实现阶段，建议引入 **springdoc-openapi**（Swagger UI）自动生成接口文档——
它能让前端直接在线调试，也省掉手工维护文档的功夫。

> 这属于"规模到了再升层"的范畴：期 0/期 1 先手写在 `docs/` 里，
> 等到接口数量上来了再引入工具。
