# 乐团管理系统（for_band）

给学校**山水民族管弦乐团**做的管理系统。团员登录看排练安排、签到；管理员维护名册、排练、考勤、曲目、
演出与练习录音。

技术栈是 Java / Spring Boot，前后端分离，同时作为**后端实习的求职作品**。

---

## 当前状态

**期 0 完成（2026-09-21）**：Spring Boot 3.2 本机跑通，连上本机 MySQL，
`section` 表落库（首次启动自动写入 7 个初始声部），`/api/health` 与 `/api/sections`
验证通过，静态首页由后端托管。

## 目标形态

- **后端**：Java 17 (LTS) + Spring Boot 3.2.x + MySQL 8.0 + MyBatis-Plus，输出 REST API
- **客户端 A**：网页端（**先做**，覆盖所有设备，含 iPhone / 鸿蒙）
- **客户端 B**：原生安卓 App（期 2，同时当移动平台开发课的作业）
- **部署**：本机跑通 → 云服务器（`jar` + systemd + Nginx）

---

## 怎么跑起来

以下已于 2026-09-21 验证通过：

```bash
# 后端（需要 JDK 17，JAVA_HOME 已指向 17）
mvn spring-boot:run

# 网页端：由后端直接托管，浏览器打开 http://localhost:8080
# 接口：GET /api/health（code=0，sectionCount 与声部数一致）、GET /api/sections（声部列表）
```

首次在新机器上跑的准备工作（建库 `band`、账号 `band_app`、执行 `sql/schema.sql`）
见 [`docs/12-部署与备份.md`](docs/12-部署与备份.md) §12.2。

## 三条硬约定

1. **先读规格再写代码。** 规格与实现冲突时，以 `docs/` 为准，并回头改规格。
2. **改表结构必须同步 `docs/13-数据模型总表.md`。** 规格分散在十几份文档里，总表是唯一权威；
   不同步的话，几天后文档之间就会互相矛盾（这个坑在写规格阶段已经踩过一次）。
3. **标「暂定」的条目不许当既定事实实现。** 所有暂定项集中在 `docs/00` 的汇总表里，
   附了替补方案，等条件明朗后一次性改。
