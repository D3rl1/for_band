# 乐团管理系统（for_band）

给学校**山水民族管弦乐团**做的管理系统。团员登录看排练安排、签到；管理员维护名册、排练、考勤、曲目、
演出与练习录音。

技术栈是 Java / Spring Boot，前后端分离，同时作为**后端实习的求职作品**。

---

## 当前状态

**期 1.5 已完成，2026-09-23 已上线**（腾讯云轻量应用服务器：Nginx + systemd + 每日备份 + 证书续期告警）。

**"还剩什么没做"只看 [`交接单.md`](交接单.md)**——它是"状态"的唯一权威，每条带状态与回执。
本文件只回答"现在在哪、从哪读起、怎么跑起来"。

## 目标形态

- **后端**：Java 17 (LTS) + Spring Boot 3.2.x + MySQL 8.0 + MyBatis-Plus，输出 REST API
- **客户端 A**：网页端（**先做**，覆盖所有设备，含 iPhone / 鸿蒙）
- **客户端 B**：安卓 App（**WebView 壳**，源在 `android/`，打开线上 `/events.html`）；原定的 Kotlin 原生版未落地，是否改回待定。期 2 同时当移动平台开发课的作业
- **部署**：本机跑通 → 云服务器（`jar` + systemd + Nginx）——**已完成，见 `docs/12`**

---

## 怎么跑起来

```bash
# 后端
mvn spring-boot:run

# 网页端：由后端直接托管，浏览器打开 http://localhost:8080
```

- **重启**跑 `./restart.sh`；**改完前端**（`src/main/resources/static/` 下任何文件）跑 `./refresh.sh`
  ——为什么必须这样、脚本各自做了什么，见 [`AGENTS.md`](AGENTS.md)「运行与环境」。
- 首次在新机器上跑的准备工作（建库 `band`、账号 `band_app`、执行 `sql/schema.sql`）见
  [`docs/12-部署与备份.md`](docs/12-部署与备份.md) §12.2。
- **上线部署**（服务器、Nginx、systemd、备份、证书）全在 `docs/12`。

## 三条硬约定

1. **先读规格再写代码。** 规格与实现冲突时，以 `docs/` 为准，并回头改规格。
2. **改表结构必须同步 `docs/13-数据模型总表.md`。** 规格分散在十几份文档里，总表是唯一权威；
   不同步的话，几天后文档之间就会互相矛盾（这个坑在写规格阶段已经踩过一次）。
3. **标「暂定」的条目不许当既定事实实现。** 所有暂定项集中在 `docs/00` 的汇总表里，
   附了替补方案，等条件明朗后一次性改。
